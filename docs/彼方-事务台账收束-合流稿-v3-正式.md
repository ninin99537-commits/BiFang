## 0. 一句话

收束 = **创建层防歧义**（时间锚纪律 + 粒度规则）＋ **轮次层强制对账**（逐条表态 + 未回票差集 warn/标记）＋ **危害层降级**（未回票 → 注入"待确认"）＋ **兜底层**（人类面板 + 主 AI 闭环）。
代码只做机械事；**死活是语义裁决，只归模型**；账龄只当展示上下文，不当事判据；不新增字段。

## 1. 钉死的事实（含新发现 F6b 与方向守卫的依据）

F1–F8（v1 稿）经双方核对成立。F6 拆成两条，并附加守卫依据：

- **F6a**：无编号"重抄内容 + 改了状态"的载荷被指纹去重吞掉——改动落不了地（`事务台账.ts:290-293`）。
- **F6b**：无编号整份重抄时，每条先置真 `收到记录`（`:289`，在指纹去重 `:291-293` 之前）再被去重吞掉 → 合并末尾照样 `封顶`（`:309-310`）→ 静默淘汰最旧终态（实测 9 终态 → 8），违反 `:276-278` 注释"没变就不该让旧账凭白老化"。带编号重抄（规范形态）安全。
- **方向守卫的依据（必修）**：`归一一条` 对缺状态的载荷默认填 `进行中`（`:141`）。因此 `{内容:"买菜"}`（无编号、无状态）撞上**已完成**的"买菜"时，若按"只收状态/结果"执行会把它改回进行中——**终态复活**；该形态今天被静默丢弃、不会发生，所以不加守卫的修复会引入新行为。
- **守卫的边界依据**：面板三个状态按钮（`悬浮球界面.vue:315` 用 `台账状态表` 渲染）允许玩家把终态点回进行中 → **编号命中与面板同权**；指纹命中只是"靠内容猜的"，只许收束。

**注入判据钉死：未回票，不是账龄。**

| 用途 | 判据 | 约束 |
| --- | --- | --- |
| 注入"（未表态，待确认）"标记 | 本轮未回票 = 卡上全部进行中编号 − 本轮载荷**命中库中编号**的集合 | 逐轮、无状态、零字段；"命中"含改了或没改；幽灵编号不计票 |
| 给更新 AI 的"（写下 10-17；内容锚…）" | 已有 `时间` 字段 + 当前剧情时间 | 纯展示上下文，参与零标记/裁决；但它是作废门槛①的执行前提 |
| 封顶淘汰次序 | 数组顺序（写下先后），只淘汰终态 | 不引入新语义 |

已回票集合从合并处**临时传参**给世界书写入环节（不落库）→ 面板看不到该标记、切聊天后标记自然消失（语义正确：它描述"本轮"）。

### 2.1 改动 #4 的完整规格（含四条）

1. **F6 修复**：指纹命中 → 认作"匹配到某条已有事务"→ 取**第一条（数组序）** → 按规则 2 只收 `状态/结果`。存储层同指纹实际不可达（新增路径 `:291-293` 拦第二条、面板不能新增、旧字符串迁移只出 1 条）→ **不做读取阶段指纹去重**（读取是纯规范化，只对编号去重，加了内容去重等于赌删哪条，还会动 [5]/[12] 周边）。
2. **方向守卫**：指纹命中时——
   - 命中条为终态、载荷状态为"进行中/缺失"（含 `归一一条` 默认值）→ **忽略 + warn**（防终态复活）；
   - 进行中 → 终态（收束）、以及 终态 → 终态（视为修正）→ 放行；
   - **编号命中 = 明示指名 → 允许任意合法状态转换（含重开终态），与面板同权**，不受守卫约束。
   - 与 v1.1 §1.6 不冲突：重开是重大动作，不该由一次内容巧合触发；要重开就走"作废旧条 + 显式开新条"，或编号指名。
3. **收到记录归位**：从 `:289` 挪到规则 3 判定之后（确定要新建处）；指纹命中路径与编号命中路径同样**只在真的改了时置真** → 纯重抄不再触发封顶。
4. **规则3 静默丢弃留痕**：每轮每 NPC **汇总一行**（不逐条打，防整份重抄刷爆日志）：
   `[彼方] NPC「小葵」本轮 3 条载荷因内容重复被丢弃(其中 2 条命中终态条目)`
   理由："同内容承诺第二次入账"（如反复出现的"提醒带伞"这类短承诺）现在被无声吃掉；粒度规则落地后撞车变少，但通道不该继续隐形。

**不做**：计数进卡 / 自动作废 / 终态表态 / 性质字段 / 单独小池子 / 注入拒绝写入 / 读取层数调整（暂缓，见 §5）/ 读取阶段指纹去重。

## 4. 诚实的边界

- **系统能看见"没投票"，看不见"假投票"**（漏票能数，"每条都回继续但没真看"与真继续在合并侧逐字节等价）——后者是模型可信度的终极依赖，无解，接受；这也是 #5 差集 warn 必须存在的原因。
- 作废/完成无代码路径，只能靠模型裁决 + 人类面板/主 AI 闭环兜底。
- **T6 由"铁证"降级为"歧义样本"**：旧的"窗内/窗外"二分被用户修正——判断 T6 所需信息早在卡上（时间字段 + 相对锚 + 当前剧情时间），滑出窗口不构成解释；真正毛病是**冻结内容里的锚是相对词**（读法 A"当晚绑定，过期→作废"与读法 B"承诺未兑现，小孩还惦记→继续"皆自洽）。
- 账龄判据被同类同龄反例（T6/T7）钉死；任何以天数/轮数为触发器的自动出清方案均不予采纳。
- **温度计口径事故（2026-10-11 已修，测试方发现）**：`绝对日期正则` 漏认无纪年中文日期（"10月18日"），与注释口径不一致；只因它仅喂 `缺绝对锚`，故**只漏报不误报**、任何写入路径不受影响。已修（`[-/.年]` → `[-/.年月]`）并钉进用例。教训：此后温度计一律按"只漏报不误报"验收，**修完不等于从此放心**——词表与守卫的边界同样是"参考数字"，不是验收线。

## 5. 用户三答的落点

1. **双模型（Gemini + DeepSeek 都可用、不固定）** → 设计不能依赖单一模型的服从度。代码侧防线（#4 F6 修复 + 方向守卫、#5 L1 标记**第一天就开**）是承重墙；提示词是尽力层，服从度由差集 warn 度量。两种典型偏差（整份重抄 / 只回最小集漏票）正好各是 #4 / #5 的验收样例。
2. **T6 是歧义样本（与窗口无关）** → 治它的是 #3 逐条表态 + 作废授权 + 三门槛 + 必带原因；**主 AI 闭环治不了 T6**，它管的是"戏再也不回来"的长尾（20 层前定下、之后没被任何正文碰过的承诺）。两者都要做；T6 的验收账记在逐条表态头上，记不到闭环头上。
3. **设置：读取 3 层 / 每轮更新** → 每轮都是表态机会（利好逐条表态与统计）；窗外面积最大（利好主 AI 闭环）。读取层数 3→5 **先别调**：只缩小窗外面积、解决不了 20 层前的承诺，还每轮多读两层的钱；先验证 #3 + #7 这两条免费的。

## 8. 真机验收步骤（T6 专项 + 三条留痕）

准备：真实聊天里挑一个台账含相对锚条目（T6 型：内容里是"洗完澡后"这类词）的 NPC，设置 = **更新频率 1 / 读取层数 3**。

1. **T6 不许沉默**：不刻意提这件事，连推 1–2 轮正文 → 打开该 NPC 卡看 T6。三种结果判：
   - `已完成/已作废` + 带原因（写明哪条门槛）→ **过**；
   - `进行中` + 明确回了一条 `{编号:T6,状态:进行中}`（日志/载荷可见）→ **过**（拿不准继续挂着是设计允许的）；
   - **整轮一个字都没提 T6 → 不合格**（这是唯一的硬失败线）。
2. **逐条表态率（参考值，不是验收线）**：看 info 日志里每轮的未表态条数。**真正要盯的是"单条最长连续未表态 ≥3 轮"**（同一条被连续漏 3 次 → 人工介入：手动作废或手动改内容），整轮平均值 ≥80% 只当参考。
3. **规则 3 留痕**：`[彼方] NPC「X」本轮 N 条载荷因内容重复被丢弃(其中 M 条命中终态条目)`。若 M 恒为 0 且条目状态在动 → 模型在按最小集回，最理想；若 M 持续 >0 且进行中不动 → 模型在整份重抄，配合第 2 条的介入判据。
4. **未回票标记**：warn `[彼方] NPC「X」K 条进行中里有 M 条本轮未表态(注入侧已标"待确认")` → 去世界书条目里确认那几条带了「本轮未表态，待确认」；再推一轮，主 AI 不应被它们捆住。**切一次聊天再切回来，标记必须消失**（证明它是逐轮临时的）。
5. **锚抽查（唯一验收方式）**：翻 10 条新入账条目的内容，人工看"锚是否可推"（有绝对日期，或日期+事件锚）。**不要拿 warn 数当验收线**：词表不完备，"洗完澡后"不在任何词表里，warn = 0 会假通过。
6. **面板新增**：选中任一 NPC → 未完成事项卡片底部输入内容 → 新增 → 卡片立刻多出一条 `T{下一个编号}`（时间 = 当前剧情时间），并已写进快照；输入与账上某条相同的内容 → 应收到"未新增: 账上已有内容相同的事务"提示（不静默、不重复入账）。

## 9. v3.1（作废无原因 温度计）· 已实现 2026-10-11

用户拍板「做」后落盘：把"模型把事务收成已作废、却没给原因"从**看不见**变成**看得见**。纯温度计、零行为改动、不进验收线（与 #1 的锚 warn 同一级别）。

- **落点（与主张甲草案的唯一分歧）**：草案把 `作废无原因: number` 放进 `台账诊断`；实现改为在**集成层算**（`应用更新.ts` 的 `合并一张卡`）。两条理由：
  1. 这条**完全能由前后台账推出来**（"本轮落成已作废 且 最终无结果"），不像另外三条留痕（载荷被丢 / 被吞 / 被拦）在合并后**不可见**，必须由合并层出参；
  2. `台账诊断` 的形状被用例 [8] 逐字段深比对钉着，加字段就得连带改测试，而它并不需要多这一个字段。
- **判据**：`状态 === '已作废' && 结果 为空 && 旧台账里该编号的状态 !== '已作废'`，即"本轮**新变成**已作废"。与草案"凡本轮落成已作废都 +1"有一处细微差别：已作废条本轮被重复回一次已作废，不重复计数；若认为该改成草案口径，改一行。
- **输出（甲留给乙定）**：**独立一行** info，不挤进三留痕那行——三种温度计触发条件互不相关，合并会让"这行到底在说什么"变糊：
  `[彼方] NPC「X」本轮 N 条事务收成"已作废"但没写原因(账上只有状态, 没有"为什么"): T4/T7`
- **只计 AI 路径**（`合并一张卡` 内）：面板 `改事务状态` / `新增事务` 是人在操作，人的意图不需要审计——与草案口径一致。
- **不做**：拦截 / 补写 / 自动作废 / 改面板 / 任何行为改动。
- **甲裁决（2026-10-11，主张甲）**：
  1. **落点**：采纳集成层，不改 `台账诊断` 构型——两条理由成立（前后台账可推 / [8] 深比对不动）。
  2. **判据**：已作废条被重复回一次已作废，**计 0**——"本轮新变成已作废"即"本轮落成"，重复返回不算新的作废动作，不重复计。乙口径保持；草案措辞据此改。
  3. **输出 / 只计 AI 路径 / 面板不计 / 独立一行**：确认，与实现一致。
- **验证现状（含测试）**：全库 51 用例文件全过；温度计一次性探针已验（无原因 → 1 行、带原因 → 无、仍进行中 → 无），探针已删。**测试侧断言已补 [13]**（① 无原因报 / ② 带原因不报 / ③ 仍进行不报 / ④ 重复返回不报）；`bifang-ledger-close.test.ts` 13 段 66 条，全绿。
