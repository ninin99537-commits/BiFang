# ADR-0003 · 窗口机制与悬浮球几何归谁

*状态*：**已决（2026-11 复核后仍然维持）** · *影响*：彼方 / 烟火 / 剧情导演

## 背景

三个同族插件各有一套「悬浮球 + 面板」窗口机制：iframe 尺寸、球与面板拖动、阴影、贴球锚点、界面偏好持久化。

- **烟火 / 剧情导演**：两份高度重合的实现各自演化（668 / 589 行）→ 已合并为 `src/共用/面板机制.ts`，两个插件各提供一个 adapter。
- **彼方**：仍然自带一套（`悬浮球界面.vue` 内约 800 行 + `悬浮球偏好.ts`）。README 里那句「彼方有自己的球几何，见 ADR-0003」指的就是这件事，但本文件此前不存在——这是一条**只写在别处、没有落点**的决定。

## 决定

**窗口机制归共用**，`共用/面板机制.ts` 是唯一实现，插件只提供外观（面板类名、阴影变量、球直径、阴影层序、面板宽高、提示条适配、偏好存储接缝）。

**彼方暂不接入**，保持自带实现。原因不是"懒得改"，而是 2026-11 的复核把差口坐实之后，发现彼方接不进去（见下节）。这条决定**可以被推翻**，但推翻的前提是把共享层改造完，而不是在彼方那边硬接。

## 差口（2026-11 复核实测，非推测）

| # | `面板机制` 的模型 | 彼方需要的 | 性质 |
|---|---|---|---|
| 1 | 球是**圆**：`CLOSED_SIZE` 一个数，`orbStyle` 宽高同值，clip-path 用 circle | 宽 ≠ 高（`悬浮球直径` / `悬浮球高`），球是**圆角矩形** | 核心几何模型不同 |
| 2 | `panelRectView` 只在本文件内用，**不导出** | 遮罩挖洞要知道面板画在哪、圆角多大 | 导出面缺 |
| 3 | `applyFrame` 由内部 `watch` 调度，**不导出**、没有"几何变了"的信号 | 弹条定位与遮罩重摆要能在面板上屏 / resize 时被通知 | 导出面缺 |

另有四块彼方独有、共用层完全没有的东西：**遮罩挖洞**（4 边带 + 4 角径向渐变补丁）、**「面板没上屏」的 1.8s 看门狗 + 状态字 + `onErrorCaptured`**、**更新弹条注入宿主页**。其中前两块是为一起真实事故（Firefox 里 iframe 打开后不画，`elementFromPoint` 全落空）建的诊断层。

## 为什么没在这轮做

1. 差口 1 是**改共享层的核心几何**（圆形 → 圆角矩形；`r = min(w,h)/2` 时与其他两家数学等价），验收面从 1 个插件变成 3 个。
2. 彼方这一层是整个插件里**真机坑最密**的地方（README 里六条记录：clip-path 不裁命中测试、`pointercancel` 卡住 `isDragging`、`setPointerCapture`、四角补丁、遮罩不跟 resize、卸载残留），而它**没有任何运行时用例**——最强验证只有 `@vue/compiler-sfc` 编译通过 + 手点。
3. 在这样一种地方一次性重写 600 行、验证只剩"编译通过"，是在赌。

## 要做的话，顺序是

1. **只改共享层**：球从圆泛化成圆角矩形（矩形 + `r = min(w,h)/2`，另两家的渲染参数不变）；导出 `面板矩形` / `面板尺寸`；`applyFrame` 之后给一个可订阅的几何信号。这一步可被现有用例覆盖。
2. 再让彼方接上：几何 / 拖动 / 阴影 / 偏好走 `面板机制`，**遮罩 / 看门狗 / 状态字 / 弹条继续留在彼方**（它们叠在上面，用第 1 步导出的矩形与信号）。
3. 遮罩与看门狗要不要也上移到共用，等第 2 步做完、壳变薄之后再看——那时候才看得清它该长什么样。

## 已经做了的那一半

**界面偏好**（2026-11，提交 `44c4244`）：`彼方_主题` / `彼方_悬浮球` 两个整键覆盖的全局变量 → 接上 `共用/界面偏好.ts` 的纪律（全局优先 + localStorage 兜底 + 只写相对基线改动过的字段 + 没基线不写全局），新键 `彼方_界面偏好`，旧键只读不删。
这块**没有 UI 风险**，且它建出来的那个 adapter 恰好就是 `面板机制` 配置里 `存储: 偏好存储` 要的输入——第 1 步之后直接可复用。
