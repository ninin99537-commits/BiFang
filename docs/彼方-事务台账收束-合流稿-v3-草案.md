## 0. 一句话

收束 = **创建层防歧义**（时间锚纪律 + 粒度规则）＋ **轮次层强制对账**（逐条表态 + 未回票差集 warn/标记）＋ **危害层降级**（未回票 → 注入"待确认"）＋ **兜底层**（人类面板 + 主 AI 闭环）。
代码只做机械事；**死活是语义裁决，只归模型**；账龄只当展示上下文，不当事判据；不新增字段。

## 1. 钉死的事实（含新发现 F6b）

F1–F8（v1 稿）经双方核对成立。F6 拆成两条：

- **F6a**：无编号"重抄内容 + 改了状态"的载荷被指纹去重吞掉——改动落不了地（`事务台账.ts:290-293`）。
- **F6b（新，代码序实锤）**：无编号整份重抄时，每条都先置真 `收到记录`（`:289`，在指纹去重 `:291-293` 之前）再被去重吞掉 → 合并末尾照样执行 `封顶`（`:309-310`）→ **静默淘汰最旧终态**（实测 9 终态 → 8，T1 被删），正面违反 `:276-278` 注释"没变就不该让旧账凭白老化"。带编号重抄（规范形态）安全。

**注入判据钉死：未回票，不是账龄。**

| 用途 | 判据 | 约束 |
| --- | --- | --- |
| 注入"（未表态，待确认）"标记 | 本轮未回票 = 卡上全部进行中编号 − 本轮载荷**命中库中编号**的集合 | 逐轮、无状态、零字段；"命中"含改了或没改；幽灵编号不计票 |
| 给更新 AI 的"（写下 10-17；内容锚…）" | 已有 `时间` 字段 + 当前剧情时间 | 纯展示上下文，参与零标记/裁决；但它是作废门槛①的执行前提 |
| 封顶淘汰次序 | 数组顺序（写下先后），只淘汰终态 | 不引入新语义 |

已回票集合从合并处**临时传参**给世界书写入环节（不落库）→ 面板看不到该标记、切聊天后标记自然消失（语义正确：它描述"本轮"）。

| # | 改动 | 位置 | 成本 | 类型 |
| --- | --- | --- | --- | --- |

| 5 | 差集 warn + 未回票 → 注入逐条"（未表态，待确认）"标记 | 合并 + 渲染（临时传参） | 小、零字段 | 代码 |

| 7 | 主 AI 闭环两句 + **名词对齐**（证据须落在该条 `内容` 的具体物品/人名/地点上，如"买两支笔"不算 T7、"拿了盒软糖"才算） | 提示词 | 零 | 提示词 |

## 3. 验收口径（第一版补丁；T6 是窗内案例 → 1–2 轮内可出结果）

| 项 | 口径 |
| --- | --- |
| T6 | **不许沉默**：1–2 轮内必须给带理由的裁决（作废+原因，或 继续+理由，都算过；整轮不提 T6 = 唯一确定的失败）。裁决对错由用户按读法 A/B 真机判 |
| 逐条表态 | 差集 warn 为凭证：**per-item 最长连续未表态 ≥3 轮 → 人工介入**；整轮均值 ≥80% 只当参考线（均值会掩盖"同 10% 每轮被漏"） |
| F6 | 新增测试三例：纯重抄（无编号）→ 原样不动、不触发封顶；重抄 + 改状态（无编号）→ 状态落地；原 [3]改写无效 / [5]去重 / [6]封顶 / [7]空回合 保持绿 |
| 未回票标记 | 模型全回票的轮次 → 无任何标记；漏一条 → 注入格里该条逐条标"（未表态，待确认）"+ 日志记差集 |
| 主 AI 闭环 | 正文出现指向该条**具体名词**的处置或放弃 → 1 轮内台账跟随（作废/完成） |
| 粒度 / 锚 | 对照卡 T4/T7/T8 = 1 条；新开条目增速下降；新内容相对时间词 warn 为 0 |

## 4. 诚实的边界

- **系统能看见"没投票"，看不见"假投票"**（漏票能数，"每条都回继续但没真看"与真继续在合并侧逐字节等价）——后者是模型可信度的终极依赖，无解，接受；这也是 #5 差集 warn 必须存在的原因。
- 作废/完成无代码路径，只能靠模型裁决 + 人类面板/主 AI 闭环兜底。
- **T6 由"铁证"降级为"歧义样本"**：旧的"窗内/窗外"二分被用户修正——判断 T6 所需信息早在卡上（时间字段 + 相对锚 + 当前剧情时间），滑出窗口不构成解释；真正毛病是**冻结内容里的锚是相对词**（读法 A"当晚绑定，过期→作废"与读法 B"承诺未兑现，小孩还惦记→继续"皆自洽）。
- 账龄判据被同类同龄反例（T6/T7）钉死；任何以天数/轮数为触发器的自动出清方案均不予采纳。

## 5. 用户三答的落点

1. **双模型（Gemini + DeepSeek 都可用、不固定）** → 设计不能依赖单一模型的服从度。代码侧防线（#4 F6 修复、#5 L1 标记**第一天就开**）是承重墙；提示词是尽力层，服从度由差集 warn 度量。两种典型偏差（整份重抄 / 只回最小集漏票）正好各是 #4 / #5 的验收样例。
2. **T6 是窗内案例** → 治它的是 #3 逐条表态 + 作废授权 + 三门槛 + 必带原因；**主 AI 闭环治不了 T6**，它管的是"戏再也不回来"的长尾（20 层前定下、之后没被任何正文碰过的承诺）。两者都要做，但 T6 的验收账不能记到闭环头上。
3. **设置：读取 3 层 / 每轮更新** → 每轮都是表态机会（利好逐条表态与统计）；窗外面积最大（利好主 AI 闭环）。读取层数 3→5 **先别调**：只缩小窗外面积、解决不了 20 层前的承诺，还每轮多读两层的钱；先验证 #3 + #7 这两条免费的。
