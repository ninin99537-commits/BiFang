### 1.2 缺陷 1（严重）：`'无'` 在快照往返后丢失

**位置**：`账本迁移.ts:499`

```ts
...(规范化必演(raw.必演) ? { 必演: 规范化必演(raw.必演) } : {}),
```

`规范化必演('无')` 返回 `null`（正确），但这一行把它当成"没内容 → 不写这个键"，
于是 `'无'` **整条消失**，读回来是 `undefined`。

**实测**：

```
FAIL  必演 = '无'  → 往返后 undefined
FAIL  提醒有「上一道指令没有必演」（期望没有）
```

**为什么严重**：这条往返**每轮都走**。
存：`快照.ts:155` → `账本字段表` 存行（`:201` 原样克隆，`'无'` 存进去了）
读：`快照.ts:117` → `读回` 行 → `规范化指令`（`:203`）→ `:499` 丢掉 `'无'`

⇒ 导演这轮写 `"无"`，下轮读回就是 `undefined` → 提醒照响 → **正是 ① 要消灭的行为**。

**修法**：

```ts
...(raw.必演 === '无'
  ? { 必演: '无' }
  : 规范化必演(raw.必演)
    ? { 必演: 规范化必演(raw.必演) }
    : {}),
```

⚠️ 别写成 `必演: raw.必演 ?? null` —— 那会让脏值（如 `"她走了"`）绕过
`规范化必演` 的五个字段补全（`命运`/`角色ID`/`镜头外`/`既成事实`/`未执行轮`）。

### 1.3 缺陷 2（严重）：提示词自相矛盾

`prompts.ts` 里相隔两行，要求相反：

| 行 | 原文 | 要求 |
|---|---|---|
| **184**（旧句未删） | 「只有"这一场只要气氛/过渡、没有确定事件"时才给 **null**」 | 没有 → 写 `null` |
| **186**（dsh 新加） | 「**明确没有就写 "无"**……**不要留空/null**」 | 没有 → 写 `"无"` |

模型选第 184 行 = ① 完全没做（`null` = 漏写 = 提醒照响）。

**修法**：第 184 行末尾改成「没有确定事件时写 `"无"`（见下一条）」，把 `null` 从这条里拿掉。

### 1.4 缺陷 3（中）：`提醒.ts:215` 的 `=== '无'` 是冗余分支

当前判据：

```ts
if (!上一道 || 上一道.已跳过 || 上一道.必演 === '无' || 上一道.必演) return [];
```

`'无'` 是**真值字符串**，`|| 上一道.必演` 本来就会 `return []`。
`=== '无'` 这一支删掉行为不变 —— 实测变异 B（删掉它）**0 红**。

⇒ 用例里对应那条断言是**假绿**：它测不到任何东西。

**处置建议**：留着无害（防御性写法），但**用例里要标明它是冗余**，
或者干脆删掉以免后人误以为"三态靠这一支"。

### 1.5 缺陷 4（严重）：用例完全测不到快照往返

**决定性证据**：把 `账本迁移.ts:499` 修好（加上 `'无'` 分支）→ 用例仍然 **17 通过 / 0 失败**。

```
=== 变异 D【关键】：修复往返 —— 用例若仍绿 = 它测不到往返 ===
```

修复和不修复，用例表现一样 ⇒ **它没有覆盖生产路径上真正会坏的那一段**。

**要加的用例**：

```ts

  const 原 = 造账({ ...基础指令, 必演 });
  return sanitizeSnapshot(快照载荷(原) as any)?.当前指令?.必演;
```

## 二、③ 构建标记自动化（方案 C）

### 2.1 实现核对：✅

`tests/daoyan-构建标记.test.ts`，判据 = `标记日期 >= src/剧情导演/ 最新文件日期`。
结构正确：格式校验 → 日期比较 → 判据自检（`昨天 < 今天`、`乱格式 → 0`）。

### 2.2 变异测试：✅ 两个方向都抓到

| 变异 | FAIL 数 |
|---|---|
| A 标记日期改回 `2026-11-12` | **1** |
| B 标记格式改坏（`daoyan-v23-...`） | **4** |

还原后 8 通过 / 0 失败。

### 2.3 缺陷（真实盲区）：同一天改代码抓不到

**实测**：把标记描述改成 `'daoyan-2026-11-13-旧描述没更新'`（日期不变）→ 用例**绿**。

```
[2] 标记日期 >= src/剧情导演/ 最新文件日期
  PASS  标记日期(2026-11-13) >= 最新源码日期(2026-11-13)
结果: 8 通过, 0 失败
```

**为什么这是最常见的场景**：一天里通常改好几轮。
今天（11-13）我们就改了 ① ② ③ + 世界书 A 案 + 超期收章 + 死字段 + J 批 ——
只要日期是当天，改多少次都不会红。**这恰好是"真机分不清跑的是哪一版"的原始场景。**

### 2.4 建议：日期不够，要内容指纹

方案 C 判据从"日期"升级为"**源码内容指纹**"：

```ts
// 构建标记里带一个短指纹
export const 构建标记 = 'daoyan-2026-11-13-<8位指纹>-世界书A案+...';

// 用例：算 src/剧情导演/*.ts|*.vue 的内容 sha1 前 8 位，比对标记里的指纹
```

这样：
- 改任何一行源码 → 指纹变 → 标记没跟着改 → **红**
- 只改注释也算改（合理，因为产物变了）
- 不受 mtime 被 `copyFileSync` 保留的影响（这也解决了注释里提到的那个坑）

**注意**：`index.ts` 自己含标记，算指纹要**排除它自己**，否则改标记会让指纹变、永远红。

如果觉得指纹太重，**退一步的最小改法**：判据改成
`标记里的描述必须提到最近改动的文件名`（弱一些，但比纯日期强）。
不过我更推荐指纹 —— 它一次解决"同一天"和"mtime 被保留"两个问题。
