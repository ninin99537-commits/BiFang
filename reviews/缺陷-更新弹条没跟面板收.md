# 缺陷定位：更新弹条没跟着面板收（2026-11-13）

## 用户报的现象

> 「就是比如更新中之类的提示条，我打开面板的时候提示条会挂在面板左边」
> 「打开面板那一刻就已经挂在左边」

## 先排除了两个错的方向

我一开始猜是 toast（`dj-toast-stack`），后来又猜是球气泡（`dj-orb-tip`）。**两个都错**，而且我用它们做了好几轮实验，全部假绿。

### 假绿记录（必须记下来）

| 探针 | 我以为会怎样 | 实际 |
|---|---|---|
| 「测试连接」按钮 | 产生一条 toast | **不产生**。结果只写进面板内的 `测试结果` ref（`悬浮球界面.vue:1679-1690`） |
| 「清理世界书条目」按钮 | 产生 toastSuccess | 无条目时**不产生**（走的是"没有导演条目了"分支之前就 return） |
| 「复制报错发给助手」按钮 | 产生 toast | 无报错时**不产生** |

三次都得到 `toastCount === 0`，三次都判成 "PASS: 面板开时 toast 被抑制"。**装置根本没产生目标事件，PASS 是假的。**

## 真正定位：扫全父文档的可见浮层

探针：`tmp/cdp/scan-visible-floating.js`

面板打开时，酒馆父文档里三个浮层的真实状态：

| id | 位置 | z-index | 可见 | 在面板左边 |
|---|---|---|---|---|
| `dj-toast-stack` | l=78 | 2147482998 | 否（空栈） | - |
| `dj-orb-tip` | l=284 t=175 | 2147482998 | 否（opacity:0） | - |
| **`剧情导演_更新弹条`** | **l=331 t=409 169×40** | **2147482999** | **是** | **true** |

面板视口 `left = 679`，弹条 `right = 500` → 正好贴在面板左边。
弹条文本：`导演编排中…` + `中断` 按钮。

**这就是用户看到的那条。** 它是第三套独立浮层，既不在 toast 栈里，也不走 `setToastSuppressed`，所以 `面板机制.ts:418` 的抑制链对它完全无效。

## 根因

`src/剧情导演/悬浮球界面.vue:1172`

```js
watch([更新中, () => updatingStore.message], ([active, message]) => {
  ...
  if (active) {
    更新弹条El = 确保更新弹条(doc);
    更新弹条El.style.display = 'flex';   // ← 面板开着也照样显示
```

`定位更新弹条()`（`:1118-1133`）同理，只算球锚点，不检查面板状态。

## 烟火有正确参照

`src/烟火_世界运转/推进弹条.ts:110`

```js
watch([依赖.推进中, 宿主.panelOpen], ([active, open]) => {
  if (active && !open) 建();
  else 移除();          // ← 面板一开就移除
});
```

剧情导演这条弹条注释里写着「与彼方/烟火同款」，是从烟火抄来的，**抄的时候漏了 panelOpen 这一半**。

## 同款缺陷：彼方

`src/彼方_NPC幕后生命状态系统/悬浮球界面.vue:854`

```js
watch([updatingActive, updatingMessage], ([active, message]) => {
```

同样没有 panelOpen。彼方面板开着时 `彼方_更新弹窗`（z 2147483003）也会挂在左边。
`:349` 的 `watch(panelOpen, 开 => setToastSuppressed(开))` 只管 toast，管不到弹条。

## 修法

watch 依赖扩成 `[更新中, message, panelOpen]`，面板开着时不显示。

优先选**移除式**（跟烟火一致）而不是 `display:none`：
`display` 方式要额外处理「面板开关一次后 display 与 更新中 不同步」的组合态，容易再漏；
移除式配合「面板关且仍在更新中时重建」天然覆盖所有组合。

**不会丢能力**：面板里已有「中断编排」按钮（`悬浮球界面.vue:224`，`v-if="更新中"`）。

## 变异要求

| 变异 | 期望 |
|---|---|
| M1 删掉 watch 依赖里的 panelOpen | 红 |
| M2 删掉 panelOpen 为 true 的隐藏/移除分支 | 红 |
| M3 删掉「面板关回去且仍在更新中时恢复显示」 | 红（否则变成"面板开一次后再也不出弹条"） |

M3 是这次修法最容易引入的新 bug，必须单独钉。

## 教训

**「抑制机制工作正常」和「用户看到的那条被抑制了」是两回事。**

我用 `decisive-suppress-test.js` 证明过：往 `dj-toast-stack` 塞一条 → 开面板 → 条被撤掉（`toastCount` 1→0）。这个结论是**对的**，但它只覆盖了 toast 那一套。用户看到的根本不是 toast。

判断「某个抑制机制有效」之前，必须先确认**用户看到的东西属于这套机制**。这一步不做，后面所有实验都是在验证一个不相关的东西。
