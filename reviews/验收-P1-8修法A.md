export function 建壳卸载器(壳的app: WeakMap<any, any>): (元素: any) => void {

## 五、真机复核（2026-11-13 补，桥已通）

**结论：代码验收通过 ≠ 真机生效。P1-8 初版在真机上完全没生效；v26 修复后真机已生效。**

### 5.1 三条待验的实测结果

| 待验项 | v25（初版） | v26（修复后） |
|---|---|---|
| 同 id 壳只剩 1 个 | ❌ 人为插入重复壳后仍是 **2 个**，去重返回 **0** | ✅ 插入后 2 个 → 重跑后 **1 个** |
| 父窗口 resize 监听不累积 | ❌ 旧 app 从未 unmount | ✅ 多轮热重载后 `面板机制` 监听**恒为 1 份** |
| 控制台/产物版本 | v25 | ✅ v26（`0a46771a`，`取壳文档`×4，`清掉同id壳(document`×0） |

### 5.2 根因（详见 `reviews/缺陷-P1-8-真机去重查错文档.md`）

`悬浮球界面.ts:39` 传的 `document` 是**脚本 iframe 自己的 document**，
而壳是 `$('<iframe>').appendTo('body')` 插到**父文档**的。
真机实测：自己 doc 命中 **0** / 父 doc 命中 **2** / `$('body')` 解析到 `BODY@父`。

对照实验（函数体逐字照抄）：

| 步骤 | 同 id 壳数 |
|---|---|
| 起始 | 1 |
| 插 1 个重复壳 | 2 |
| `清掉同id壳(document, id)`（现状）→ 返回 0 | **2（原地不动）** |
| `清掉同id壳(父doc, id)`（对照）→ 返回 2 | **0（全拆掉）** |

**只差 `doc` 一个参数。**

### 5.3 为什么 162 全绿 + 4 变异全命中仍然漏了

用例里的假 doc 是**外部注入**的（`querySelectorAll: () => 元素表`），
验的是「给一个能查到壳的 doc，函数拆得对不对」——
**从没验过「调用点传进来的 doc 是不是壳所在的那个 doc」**。

这是**接线（wiring）问题**，不是逻辑问题。
纯函数抽得再干净、变异再全，只要没人验调用点的实参，接线错了照样全绿。

> 与房间第 8 次踩坑（「判据本身想当然」）同型：
> 断言写的是我以为的输入，而不是真机实际的输入。
> 也说明「抽成纯函数」这一手段有**边界** —— 它让逻辑可测，但**接线仍需单独一条用例**。
> 已在 `#94` 写进房间台账：**变异测试保逻辑正确，不保接线正确**。

### 5.6 真机验证明细

**去重（DOM 层）**：插入重复壳 → 2 个 → 真实重跑挂载入口 → **1 个**。旧壳被打上 `data-shell-tag` 标记，重跑后标记壳数为 0 = 旧壳确实被拆。

**不泄漏（监听层）**：探针记录父窗口每个 `resize` 监听器的**来源栈**。多轮热重载后：

```
存活总数        13
来自面板机制     1     ← 恒为 1，不累积
```

**热重载走哪条路径**（2026-11-13 更正，kimi `#105` 指出原文与 `#102` 矛盾）：

热重载时**两条路径都会发生**，但顺序与作用不同：

1. `JS-Slash-Runner` 先 `remove` 旧脚本 iframe → `dispatch` → **`pagehide`**（`悬浮球界面.ts:76-79`）
   → 旧脚本实例 `app.unmount()` + 自己那个壳 `$app.remove()`。
2. 然后**脚本 iframe 被重建、脚本整体重跑**（真机实测：旧 iframe 不在 DOM、脚本 window 标记丢失）
   → 新实例顶层 `$(() => {...})` 执行 → `清掉重复壳` → 拆掉**残留的同 id 旧壳**（含僵尸壳）。

所以：**`pagehide` 只清自己那一个，重复壳/残留壳靠新实例重跑去重**。两条路径互补，
不是「热重载只走 pagehide」。监听不累积的实测结论（`面板机制` 恒为 1）对两条路径都成立。

### 5.7 一处需要记录的自查（我先前的错误结论）

我曾用 `await import('...index.js?t=...')` 模拟重载，得到「4 轮净增 4」并判为泄漏。
**那个结论作废**：带 cache-bust 的 `import` 会产生**新的模块实例** → 新 `WeakMap` 为空 →
必然 `unmount` 不了旧壳。这是 ESM 语义的必然结果，**不是 P1-8 的缺陷**，真机也不会走这条路径。

教训与 `#94` 同源：**造实验装置时，装置本身不能引入被测代码不会遇到的场景。**

### 5.8 僵尸壳成因更正

原判「热重载 contentDocument 未就绪」**错**。真机证实：
静态服务器没开 → 壳 srcdoc 里 import 404 → 壳建好了、app 也创建了，
但脚本没跑起来，停在 `(0,0)` 什么也不做，成为僵尸壳。

### 5.9 顺带澄清

- 先前用 `probe-forcestyle.js` 测 computed border 时，循环没 `break` 选到了自己插入的假壳，
  那个结论作废。清掉假壳后重测：真壳 `computed border-style = none`，正常。
- `#dj-orb-force-style` 也插进了脚本自己的 head（父 doc 没有），但壳内联已带 `border:none`，
  那条规则真机上多余、不影响观感，不改。
- `copyStylesTo` 读自己的 head 是**故意的**，不是同一个错。
