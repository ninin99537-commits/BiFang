# 缺陷 · P2 2.5 必演三态：两处会让改动失效的地方

> 需求方（opencode）2026-11-13。dsh 的 ① 已交付实现，需求方独立复验发现两处问题。
> 行为矩阵 6/6 全对，但**生产路径上仍会失效**。

## 一、先说好消息：行为是对的

用真实 `结构提醒` + `规范化必演` 跑，6/6 通过：

| 输入 | 提醒里有「上一道指令没有「必演」」 | 期望 | 结果 |
|---|---|---|---|
| `必演 = null`（没说） | 有 | 有 | ✅ |
| `必演 = '无'`（明确声明没有） | 没有 | 没有 | ✅ |
| `必演 = {内容:'x',...}`（有事件） | 没有 | 没有 | ✅ |
| 老账本 `必演` 字段整个缺失 | 有 | 有 | ✅ |
| `规范化必演('无') === null` | — | null | ✅ |
| `规范化必演({内容:'x'})` 仍返回事件 | — | 非 null | ✅ |

引擎侧链路完整：`引擎规则.ts:803` `明确无必演 = 下一幕.必演 === '无'` →
`:805` 传给装配 → `:964` `必演: 必演 ?? (明确无必演 ? '无' : null)` 写回指令。

## 二、缺陷 1（严重）：`'无'` 在快照往返后丢失

### 位置

`src/剧情导演/账本迁移.ts:499`

```ts
...(规范化必演(raw.必演) ? { 必演: 规范化必演(raw.必演) } : {}),
```

`规范化必演('无')` 返回 `null`（这是**正确的**——它是给"有事件"用的）。
但这一行把它当成"没内容 → 不写这个键"，于是 `'无'` **整条消失**，读回来是 `undefined`。

### 实测

```
FAIL  必演 = '无'      → 往返后 undefined
FAIL  必演 = null      → 往返后 undefined      ← 这个无所谓（提醒用 !必演 判）
PASS  必演 = 对象      → 往返后 {"内容":"她推门进来",...}

往返后 当前指令.必演 = undefined
FAIL  提醒有「上一道指令没有必演」（期望没有）
```

### 为什么这是严重的

这条往返**每轮都走**：

- 存：`快照.ts:155` `...快照载荷(data)` → `账本迁移.账本字段表` 的 `存` 行（`:201-202` 原样克隆，`'无'` 存进去了）
- 读：`快照.ts:117` `...sanitizeSnapshot(snapshot)` → `账本字段表` 的 `读回` 行 → `规范化指令`（`:203`）→ `:499` 丢掉 `'无'`

所以导演这一轮写了 `"无"`，下一轮读回来就是 `undefined` → 提醒照响 →
导演被反复催"上一道指令没有必演"，而这正是 ① 要消灭的行为。

**改动在单轮内是对的，跨轮就失效了。**

### 修法

`规范化指令` 里 `必演` 要保留三态，不能只留"有事件"：

```ts
// 账本迁移.ts:499 附近
...(raw.必演 === '无'
  ? { 必演: '无' }
  : 规范化必演(raw.必演)
    ? { 必演: 规范化必演(raw.必演) }
    : {}),
```

⚠️ 注意别写成 `必演: raw.必演 ?? null` —— 那会把任意脏值（字符串 `"她走了"`）原样带进账本，
绕过 `规范化必演` 的字段补全（`命运`/`角色ID`/`镜头外`/`既成事实`/`未执行轮` 五个字段）。

### 变异测试要求

删掉 `raw.必演 === '无'` 这一支，用例必须变红。

## 三、缺陷 2（严重）：提示词自相矛盾

### 位置

`src/剧情导演/prompts.ts`，两句相隔两行，要求相反：

**第 184 行**（旧句，未改）：
> 只有"这一场只要气氛/过渡、没有确定事件"时才给 **null**。

**第 186 行**（dsh 新加）：
> **明确没有就写 "无"**……**不要留空/null** —— 那表示"你没填"，脚本会提醒"上一道指令没有必演"。

### 为什么这是严重的

模型读到的是一份**互相抵消**的指令。第 184 行说"没有就写 null"，第 186 行说"不要写 null"。
模型选哪句都合理 —— 而选第 184 行就等于 ① 完全没做（`null` = 漏写 = 提醒照响）。

这不是"措辞不严谨"，是**同一份提示词里两条相反的硬指令**。必须删掉第 184 行末尾那句，
或者把它改成"没有确定事件就写 `"无"`"。

### 建议改法

第 184 行末尾：

```
… 就写进必演; 没有确定事件时写 "无"（见下一条）。
```

把"null"从这条里彻底拿掉，让三态只有一处定义（第 186 行）。

### 另一处需要确认

第 363 行（平静模式）：
> **不要安排必演事件**: 「下一幕.必演」一律写 null …

这条是**平静模式专用**（`prompts.ts:330` 的注释：平静期只记账不下令）。
平静期写 `null` 是**对的**（那时候确实不该催）—— 但需要 dsh 确认：
平静期写 `null` 会不会触发 `上一道缺必演` 提醒？
`提醒.ts:214` 有 `if ((Number(账本.平静场数) || 0) !== 0) return [];` 挡着，所以不会。
**这条不用改，但请在用例里钉住**（平静期 `必演=null` 不响提醒）。
