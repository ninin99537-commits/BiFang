# 裁定 · P2 2.4「删反向豁免」——立批前提已被真机数据推翻（2026-11-13）

> 需求方（opencode）。真机：`最后生还者` 聊天，1541 楼，账本 78 轮。
> 结论：**P2 2.4 不再按原设计立批**。它已经从「改行为」变成「删死代码」，且删了会**减少**用户可见信息。

---

## 一、原设计与新事实

`reviews/待批-P2-单一裁决点.md` §2.4 的前提是：

> 「导演有明确意图」这条反向豁免恒真 → 四条结构规则 0 次生效 → 89.7% 的戏没有张力。
> 所以要**删掉**这条豁免。

但代码里它已经被一个**开关**接管了（`引擎规则.ts:619`）：

```ts
const 让位 = 结构规则优先 === false && 导演有明确意图;
```

`schema.ts` 里 `结构规则优先: z.boolean().default(true)`，`update.ts:389` 从设置接线，
`悬浮球界面.vue:900` 有开关和说明。**默认 true ⇒ 生产环境 `让位` 恒为 false ⇒ 豁免已经不生效了。**

P2 2.4 要删的，是 `让位` 为 true 的那条**回退路径**——只有用户手动把开关关掉才会走到。

## 二、真机实测：开关确实有行为差异（不是死代码）

真机设置实测（`getVariables({type:'global'})`）：`剧情导演_settings.导演.结构规则优先 === true`。

用**这份真实账本**（`tmp/ledger-slim.json`，第 1539 楼、连续低张力 54、硬性要求 249 字）
离线跑 `构造本幕指令` 两次：

| 开关 | 节拍 | 代码调整 |
|---|---|---|
| `true`（生产默认） | **阴影** | `张力曲线：导演原拟「日常」→ 代码改成「阴影」，因为连续 54 幕低张力（结构规则优先已开；导演原拟已记入本轮回执）` |
| `false`（老行为） | **高潮** | `张力曲线：连续 54 幕低张力，建议埋险；但导演本幕有明确要求，保留其节拍「日常」`<br>`收束出口：本章已进入「收束」，节拍不能是「日常」（既不推进也不现在还债）→ 改为「高潮」` |

**差异是真的**：节拍从「日常」变成「阴影」。开关不是装饰。

同时它也证明**收束出口不吃豁免**（`:741` 注释写明），所以 `false` 时仍然改成了「高潮」——
这条通道本来就已经独立于豁免在工作。

## 三、为什么不能删（三条理由）

### 1. 删了会**减少**用户可见信息，不是修复

`true` 分支的文案是：
> `导演原拟「日常」→ 代码改成「阴影」，因为连续 54 幕低张力（结构规则优先已开；导演原拟已记入本轮回执）`

`false` 分支的文案是：
> `连续 54 幕低张力，建议埋险；但导演本幕有明确要求，保留其节拍「日常」`

两条都**记录了导演原意**。删掉 `false` 分支不会让信息变多，只会让"用户主动关掉开关"这个操作**失效**。

### 2. 它是用户已拍板的 A/B 退路，不是遗留物

`悬浮球界面.vue:900` 的界面文案写得很清楚：
> 「关掉它则完全按导演给的节拍走（老行为）」

用户当初要的就是「真机 A/B 的退路」。删掉 = 把用户已经拿到手的开关变成单向阀。

### 3. P2 文档自己的硬边界禁止

`reviews/待批-P2-单一裁决点.md` §三.4：
> **2.4 必须单独一批，且必须带真机观察口径**。

现在的真机观察口径已经跑出来了，结论是「开关工作正常」。按这条口径，2.4 的**验收标准本身就不成立**。

## 四、真正的残留问题（值得单独立批的）

真机暴露了一个**别的问题**，比 2.4 更值得修：

### 真机账本里的指令是旧产物时代的

`当前指令`（编号 17，生成楼层 1539）的 `代码调整` 里写着：
> `连续 54 幕低张力，建议埋险；但导演本幕有明确要求，保留其节拍「日常」`

**但真机设置是 `结构规则优先 = true`。** 按现在的代码，这不可能生成这条文案。

⇒ 这条指令生成于**开关上线之前**（旧构建产物）。它一直躺在账本里没被重算。

**这不是 bug**——账本本来就是历史记录。但它说明两件事：

1. 真机验收**必须用新生成的指令**。1539 楼那份是旧产物，不能当 A/B 基线。
2. `构建标记` 还停在 `daoyan-2026-11-12-提醒规则成表v22`，而代码已改到 11-13。
   真机日志第一行分不清跑的是哪一版 —— 这才是当前该修的东西。

### 建议：P2 2.4 改判为「不改」，另立「构建标记 + 旧指令重算」

| 项 | 处置 |
|---|---|
| P2 2.4 删反向豁免 | **撤批**。理由是立批前提（豁免恒真）已被开关绕过；删了只会砍掉用户已拍板的 A/B 退路 |
| 构建标记 v22 → v23 | **收尾必做**。真机日志第一行要能分辨版本 |
| 旧指令重算 | **不做**。账本是历史记录，不该被事后改写；下一轮生成自然会用新代码 |

## 五、这条记录本身的价值

P2 2.4 是**唯一一个「文档写的病」和「代码现在的病」不一致**的项：

- 文档基于 113 快照（开关上线前）→ 结论"豁免恒真"
- 代码已经是开关版（`默认 true`）→ 豁免已失效

如果不跑真机 A/B，按文档删掉 `让位`，会：
1. 删掉 `false` 分支 → 用户关掉开关时行为变得不可预期；
2. 真机上**看不出任何变化**（因为 `让位` 本来就是 false）→ 验收会以为"改成功了"，实际是白改。

**这正是「用旧产物下结论」的第 7 次同型风险的翻版**：这次不是我用旧产物，是**文档用旧结论**。
