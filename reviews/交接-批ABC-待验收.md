## 3. 批 C 有一处**新增面**，请你重点看

盘点报告原本只写了 `连续高阈值` 没接 settings。
批 C 派活前实跑发现 **`连续低阈值` 是同一个病**：

```
提醒.ts:808（改前）  if (连高 >= 连续高阈值默认)   ← 至少是常量
提醒.ts:812（改前）  if (连低 >= 3)                ← 字面量 3，连常量都没用
```

**为什么盘点时漏了**：字面量 `3` 恰好等于 `连续低阈值默认`（`schema.ts:58`）。
所有用例都用默认值 → 「默认值下行为正确」恒真 → 只有改过设置的用户才看得到。

→ 这是**报告本身的缺口**，我在 `报告:897` 后加了更正段，没有静默改原文。

## 4. 建议的验收方法（你可以否掉，自己另定）

### 批 A：红绿 + 变异归因

```bash
node tests/build.mjs tests/daoyan-留白判据.test.ts tmp/a.mjs && node tmp/a.mjs
```

**三条已知容易假绿的点**（报告里都有）：
1. ①②③ 必须分开 —— 三处结果不同（余波/阴影/余波），合并成一条就无法归因
2. ④ 必须拆 ④a/④b 单腿 —— `要留白` 是 OR，全真组合只能证明「至少一条腿通」
3. ⑫ 必须两个夹具 —— 单夹具会让主路径 `:752` 和兜底 `:778` 互相掩盖

### 批 B：**不看红绿，看注释与代码是否一致**

批 B 不动行为，红绿验不出来。有效办法是**双向对照**：

1. 注释里每个断言性短语（「只用于 X」「不用于 Y」「记的是 Z」）→ 去代码找**唯一**读/写点
2. 找不到 → 注释在描述一个不存在的机制
3. 找到两处说法不同 → 其中一处错
4. 同一段注释前后打架 → 读者会信错的那句

⚠️ 这条尤其重要：**批 B 里有一句是我（需求方）写错的量纲**，dsh 照抄。
如果你发现注释与代码不一致，**先看这句是不是从派活单/报告抄来的** —— 错可能在需求文档。

### 批 C：对照组是必须的

只写「传 6 → 不出现」是假绿（函数不读参数、或夹具没触发，都能让它成立）。
必须有「不传 → 出现 1 条」的对照。

另请亲手验一条：`NaN` 兜底。
`NaN ?? 5` 返回 `NaN`，`连高 >= NaN` 恒 false → 提醒**永远不响**（静默失效）。
所以兜底必须写 `Number.isFinite(Number(x)) ? Number(x) : 默认`。
把 `:821` 改成 `阈值?.高 ?? 连续高阈值默认` → 必须红。

→ 你验收时如果看到指纹不符，先查**行尾**再怀疑实现：
```bash
python -X utf8 -c "import io; b=io.open('src/剧情导演/提醒.ts','rb').read(); print('CRLF=%d 裸LF=%d' % (b.count(b'\r\n'), b.count(b'\n')-b.count(b'\r\n')))"
```
