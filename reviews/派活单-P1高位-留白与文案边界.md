### ⚠️ 更正：P5 拆分基线**必须**同步改（2026-11-13 实测，dsh #182 的「不用改」不成立）

dsh 在 #182 说「字段表加导出不破坏 P5 那两条判据，**不用改 P5 拆分基线**」。**实测是错的。**

复现（`tmp/_p5chk.mjs`，直接打包 `tests/daoyan-P5拆分.test.ts`）：

```
FAIL  基线 39 个符号全部仍有声明
      期望 []
      实际 ["是生活幕"]
结果: 15 通过, 1 失败
```

**根因是用例自己的洞，不是实现写错。** `tests/daoyan-P5拆分.test.ts:60-62` 的声明正则：

```js
/^export (?:interface|type|const|function|async function|class)\s+([A-Za-z0-9_\u4e00-\u9fa5]+)/gm
```

只认**直接声明**，不认 re-export。四种写法实测：

| 写法 | 正则 | 说明 |
|---|---|---|
| `export function 是生活幕(...)` | 命中 | 原形态 |
| `export { 是生活幕 };` | **漏掉** | re-export，`提醒.ts` 的正确改法 |
| `export { 是生活幕 as 是生活幕 };` | **漏掉** | 别名 re-export |
| `export const 是生活幕 = 字段表的是生活幕;` | 命中 | 别名赋值，但会被单一定义纪律质疑 |

**修法（推荐）**：给用例的声明正则补一条 re-export 分支，已实测可用 ——
改完「声明总数 40 → 41，基线缺失 `[]`」，[2] 组恢复全绿。

```js
/^export (?:interface|type|const|function|async function|class)\s+([A-Za-z0-9_\u4e00-\u9fa5]+)|^export\s*\{([^}]*)\}/gm
// group(1) = 直接声明名；group(2) 按逗号拆、取 `as` 后面的名字
```

**为什么推荐补正则而不是改写法**：这个正则漏 re-export 是**用例的洞** ——
意味着以后任何符号改成 re-export 都会假红。补它是把洞填上，不是放宽判据。

⚠️ **改完必须验证判据仍能失败**：删掉 `提醒.ts` 的 `export { 是生活幕 };`，用例必须红。
（现有 `:65` 那条「对照: 去掉 export * 就会失联」仍保留，两者不冲突。）

**回执硬要求**：`daoyan-P5拆分.test.ts` 若改，必须写「原文 → 新文 → 为什么」，不许静默改。

## 3. 文案边界 A（改文案的前置条件）

`提醒.ts:255-257` 现状：

```ts
const 天数 = Number(账本.世界时间?.天数) || 0;
const 隔天 = Math.max(0, Math.round(天数 - (Number(该出手.最后行动天) || 0)));
const 多久 = 隔天 > 0 ? `已 ${隔天} 天没动手` : '仍未出手';
```

改成两分支：

```ts
const 最后行动天 = Number(该出手.最后行动天) || 0;
const 隔天 = Math.max(0, Math.round(天数 - 最后行动天));
// 边界 A：最后行动天 为 0/缺失（老账本 / 新建对手）→ 它一次都没被催过，不能说「已 N 天没催」
const 多久 = 最后行动天 <= 0 ? '还没催过它出手' : 隔天 > 0 ? `已 ${隔天} 天没催它出手` : '仍未出手';
```

**这条必须有专门用例**（dsh 点名「无人看守区第一名」）：它只在老账本/新建对手出现，
不特意构造永远看不到。

**边界 B 已核实安全**：逾期按**幕**算（`字段表.ts:379`：`当前幕 - 最后行动幕`），
改文案不污染裁决。

### ⚠️ 更正：「天数之差」是错的（2026-11-13 批 B 复核，opencode 自己写错）

本文原写「模型自报**天数之差**」。**量纲错**，代码事实：

```ts
// 写：update.ts:477
冲突条.最后行动天 = Number(账本.世界时间?.天数) || 0;      // 绝对刻度：故事内第 N 天
// 读：提醒.ts:255-256
const 天数 = Number(账本.世界时间?.天数) || 0;
const 隔天 = Math.max(0, Math.round(天数 - 最后行动天));    // 差在这里才算
```

`最后行动天` 存的是**写入那一刻的故事内累计天数**，不是「差」。差是 `隔天`。
若它真是「差」，`天数 - 差` 就是差减差 → 负数 → 被 `Math.max(0, …)` 吞成 0 → 症状是「永远显示 0 天」。

准确措辞：**「模型自报的故事内累计天数（绝对刻度），代码不校验合理性；只用于文案，不用于逾期裁决」**。

### ⚠️ `:149` 与 `:150` 自相矛盾

`:149` 原句把两个字段合起来说「对手节流用（几幕没出手了）」，但节流只读 `最后行动幕`：

```ts
// 字段表.ts:381  该催对手行动      const 逾期 = 当前幕 - (Number(条.最后行动幕) || 0);
// 字段表.ts:393  取该出手的对手    const 逾期 = 当前幕 - (Number(条.最后行动幕) || 0);
```

**一次都没读 `最后行动天`。** 于是 `:149` 说「节流用」、`:150-151` 说「不用于逾期裁决」，
同一段注释里互相否掉，读者会停在第一句。必须拆成两句。

```

用户设置 连续低阈值 = 6：  引擎调整 0 行（尊重设置）   提醒「低张力」1 条   ← 只有引擎生效
```

这和 dsh 说的「无人看守区」同一族 —— 默认值把缺口盖住了。

**所以批 C 必须两个阈值一起接**，只接高阈值 = 修一半。

```ts
  /** 张力阈值: 生产路径由 settings 传入; 不传 → 退回 schema 默认常量 */
```
