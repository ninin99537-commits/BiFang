## 二、两处我要记下来的边界（不影响通过）

### 1. 对照② 注入了 `已换聊天: () => false`，没有调真实函数

真实 `已换聊天()`（`update.ts:624-632`）里有 `if (!发起聊天) return false;`。用例里那行是注入的桩，所以它验的是 `安排补推` 的**分支接线**，不是真实 `已换聊天(null)` 的返回。

**这不构成缺陷** —— `安排补推` 是缝，缝的行为已被钉住；真实函数那三行是纯函数，源码辅助断言里没有覆盖，但风险极低（读不到 ID 就照旧，是"宁可照做也不丢结果"的既定取向）。

**记一条**：以后凡"注入桩替代真实函数"的对照，交付说明里要写明"验的是哪一段、没验哪一段"。

### 2. 守卫跳过时 `补推定时器` 停在旧句柄上

```ts
补推定时器 = 安排补推({ …, 执行: () => { 补推定时器 = null; … } });
```

守卫 `return` 时 `执行` 不跑 → `补推定时器` 保留一个已过期的句柄，直到下一次入口 `clearTimeout` 才归零。

**不是 bug**：`clearTimeout` 对已触发的句柄是 no-op；唯一后果是"非 null"这个状态多留一会儿，而它只被用来 `clearTimeout`。**不派活**，记在这里免得下次误判。

## 五、一条通用纪律（写进房间口径）

**源码级正则断言是脆的**：实现一改就得跟着改，而且它只证明"字在那儿"，不证明"行为对"。以后凡"某条纪律必须成立"，优先写**行为断言**（假宿主 + 断言调用记录）；源码断言只作防回退的辅助，并在用例里标注"脆"。
