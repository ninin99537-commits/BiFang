剧情导演 · 留白判据 —— **归因污染**（2026-11-13，需求方复核 dsh 批 A）

# 问题

`tests/daoyan-留白判据.test.ts` 的 ① 标称测「rule1 高张力 → 余波」，
但它用的张力夹具 `连续高` 的 `最近节拍 = ['受挫','反转','高潮']` **以「高潮」结尾**。

后果：`rule4`（高潮后必有代价，`引擎规则.ts:665`）的触发条件 `最近 === '高潮'` **同时成立**。

# 实测归因表（逐条规则单独删豁免）

| 变异 | ① | ② | ③ |
|---|---|---|---|
| 删 `:638` rule1高 豁免 | **红** | 绿 | 绿 |
| 删 `:649` rule1低 豁免 | 绿 | **红** | 绿 |
| 删 `:665` rule4 豁免 | **红** | 绿 | **红** |

- ② 归因干净：只有删 rule1低 才红。
- ① 和 ③ **共享同一个失败源**：删 rule4 时两条一起红。
- ① 虽然也能抓到 rule1（删 :638 时红），但它**不是「只测 rule1」**。

# 根因（实跑确认，不是推断）

留白生效时 rule1 先跳过（`:638` 的 `!要留白` 为 false），
但 `连续高` 组的最后一个是「高潮」，**rule4 随即接手**把节拍改成「余波」。

探针输出（`tmp/probe-1.ts`，已删 rule4 豁免）：

```
① 场景 节拍 = 余波
① 场景 调整 = ["高潮后必有代价：导演原拟「日常」→ 代码改成「余波」，因为上一幕是高潮…"]
```

注意调整文案来自 **rule4**（「高潮后必有代价」），不是 rule1（「张力曲线」）。
**所以 ① 实际观察的是 rule4 的结果，不是 rule1 的。**

# 这违反了我们自己的纪律

报告 `:652-656` 明写：

> **① ② ③ 必须分开，不能合并成「rule1/rule4」**：
> 三处强制赋值是 `:639`（→余波）、`:650`（→**阴影**）、`:666`（→余波），
> **结果不一样**。合并成一条断言虽然能同时抓三条，
> 但**变异时无法区分是哪条规则漏了**。

现在的情况更隐蔽：**标题分开了，夹具没分开**。
① 和 ③ 共享「以高潮结尾」这个使 rule4 恒真的条件 —— 正是 dsh 自己总结的那条
「对照组和实验组共享了同一个使被测机制恒真的条件」，只是这次发生在**被测组内部**。

# 修法

① 的张力夹具必须让 **rule1 成为唯一能改写的规则**：

- 尾部连续高张力 ≥ 高阈（3）→ rule1 触发
- 但**最后一个不是「高潮」** → rule4 不触发

例：`最近节拍 = ['受挫','反转','受挫']`（尾部连续高 = 3，最后一个是「受挫」）。

改完必须重跑归因表，要求：

```
删 :638 → 只有 ① 红
删 :649 → 只有 ② 红
删 :665 → 只有 ③ 红
```

# 顺带核出的第二处

`[4]` 属性穷举的「连续高」那一列同样以「高潮」结尾，
所以 `[连续高×生活×推进]` 与 `[高潮后×生活×推进]` **走的是同一条路径**（rule4）。
穷举的覆盖度因此比 24 组的名义值低 —— 名义 4 种张力，实际只有 3 种独立路径。

这条不一定要改（穷举的职责是「新路径自动被发现」，不是归因），
但**必须在用例注释里写明**，否则下一个读的人会以为「连续高」和「高潮后」是两条独立路径。
