## ④ 批次 J（三条"静默失败"）

### P1-7 `onUnmounted` 用 `parentWin.value` 摘 resize 监听，可能已为 null

`src/共用/面板机制.ts:622` 挂、`:626` 摘：

```ts
parentWin.value?.addEventListener('resize', onViewportResize);   // :622
onUnmounted(() => {
  parentWin.value?.removeEventListener('resize', onViewportResize);  // :626
```

`parentWin` 是 `computed(() => frameWin.value?.parent ?? null)`（`:88`），依赖模板 ref。Vue 卸载时可能先置空 ref 再 flush `um` 钩子 → `:626` 静默不执行 → 监听器永久留在父窗口，闭包拖住整个组件。

**修法（不需要真机确认时序，这样写无条件正确）**：挂的时候存进局部变量，摘的时候用那个变量。

```ts
let 挂了resize的窗口: Window | null = null;
// onMounted:
挂了resize的窗口 = parentWin.value;
挂了resize的窗口?.addEventListener('resize', onViewportResize);
// onUnmounted:
挂了resize的窗口?.removeEventListener('resize', onViewportResize);
挂了resize的窗口 = null;
```

**用例**：新建 `tests/共用-resize监听配平.test.ts`（或放进 `daoyan-orb-status.test.ts`，你定），必须能失败：
- 假 window 记录 add/remove 调用；
- 模拟"卸载时 `parentWin.value` 已为 null"（挂载后把 ref 置空）→ 断言 `remove` **被调用了一次**、且 `add` 与 `remove` 是**同一个函数引用**；
- 对照组：不置空时也配平（证明不是"永远不挂"）。

### P1-8 壳 iframe 不做 `script_id` 去重

`src/剧情导演/悬浮球界面.ts:28-45` 直接 append，不查重。重复加载 → 两个球、两套监听，`pagehide`（`:56-59`）只清自己那一个。

**修法**：append 前遍历 `document.querySelectorAll('iframe[script_id]')`，`.getAttribute('script_id') === 本脚本 id` 的**先 `.remove()`**（不要复用 —— 旧 Vue app 已经挂载，复用等于两套 app 抢同一个 document）。

**用例**：新建 `tests/daoyan-壳iframe去重.test.ts`：
- 假 `document`（记录 append/remove/querySelectorAll）；
- 调两次挂载 → 断言最终只有一个同 `script_id` 的 iframe、且旧的那个 `remove` 被调用过；
- 对照组：`script_id` 不同时**不**删别人的 iframe。

如果 `悬浮球界面.ts` 的挂载逻辑在 `$(() => {...})` 里不好直接调，把"去重"抽成一个可导出的小函数（例如 `export function 清掉同id壳(doc: Document, id: string): void`），再测它。**抽函数可以，行为不许变。**

### P1-9 `loadData` 静默返回空账本

`src/剧情导演/快照.ts:49-56`：

```ts
try { lastId = useHost().chat.lastMessageId(); } catch { lastId = -1; }
if (floors.length > 0 && lastId < 0) {
  return { ...emptyData(), 清空层: meta.清空层, 已剧终: !!meta.已剧终 };
}
```

**这条路径一个 `console.warn` 都没有**，面板显示"还没有章回/伏笔"，用户以为账本被清空。

我已核过：`index.ts:203-215` 的 3 秒补读条件是 `hasSnapshots && !章回 && 伏笔空`，**这条路径天然满足**，所以补读本来就会跑 —— **不需要改 `index.ts`**。

**修法**：
1. 区分两种情形：`lastMessageId()` **抛错**（宿主没就绪）vs **返回 < 0**（聊天为空/未加载）。抛错那条必须 `console.warn` 带上错误文本（`错误文本()` 或 `String(error)`）；
2. `toastWarning` 一次（模块级标记，别每次 `reload()` 都弹）：文案必须含「账本暂时读不到」与「会自动重试」；
3. 若 `toast.ts` 引入会造成循环依赖（`toast` → … → `快照`），就退化成 `console.warn` + 在返回值上带一个可查标记（例如模块级 `最近读取降级原因`），并在交付说明里写清为什么没上 toast。

**用例**：新建 `tests/daoyan-读账本降级.test.ts`：
- 假宿主 `lastMessageId` 抛错 → `loadData()` 返回空账本、**且 `console.warn` 被调用过**（用 `console.warn` 替换记录）、且 toast 只弹一次（连调两次 `loadData` 断言 1 次）；
- 假宿主返回 `-1`（不抛）→ 不弹 toast（这是"聊天本来就空"，不是故障）；
- 对照组：正常宿主 → 读到快照、零 warn、零 toast。
