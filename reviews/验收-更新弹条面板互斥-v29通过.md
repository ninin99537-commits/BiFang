# 验收：更新弹条跟面板互斥（v29 通过）

日期：2026-11-13
缺陷来源：用户报「打开面板的时候提示条会挂在面板左边」

## 一、缺陷定位

### 用户看到的是什么

不是 toast，不是球气泡，是**第三套独立浮层**：`剧情导演_更新弹条`。

真机现场（面板打开时扫父文档所有可见浮层）：

| id | 位置 | z-index | 可见 | 在面板左边 |
|---|---|---|---|---|
| `dj-toast-stack` | l=78 | 2147482998 | 否（空栈） | - |
| `dj-orb-tip` | l=284 t=175 | 2147482998 | 否（opacity:0） | - |
| **`剧情导演_更新弹条`** | **l=331 t=409 169×40** | **2147482999** | **是** | **true** |

面板视口 `left = 679`，弹条 `right = 500` → 正好贴面板左沿。
弹条文本：`导演编排中…` + `中断` 按钮。

### 根因

`src/剧情导演/悬浮球界面.vue:1172`（修前）的 watch 只看 `[更新中, message]`，不看 `panelOpen`：

```js
watch([更新中, () => updatingStore.message], ([active, message]) => {
  if (active) {
    更新弹条El.style.display = 'flex';   // ← 面板开着也照样显示
```

这条弹条不在 toast 栈里，也不走 `setToastSuppressed`，所以 `面板机制.ts:418` 的抑制链对它完全无效。

### 同款缺陷：彼方

`src/彼方_NPC幕后生命状态系统/悬浮球界面.vue:854`（修前）同样只看 `[updatingActive, updatingMessage]`。
彼方的 `:349` `watch(panelOpen, 开 => setToastSuppressed(开))` 只管 toast，管不到弹条。

### 正确参照：烟火

`src/烟火_世界运转/推进弹条.ts:110` 早就修过同款：

```js
watch([依赖.推进中, 宿主.panelOpen], ([active, open]) => {
  if (active && !open) 建();
  else 移除();
});
```

这两条弹条当初从烟火抄来，漏了 `panelOpen` 那一半。

## 二、修法

新增 `src/共用/更新弹条判定.ts`：

```ts
export function 应显示更新弹条(更新中: boolean, 面板开着: boolean): boolean {
  return !!更新中 && !面板开着;
}
```

两个调用点的 watch 依赖补 `panelOpen`，判据改用纯函数，**不显示时是 `.remove()` + 置 null**（不是 `display:none`）。

选移除式的理由：`display:none` 会留下「面板开关一次后 display 与 更新中 不同步」的组合态；移除 + 置 null，下次应显示为真时重建，天然自愈。

**不丢中断能力**：面板内已有「中断编排」按钮（`悬浮球界面.vue:224`，`v-if="更新中"`）。

**每条都核对了失败项名称，确认红的原因正确，不是碰巧红。**

### M4 是本轮最有价值的一条

第一版判据是：

```js
ok(名 + ': watch 依赖里有 panelOpen', /watch\(\[[^\]]*panelOpen[^\]]*\]/.test(码));
```

这是**全文件搜**。彼方文件里有两个含 `panelOpen` 的 watch：

```
watch([panelOpen, anchorX, anchorY]                   ← 贴球锚点重排，与弹条无关
watch([updatingActive, updatingMessage, panelOpen])    ← 弹条本身
```

把弹条那条的 `panelOpen` 删掉后，第一条照样命中 → 断言仍然 PASS。**M4 实测全绿（11/0）**。

这是台账第②条「判据词太泛」，与 P1-8 的「整段删调用还能绿」同一个病。

修法：先定位到弹条那个 watch，再判它的依赖。

```ts
function 弹条watch依赖(码: string): string | null {
  const i = 码.indexOf('应显示更新弹条(');
  if (i < 0) return null;
  const j = 码.lastIndexOf('watch([', i);   // 往前找最近的 watch([
  if (j < 0) return null;
  const k = 码.indexOf(']', j);
  if (k < 0 || k > i) return null;           // ] 必须夹在 watch 开头与调用点之间
  return 码.slice(j + 'watch(['.length, k);
}
```

改后 M4 变红，失败项正是 `彼方: **弹条那个** watch 的依赖里有 panelOpen`。

### 一个环境坑（记录）

彼方第一次验证是 FAIL，原因是**真机上跑的仍是旧版代码**：

- `stop` 后弹窗是 `display:none` 且留在 DOM 里 = 旧版行为
- 新版是 `.remove()` + 置 null，元素应该从 DOM 消失

dist 里已经是新代码，但彼方壳没重新执行。触发 webpack 重编也不够 —— 彼方壳是更早建的。

最后用 `node tools/酒馆调试.mjs reload` 刷新整个酒馆页面才生效。刷新后**彼方的 `script_id` 变了**（`1e1f30fa` → `cfff5938`），这是酒馆重新生成 id，不是脚本换了。

教训：**「dist 里是新代码」不等于「真机跑的是新代码」。** 判断真机版本不能看 dist，要看行为差异探针（移除 vs display:none）。

## 八、本轮教训

1. **「某个抑制机制有效」≠「用户看到的东西被抑制了」。** 我用 `dj-toast-stack` 塞条证明抑制链是通的，结论是对的，但用户看到的根本不是 toast。判断之前必须先确认用户看到的东西属于哪套机制。

2. **三个探针全部无效，得到三轮假绿。** 「测试连接」结果写在面板内 ref 里不走 toast；「清理世界书条目」无条目时不产生 toast；「复制报错发给助手」无报错时不产生 toast。装置有效性必须**先单独验证**，不能默认按钮会产生目标事件。

3. **判据词太泛（台账第②条）又犯了一次。** 全文件搜 `panelOpen` 被另一条无关 watch 顶包。收窄到「调用点所在的那个 watch」才抓得住。

4. **dist 更新 ≠ 真机更新。** 真机版本要用行为差异探针判断，不能看 dist 时间戳或构建标记。
