# ① 量纲错：`字段表.ts:150` 说「天数之差」

**这是需求方自己在派活单 `§4` 写错的措辞，dsh 照抄。错在需求文档，不在实现。**

## 代码事实

```ts
// 写：update.ts:477
冲突条.最后行动天 = Number(账本.世界时间?.天数) || 0;      // 绝对刻度：故事内第 N 天

// 读：提醒.ts:255-256
const 天数 = Number(账本.世界时间?.天数) || 0;
const 隔天 = Math.max(0, Math.round(天数 - 最后行动天));    // 差在这里才算
```

`最后行动天` 存的是**写入那一刻的故事内累计天数**，不是「差」。差是 `隔天`。

## 如果它真是「差」会怎样

`隔天 = 天数 - 差` → 差减差，量纲不成立 → 负数 → 被 `Math.max(0, …)` 吞成 0
→ 症状：**永远显示「已 0 天没催它出手」**。

这正好是判据 ⑨ 那个「已 0 天」假话的另一种成因 —— 不是分支漏了，是**量纲读错**。

## 准确措辞

> 「模型自报的**故事内累计天数（绝对刻度）**，代码不校验合理性；
> 只用于**文案**，**不用于逾期裁决** —— 逾期按幕算（当前幕 - 最后行动幕）。」

注意 `账本数据.ts:672` 会沿用模型自报值（`Number(规范.最后行动天) || Number(旧条?.最后行动天) || …`），
所以「模型自报」对，「自报**天数之差**」不对。

# ⑥ 可复用的验收方法：双向对照

批 B 不动代码，红绿验不出来。有效办法是**双向对照**：

1. 注释里每一个**断言性短语**（「只用于 X」「不用于 Y」「记的是 Z」），去代码里找**唯一对应的读/写点**
2. 找不到 → 注释在描述一个不存在的机制
3. 找到两处说法不同 → 其中一处错
4. 同一段注释里前后打架 → 读者会信错的那句

本次三处都是这样撞出来的，没有一处靠读代码"感觉不对"。
