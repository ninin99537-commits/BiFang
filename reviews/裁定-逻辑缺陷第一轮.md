### P0-1 `节拍结束` 缺省 true，`已持续轮` 恒为 1，「节拍跨轮」是死分支

**我核过的位置**：
- `账本数据.ts:870`：`const 节拍结束 = 载荷?.节拍结束 === undefined ? true : !!载荷.节拍结束;`
- `账本数据.ts:871`：`const 同节拍继续 = !节拍结束 && !!旧.当前节拍 && 旧.当前节拍.节拍 === 上一幕节拍;`
- `账本数据.ts:872-874`：不同节拍继续时 `已持续轮` 重置为 1
- `引擎规则.ts:793`：`const 节拍跨轮 = Number(账本.当前节拍?.已持续轮) > 1;`
- `引擎规则.ts:822`：`else if (!核验.已执行 && 节拍跨轮)` —— 这条豁免分支

**判定**：**代码缺陷成立，但真机当前未触发** —— 这两件事必须分开说。

- **代码层面**：模型只要漏写 `节拍结束`，`已持续轮` 就被重置为 1，`节拍跨轮` 恒假，`:822` 那条豁免永不进入。逻辑漏洞真实存在。
- **真机层面**：我用 `tmp/cdp/p0-1-proof.js` 读了用户 Chrome 里正在跑的账本，`当前节拍.已持续轮 = 4`，说明**模型这一轮确实写了 `节拍结束: false`**，`同节拍继续` 生效了。

所以**不能**把这条说成「正在造成戏被赶走」。它是「一漏写就静默失效」的脆弱点，不是当前病因。

**当前真机的病因是另一件事**（同一份取证的读数）：

```
连续低张力: 54       当前张力: 0
张力.最近节拍: 日常 ×6
距上次高潮楼层: 78
已分析轮数: 78
```

78 轮没有一次高潮，连续 54 轮低张力，最近 6 个节拍全是「日常」。**这才是要修的东西**，而它的根因是 `引擎规则.ts:695` 的 `让位`（P2 的 2.4），不是 `节拍结束`。

**修法**（改一行）：缺省不当作「演完」——
```ts
const 节拍结束 = 载荷?.节拍结束 === undefined
  ? !(旧.当前节拍 && 旧.当前节拍.节拍 === 上一幕节拍)   // 没写：只有节拍真的换了才算结束
  : !!载荷.节拍结束;
```

**为什么这是行为变更而不是文案**：它让 `已持续轮` 真的能涨。必须单独一批 + 真机观察。

**优先级下调**：真机 `已持续轮 = 4` 证明当前模型会写 `节拍结束`，所以这条**不是**当前病因，降为「健壮性」而不是「修复」。本批不做。

### P0-2 `章长度提醒` 的「推进中 40 场」分支在正常幕纲下不可达

**我核过的位置**：
- `提醒.ts:82`：`const 超期 = 幕纲数 > 0 && 演了几场 > 幕纲数 * 3;`
- `提醒.ts:118`：`if (判.超期) return '幕纲落后';`
- `提醒.ts:685`：`if (长 < 章长度阈值) return [];`（阈值 40）
- `提醒.ts:688`：`if (选收章发言者(账本, 当前场) === '幕纲落后') return [];`

**判定**：成立。`prompts.ts:148` 要求幕纲 3~5 幕 → 超期在 `5*3+1 = 16` 场就成立。40 > 16，所以 `:688` 必然先返回空。**`:689` 那句「已经演了 N 场还没进入收束」在幕纲 ≤ 13 时永不出现**，而真机幕纲就是 5 幕。

**后果**：`伏笔窗口按章计、章不结束长伏笔永远等不到窗口` —— 这条唯一的计量出口是哑的。

**修法**：两个阈值只能留一个当「该收章」判据。最小改动：
```ts
const 超期 = 幕纲数 > 0 && 演了几场 > Math.max(幕纲数 * 3, 章长度阈值);
```

### P0-3 `收束预算` 在提醒侧永远晚一场

**我核过的位置**：
- `update.ts:323`：`账本.已分析轮数 = (data.已分析轮数 ?? 0) + 1;`
- `取料.ts:243`：`结构提醒: 设置.导演.平静模式 ? [] : 结构提醒(账本, Number(账本.已分析轮数) || 0)` ← **这行在 `:323` 之后跑，但 `取料` 的结果在 `:319` 之前就算好了**
- `引擎规则.ts:751`：`const 收束已用 = Math.max(1, 当前幕 - 收束起始 + 1);`

**判定**：成立，但要精确说：`取料()` 在 `update.ts:319` 的 `应用(...)` 之前求值，那时 `已分析轮数` 还没 +1；而 `构造本幕指令`（`:359`）在 `:323` 之后，用的是 +1 后的值。**同一轮里两个「收束已用」差 1。**

**后果**：`引擎规则` 判预算用尽 → `收章 = true` → 进度写「已完结」。下一轮 `提醒` 才算出同一个数，但那时 `已完结` 已成立，`选收章发言者` 返回 `'章长度·开新章'`。**`:675-683` 的「已进入收束 N 场(预算 8)」永不出现** —— 用户只看到「已完结，请开新章」，看不到「为什么突然收了」。

**修法**：`取料.ts:243` 传 `+1` 后的场号，与引擎侧对齐：
```ts
结构提醒: 设置.导演.平静模式 ? [] : 结构提醒(账本, (Number(账本.已分析轮数) || 0) + 1),
```
同时 `判收章`（`提醒.ts:79`）内部写死读 `账本.已分析轮数`，要一并接受 `当前场` 参数。

### P0-4 补推 `setTimeout` 只在排程时查聊天，1.5 秒内换聊天会串档

**我核过的位置**：
- `update.ts:563-570`：`if (待补推) { 待补推 = false; if (!已换聊天(发起聊天)) { setTimeout(() => { updateDirector(...) }, 补推延迟毫秒); } }`
- `update.ts:576-584`：`已换聊天()` 的实现

**判定**：成立。`:566` 判一次就排定时器，`:567` 回调里**不再判**，`待补推` 已置 false，也没有 `clearTimeout` 的句柄。

**后果**：补推会对着**新聊天**跑一次完整编排 —— 新聊天账本被写入、被注入指令。这不是「作废」，是**串档**。

**修法**：守卫搬进回调 + 存句柄：
```ts
const 定时 = setTimeout(() => {
  if (已换聊天(发起聊天)) return;          // ← 真正生效的位置
  updateDirector(false, '补推(推进期间来了新回复)').catch(...);
}, 补推延迟毫秒);
```
并在 `updateDirector` 入口 `clearTimeout(待补推定时器)`。

### P1-5 「连着几幕高张力」引擎与提醒两套集合、两套阈值

**我核过的位置**：
- `字段表.ts:570`：`高张力节拍 = ['受挫', '反转', '兑现伏笔', '高潮']`
- `引擎规则.ts:630` 附近：用 `高张力节拍`，阈值「连续 3 幕」
- `提醒.ts:709`：`const 连高 = 尾连续(['高潮', '兑现伏笔']);`
- `提醒.ts:710`：`if (连高 >= 2)`

**判定**：成立。两句话说的是同一件事（「别一直堆高压」），判据不同：
- `受挫×3` → 引擎强制改余波，提醒**一声不响**
- `高潮×2` → 提醒喊「别再堆高潮」，引擎认为**还没到阈值**

**修法**：`提醒.ts:709-710` 改成 `尾连续(高张力节拍)` + 阈值 `连续高阈值默认`，从 `字段表`/`schema` 导入，与引擎共用一份。

### P1-6 `日常` 在契诃夫规则里被排除，在收束出口里又被征用

**我核过的位置**：
- `引擎规则.ts:683`：`if (章回 && 节拍 !== '兑现伏笔' && 节拍 !== '高潮' && 节拍 !== '余波' && 节拍 !== '日常')`
- `引擎规则.ts:681-682` 注释：`「日常」也排除在外 —— 这一幕的契约就是"别来事"，再把它强行改成兑现伏笔，等于把唯一的喘息幕也征用了`
- `引擎规则.ts:731-735`：`const 躲债节拍: 节拍[] = ['日常', '小胜']; if (躲债节拍.includes(节拍)) { ... 节拍 = 换成; }`

**判定**：成立，且**注释在说谎**。`:683` 的排除在收束态实际无效，因为 `:730` 的收束出口在后面无条件接管。用户看到的是「我标了日常，还是被改成兑现伏笔」。

**修法**：二选一，写进代码而不是注释：
- 保留收束出口 → 把 `:681-682` 注释改成「收束态由 :730 接管」，并从排除列表去掉 `日常`；
- 保住喘息幕 → 从 `躲债节拍` 删掉 `日常`，只禁 `小胜`。

**我的裁定：保留收束出口，删 `日常` 的排除**。理由：收束态是「必须收」，喘息幕在那里是躲债。但注释必须改，不能让下一个读代码的人以为这里有保护。

### P1-8 「最迟章到了」与「已过最迟章」差一个等号

**我核过的位置**：
- `证据链.ts:184`：`if (最迟 !== null && 当前章 > 最迟) return { 状态: '已过最迟', ... }`
- `证据链.ts:196` 注释：`③ 到最迟章只表示"该评估了", **不表示必须下一幕引爆**`
- `证据链.ts:308`：`const 最迟已到 = 窗口.最迟章 === null ? true : 章 >= 窗口.最迟章;`
- `引擎规则.ts:684`：`const 首选 = 候选们.find(项 => 项.最迟已到) ?? null;`
- `引擎规则.ts:693`：命中后（非让位）`节拍 = '兑现伏笔'`

**判定**：成立。`章 === 最迟章` 时 `最迟已到 = true`，但窗口状态仍是 `可催办`（`:187` 的说明写着「可评估, 不等于必须引爆」）。`引擎规则:684` 只看 `最迟已到` → 这一轮强制改节拍。

**后果**：`:196` 的契约被违反 —— 到点那一轮就引爆，`>` 才叫逾期。同一个边界两个函数两个答案。

**修法**：`证据链.ts:308` 改成 `章 > 窗口.最迟章`，与 `:184` 对齐；「正好到点」的催办交给 `取到期伏笔`（`可催办` 已覆盖）。
