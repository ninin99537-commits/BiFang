### 2.2 `应用更新.ts`：19 → 0

**点名项 `:61`（`彼方数据` 未定义）**：确认它**本该就是 `./快照` 导出的 `彼方数据`** ——
`更新结果 = { 数据: 彼方数据; 摘要: 更新摘要 }`，而 `applyUpdate` 的入参与返回值、
`resolveRenamedNpc` 的 `newData` 参数、`快照.saveData` 的入参全是同一个形状
（`快照.ts:185` 已 `export interface 彼方数据`）。所以改成 `import type { 彼方数据 } from './快照'`，
**没有**用 `any`。这同时把 `applyUpdate` 的入参与 `newData` 一起收紧了。

| 位置 | 改法 |
| --- | --- |
| `:12` 新增 | `import type { 彼方数据 } from './快照';` |
| `maskBaseUrl(url: string)` | 参数标 `string` |
| `resolveRenamedNpc(newData: 彼方数据, name: string, card: Record<string,any> \| undefined, playerName: string \| null)` | 四参 + 返回类型 `{ name: string; oldCard: Record<string,any> \| undefined }` |
| `applyUpdate(data: 彼方数据, parsed: Record<string,any> \| null, ...)` | 入参类型；`newData: 彼方数据` |
| `timeJump` → `_timeJump` | **未使用参数改名，不删参数**（调用点 `update.ts:74` 仍在传 `timeJump`，删了就是改签名；改名保留位置与调用约定，只让 `noUnusedParameters` 闭嘴） |
| `isTrackedNpc = (name: string)`、`skippedNewNpcs: string[]`、`updatedNames: string[]`、`removedNpcs: string[]` | 显式标注（原 `TS7034/7005`） |
| 4 处 `.filter(n => ...)` / `.map(n => ...)` | 回调参数标 `string`（`newData.名单` 的元素类型） |

**关于 `_timeJump`，需要你确认一句**：它确实从未被读（`applyUpdate` 里没有 `timeJump` 的用法），
但调用点还在传。我的处理是**只改名不删参**——签名、调用点、运行时行为全不变，
纯粹让 `noUnusedParameters` 通过。若你要的是"连参数一起删掉、调用点也不传"，那是改签名，属于批次 2 的事，我不擅自做。

### 2.3 `数据变更.ts`：2 → 0

两处 `TS7053`（`新卡['最后更新']`）根因：`const 新卡 = { ...卡, [台账字段]: 新台账 }`
被推断成 `{ 未完成事项: 幕后事务[] }`（计算属性键把索引签名丢了），于是字符串下标非法。

改法（**同一行 × 2**）：

```diff
- const 新卡 = { ...卡, [台账字段]: 新台账 };
+ const 新卡: 彼方数据['NPC'][string] = { ...卡, [台账字段]: 新台账 };
```

用的是 `快照.ts` 里那条已有的 `NPC: Record<string, { 未完成事项?: 幕后事务[]; [其它字段: string]: any }>`
—— 既保住索引签名，又不新增 `any`（那个 `any` 本来就在契约里）。
