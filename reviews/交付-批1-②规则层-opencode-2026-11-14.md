### 3.1 `生理规则.ts`：28 → 0

**点名项：两张"字符串索引数字映射表"——结论是「不是 bug」，但理由必须写下来。**

`parseConceptionCount` 的 `digit`（`:53`）和 单向闸的 `order`（`:530`）原先是对象字面量，
TS 推断成九个/三个**已知键**，用 `string` 索引就报 `TS7053`。逐条核实兜底：

| 位置 | 查不到时的行为 | 判定 |
| --- | --- | --- |
| `digit[t.charAt(1)]`（`十X` 分支） | `undefined` 是 falsy → 三元走 `: 10` | 有兜底 |
| `digit[first]`（`else if`） | `undefined` 是 falsy → 整个 `else if` 不成立 | 有兜底 |
| `order[oldKnown] ?? -1` | `?? -1` | 有兜底 |
| `order[known] ?? -1` | `?? -1` | 有兜底 |

所以四处都**不是**"undefined 直接参与运算"。改法是标注 `Record<string, number>`（形状确实是"任意字符 → 数字"的查表），
并在两处各写一句为什么不是 bug——避免下一个人重走一遍这个判断。

**关于 `cycleLen: number` 的契约说明（#59 裁决后已补入口自愈，见 §3.5）：**

「周期长度」在 `卡字段.ts:51` 属于**隐藏键**——由代码维护、模型不该返回。写入只有两处：

- `生理规则.ts`：`26 + Math.floor((随机() + 随机()) * 3.5)` → **number**
- `更新输入.ts:110`：`oldCard['周期长度'] = card['周期长度']`（把上一轮的卡回写到旧卡）

所以正常数据流里它恒为 number。旧数据**理论上**可能残留字符串。

**⚠️ 本段初稿在这里写错过一个判断，已纠正并留档：**

初稿写的是"坏值会让 `NaN` 一路传到永不判孕"。**这是错的。** `calcConceptionRate` 里
`let base = 0.01` 有初值兜着，`NaN` 不会传播：`dist` 是 `NaN` → 三个 `if/else if` 全不成立
→ `base` 保持 `0.01` → **静默按"安全期 1%"算**。实测 `"abc"` / `{}` / `true` / `-5` 在随机源=0 时
仍会判怀孕（1% 也可能掷中），从外面完全看不出异常。

也就是说坏值的真实后果比初稿描述的**更隐蔽**——不是"明显不工作"，而是"看起来正常工作、概率永远 1%"。

`calcConceptionRate` 本身**仍然不加 `?? 0` / `Number()`**（理由不变：那正是把坏值静默成安全期）。
修复放在**入口** `确保周期长度`，见 §3.5。

### 3.5 `确保周期长度`：入口自愈（**本段唯一的非纯类型改动**）

`#59` 裁决：`cycleLen` 不加兜底，但 `NaN → 永不判孕` 也是一种静默；要求在**读取/播种入口**
做一次"非法即重播"。

原判定是"键存在即跳过"，于是 `"abc"` / `{}` / `true` / `0` / `-5` 全部原样放行。改成分两类：

| 输入 | 处理 | 理由 |
| --- | --- | --- |
| `number` 且有限为正 | 不动，返回 `false` | 正常路径，零变化 |
| 能解析成正数的字符串（`"28"` / `" 28 "`） | **归一成 `28` 写回**，返回 `true` | 直接重播会悄悄改掉锁定值，而"首次确定后锁死"是本模块核心约定 |
| 其余（`"abc"` / `NaN` / `Infinity` / `{}` / `true` / `0` / `-5` / 空串 / `null` / 缺键） | 重播 26~32，返回 `true` | 算不出正数 = 当"没有" |

只认 `string` 的隐式转换，**不认 `boolean`/`object`**：`Number(true)=1`、`Number([])=0`
会把完全不相干的类型蒙混成合法值。

**行为变化（请验收位重点看这一条）：**

- 合法 `number`：零变化。
- 字符串 `"28"`：卡上从存 `"28"` 变成存 `28`。下游结果相同（JS 减法本来就隐式转数字），
  但类型与运行时从此一致。
- 真坏值：从"静默 1% 安全期"变成"重播成合法整数"。**这是行为改动**，不是类型改动。

`calcConceptionRate` 的注释同步改写为"本函数故意不做兜底，因为入口已修好"，
避免下一个人看到这里没有校验就以为漏了。

### 3.4 `恋爱规则.ts`：连带 2 条（**因签名收窄而被迫扩面**）

`剧情时间.ts` 的 `fmtStoryTime` 一旦收 `number`，`恋爱规则.ts:389/392` 就报
`Argument of type 'number | null' is not assignable`——它们直接把 `parseStoryTimeRange(...).endTs` 递进去。
**这不是主动扩大改动范围，是签名收窄的直接后果：调用点不处理就过不了类型门。**

我先试过把 `fmtStoryTime` 放宽成 `ts: number | null | undefined` + `new Date(Number(ts))`，类型能过。
**但退回来了**，理由：`new Date(Number(ts))` 与 `new Date(ts)` 只在 `number/null/undefined` 上等价，
对**字符串**输入不等价（前者 `Number('2025-01-01')` = NaN，后者按日期串解析）。虽然类型上已经禁止字符串，
但"不改行为"应当按字面兑现，不该靠"反正类型挡住了"。更关键的是：**放宽签名会把 `null` 静默变成 1970**，
正好是 #52 说的"别顺手加兜底让它编过去"。

**为什么选择在调用点收窄、而不是放宽签名**（#59 要求写清）：

| 方案 | 后果 |
| --- | --- |
| 放宽 `fmtStoryTime` 收 `null` | `null` 静默 → 1970-01-01；把"调用方没想清"变成"函数假装能处理"。**改了函数语义**，且是全仓生效 |
| 调用点加 `!` 断言 | 类型能过，但把不变量退化成注释里的口头约定，下一个人不知道凭什么非空 |
| **调用点写显式条件**（采用） | 条件对有限数值恒真 ⇒ 分支走向零变化；不变量由编译器自己验证；改的人一眼看到 `endTs !== null` 就知道这里有前提 |

最终做法：`fmtStoryTime` 保持 `ts: number`，在调用点写**显式条件**收窄：

```ts
if (本轮日期ts !== null && 基准ts !== null && range.endTs !== null) { ... }
else if (本轮日期ts !== null && 基准ts === null && range.endTs !== null) { ... }
```

`本轮日期ts` 是 `日序自时间戳(range.endTs)` 的结果，而 `日序自时间戳` 对 `null`/`undefined`/非有限值
一律返回 `null`（`剧情日期.ts:79-80`）。所以**能进这两个分支 ⇒ `endTs` 必为有限数值**，
新增的 `&& range.endTs !== null` 对它是恒真条件：不改变任何分支走向，运行时零差异。

我没有用 `!` 断言，也没有加注释口头约定——把不变量写成条件，让类型检查器自己证明。
