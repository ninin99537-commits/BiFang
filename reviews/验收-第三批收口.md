### 1.4 关于 dsh 在 #80 的反驳：他是对的

我派活时写的判据「删掉 `上一道.必演 === '无'` 判断，用例必须变红」**是错的**。

原因：`'无'` 是 **truthy 字符串**，原判据 `|| 上一道.必演` 本来就会 `return []`。
那条 `=== '无'` 分支删掉行为不变（我实测 0 红，与 dsh 一致）。

**三态真正修的不是"这条提醒响不响"，是"数据能不能区分"**：

1. `指令.必演 === '无'` 与 `null` 现在**数据层可分辨**（以前都落成 `null`，信息丢了）；
2. 将来任何「按导演想清楚了没」决策的逻辑才有东西可判；
3. 面板/诊断能看到"这一场导演明确说没有"。

这是我的判据设计错误，不是用例没牙。**已记入踩坑账（第 8 次同型：判据词/判据本身想当然）。**

### 1.5 遗留：`提醒.ts:215` 的 `=== '无'` 是冗余分支

if (!上一道 || 上一道.已跳过 || 上一道.必演 === '无' || 上一道.必演) return [];

### 2.3 保留的改进建议：同一天改代码抓不到

**实测**：把标记描述改成 `'daoyan-2026-11-13-旧描述没更新'`（日期不变）→ 用例**绿**。

这是**最常见的场景**：一天里改好几轮。今天（11-13）我们改了
① ② ③ + 世界书 A 案 + 超期收章 + 死字段 + J 批 —— 只要日期是当天，改多少次都不红。
**这恰好就是"真机分不清跑的是哪一版"的原始场景。**

**建议**（不阻塞验收，下一批做）：判据从「日期」升级为「内容指纹」——

```ts
export const 构建标记 = 'daoyan-2026-11-13-<8位sha1>-描述';
// 用例：算 src/剧情导演/*.ts|*.vue 的内容 sha1 前 8 位，比对标记里的指纹
// ⚠️ 算指纹要**排除 index.ts 自己**，否则改标记会让指纹变、永远红
```

好处：一次解决"同一天"和"mtime 被 copyFileSync 保留"两个问题。
