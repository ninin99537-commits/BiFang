### 3.1 变异 B：去重完全不执行，仍然全绿

删掉整段调用后，`悬浮球界面.ts` 里只剩一行注释含 `清掉重复壳(`。
`tests/...:292` 的 `ok('调用点用 清掉重复壳', /清掉重复壳\(/.test(源))` **只认字符串**，
注释即可满足 —— 于是「去重被整段删除」这个最严重的退化（比传错 doc 更彻底）**一条断言都没拦住**。

### 3.2 变异 E：无害注释造成假红

`:293` 的 `check('不再直接调用 清掉同id壳', /清掉同id壳\s*\(/.test(源), false)` 是**负向正则**，
它把注释里的旧写法也数进去。结果是：**加一行说明历史的注释就会让用例变红**。

这条虽然是「假红」而非「假绿」，但同样有害 —— 它会逼着后来者删掉有价值的注释，
或者干脆把注释写得更隐晦，反而降低可读性。

> 结论：`[P1-8d]` 的 ④ 两条（`:292-293`）是**源码正则**，不是行为断言。
> dsh 在 `#103` 说「接线不再用正则」，实际只把 ①②③ 换成了行为断言，**④ 仍是正则**，
> 而且正反两条各有缺陷（正向可被注释满足、负向被注释误伤）。

## 四、变异 G：这个缺口等于退回原 bug

### 4.1 为什么它等价于 v25 那个 bug

`取壳文档` 的实现是：

```ts
const 体 = 找body();
return (体 && 体.ownerDocument) || 兜底;   // 找body 返回 undefined → 走兜底
```

调用点的 `兜底文档` 传的是 `document` —— 也就是**脚本 iframe 自己的 document**。
所以 `找body: () => undefined` 会让去重精确退回 v25 状态：

> 在脚本自己的 document 里查 → 命中 0 → 去重完全没生效。

这正是 `#94` 报的那个高严重度缺陷。

### 4.2 为什么 43 条断言一条都没拦住

用例是这样喂的：

```ts
清掉重复壳({ 找body: () => ({ ownerDocument: 假父doc }), 兜底文档: 假脚本doc, scriptId: 'dj-x' });
清掉重复壳({ 找body: () => undefined,                兜底文档: 假脚本doc, scriptId: 'dj-x' });
```

**用例自己构造了一个正确的 `找body` 去喂函数**，
但**从没读过调用点（`悬浮球界面.ts:42`）传进去的那个 lambda**。
我把调用点的 lambda 换成 `() => undefined`，用例完全不受影响 —— 它压根不读那个 lambda。

（`tmp/probe-gap-g.cjs` 的输出佐证：用例里出现的 `找body` 是 `() => ({ownerDocument: 假父doc})`
和 `() => undefined`，调用点里是 `() => $('body')[0]`，两者没有任何断言关联。）

### 4.3 与情形 f 是同一类，但换了一层

| 版本 | 缺口 |
|---|---|
| v26 | 用例没测「调用点传的是**哪个 doc**」 |
| v27 | 用例没测「调用点传的 **`找body` 是不是真的在找 body**」 |

抽一层纯函数只解决了「**函数本身**可测」，**没有解决「调用点传进去的东西可测」**。
每抽一层，缺口就往上游移一层 —— 除非有一条断言真的盯住最外层那个实参。

> 这是本轮第二个「同型换层」案例。第一个是 `#94`（逻辑 vs 接线）。
> 房间级结论应更新为：**抽纯函数能让逻辑可测，但接线会随之下移一层，必须重新钉。**

## 七、已排除的怀疑（不用再查）

`清掉同id壳` 是否为死路径 —— **不是**。真机实验证明：

```
旧iframe还在DOM            : false
旧iframe与现iframe是同一个  : false
脚本window标记还在         : false
```

热重载会**重建脚本 iframe、脚本整体重跑**，所以 `悬浮球界面.ts` 顶层的 `$(() => {...})` 会重跑，
去重路径是活的。两条路径分工：

- 热重载 / 重复加载 → 新脚本重跑 → `清掉重复壳` → unmount + 拆旧壳（P1-8 防的是这个）
- 页面关闭 / 刷新 → `pagehide` → `app.unmount()` + `$app.remove()`（只清自己那一个）
