## 一、世界书条目误删（P0，数据丢失，**已冻结**）

**一句话**：插件判断"这条世界书条目是不是我写的"，用的是一串宽松的名字/内容前缀。用户自己写的条目只要长得像，就会被认成导演的，然后在**两条全自动路径**上被**静默删除，不可撤销**。

**实测（`node tmp/prove-wb.mjs`，可复跑）**：

```
  true   我的剧情导演笔记                    ← 判成导演条目
  true   剧情导演参考                        ← 判成导演条目
  true   关于剧情导演的设定                  ← 判成导演条目
  true   NPC 卡 (注: 剧情导演 用过的备注)     ← 判成导演条目
  false  世界观 / 人物志                      ✓ 正常

用户自建条目被误判为导演条目的数量 = 4 / 4
```

根因在 `src/剧情导演/世界书落点.ts:24`：

```ts
const 旧命名模式 = [/^【导演/, /^【剧情导演/, /^导演指令/, /^编剧备忘/, /剧情导演/];
//                                                                      ↑ 无锚定
```

`is导演条目()` 对它做 `名.test() || 注.test()`（`:31`），命中即返回 true。

**两条自动删除路径**（无预览、无确认）：

| 路径 | 位置 | 触发条件 |
|---|---|---|
| 启动自检 | `index.ts:218-230` | 总开关关闭 → 启动 4 秒后 `清空导演条目()` |
| 关注入 | `注入.ts:58-61` → `清理别处的副本('')` | 每轮生成前，只要「不该写」 |

**两个方案**（详细见 `reviews/待拍板-世界书条目误删.md`）：

- **A（保守）**：只认精确标记 —— `extra.daoyan === true`、精确条目名、内容签名。旧版本的条目**不再自动删**，改为"发现疑似条目时提示用户手动清理"。
  - 代价：老用户关掉总开关后，旧版本留下的条目可能还在注入。
- **B（折中）**：保留宽松匹配，但**删之前先列出来让用户确认**（toast 里给"清理/保留"两个按钮）。
  - 代价：多一次交互；批量删除时提示可能很长。

**我倾向 A** —— 数据丢失不可逆，而"旧条目还在注入"是可逆的（用户手动删一次就行）。

## 二、超期 1 场以上是否无条件说「该收章」（P1，真机未触发）

**一句话**：一个 5 幕的章卡在第 3 幕演了 41 场时，"该收章"这个声音**彻底消失**，只剩"把幕号往前推"—— 而推幕号可以无限推。

**实测（`tmp/prove-e3.mjs`）**：

```
########## 真实第 41 场，幕号 3/5 ##########
判收章: 演了几场=41 超期=true 该收=true
发言者: 幕纲落后
  · 本章已演 41 场, 幕纲却只有 5 幕(现在第 3 幕) —— 幕纲明显落后于实际进展。
    要么把「当前幕号」往前推(结束条件早就满足了吧), 要么重写后面几幕...
```

对比第 40 场（`章长度` 说的）：

```
  · 第 1 章已经演了 40 场还没进入收束 —— 请评估是否推进到本章高潮并收章...
```

**为什么会这样**：`提醒.ts:705-707` 的设计是「超期后由 `幕纲落后` 说更具体的话」，但 `幕纲落后` 只在 `有效幕号 >= 幕纲数` 时才说「该收章」（`:366` 的 `到头了`）；幕号没到最后一幕时，它说「推幕号」。

**真机是 5/5，所以当前没触发。** 但"5 幕的章卡在第 3 幕演 41 场"正是"章不结束、伏笔窗口永远不到"的形态。

**要你定**：超期 1 场以上（第 41 场起），**该不该无条件说「该收章」**，不管幕号推没推到最后一幕？

- **是**：`幕纲落后` 在超期时同时说两件事 ——「幕号推不动了/落后了」+「该收章」。
- **否**：保持现状（先劝推幕号，推到最后一幕才说该收章）。

**我倾向"是"** —— 因为"推幕号"是**可以无限推**的，而"该收章"是**硬边界**。一章演 41 场已经不收，再多一条"你可以推幕号"只会给它继续拖的理由。
