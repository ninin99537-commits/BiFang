## 二、H-3：我给的改法会弄丢一条既有纪律（dsh 对，我错）

我派单里写的是：

```ts
if (原锚点有效) return 写(原锚点);      // ← 失败就是失败, 不要偷偷换楼层
return 最新 !== 原锚点 ? 写(最新) : false;
```

**这会把「原锚点那楼已被删 → 退回最新楼」这条既有纪律弄没。**

`快照.ts` 原注释写得很清楚：原锚点那楼被删了要退回最新楼，否则 `buildSnapshotPayload` 拿不到楼层，**手改白丢**。而 `tests/daoyan-零截断` 里有一条源码断言钉着它。

dsh 第一版按我写的做，全量立刻红了 `原锚点无效时退回最新楼` —— 它自己发现了并改成按"楼层还在不在"判：

```ts
const 楼层还在 = (锚: number): boolean => {
  try { return !!useHost().chat.messages(锚)[0]; } catch { return false; }
};
if (原锚点有效 && 楼层还在(原锚点)) return 写(原锚点);
return 最新 !== 原锚点 ? 写(最新) : false;
```

**这才是对的**：三种情形本来就该分开 ——

| 情形 | 该怎么做 | 判据 |
|---|---|---|
| 原锚点在、写成功 | 返回 true | `写(原锚点)` |
| 原锚点在、**写失败** | 返回 false，**不许漂移** | `写(原锚点)` 的返回值 |
| 原锚点无效 / **那楼被删** | 退回最新楼 | `楼层还在()` 为假 |

**我的错在哪**：我把"锚点有效性"当成了一个静态属性（`原锚点有效` 只看数值范围），但它其实是**动态的** —— 那楼可能被 `/cut` 删掉了。dsh 用 `messages(锚)[0]` 现场探，才是真正的有效性。

**记进纪律**：凡我给的改法涉及"有效性判断"，必须问一句"这个有效性是静态的还是运行时的"。静态数值判断会漏掉"数据被外部删掉"这一类。

### H-2

```ts
const 旧处理到 = data.处理到楼层;
const 旧清空层 = data.清空层;
data.处理到楼层 = 锚点楼层;     // payload 要读它，必须先设
data.清空层 = 0;
const 落盘 = writeStateSnapshot(data, 锚点楼层, 锚点楼层, true);
if (!落盘) {
  data.处理到楼层 = 旧处理到;
```

顺序对：先设后回滚（`writeStateSnapshot` 的 payload 要读这两个值）。用例实测 `处理到楼层` 回到 2、`清空层` 回到 3，不是 5 / 0。

## 五、【偏离】改了一条既有断言，我认可

`daoyan-零截断` 的源码级断言：

```
- ok('原锚点无效时退回最新楼', /原锚点有效 && 写\(原锚点\)…写\(最新\)/)
+ ok('原锚点无效时退回最新楼', /原锚点有效 && 楼层还在\(原锚点\)\) return 写\(原锚点\)…写\(最新\)/)
```

**意图一字未变**（仍是"锚点无效/楼层被删时退回最新楼"），只是判据形状跟着实现走。这是**允许**的偏离 —— 因为原断言测的是"代码长什么样"，而不是"行为对不对"。真正的行为断言在 H 批新用例的对照②里。

**但记一条隐患**：源码级正则断言是脆的，实现一改就得跟着改。以后这类"退回最新楼"的行为，应该写成**行为断言**（假 host + 断言 `message_id`），而不是正则匹配源码。
