## ⚠️ 最该被记住的一句话

**类型门不检查行为等价。**

`tsc --noEmit` 通过只证明"类型自洽"，**不证明**这段代码还和原来做同一件事。
本段里有两个活证据：

1. 本段一开始就有 59 条错，其中一大半的"修法"有两种：**补类型标注**（不改行为）和
   **改代码让它符合类型**（很可能改行为）。类型门对这两种一视同仁 —— 都变绿。
   所以我这一整段是按"只许加标注、不许改逻辑"逐条手改的，靠的是**对着原代码读 diff**，不是靠门。
2. 派活单里的红线实验反过来证明了同一件事的另一半：我把一处标注改回去 → 门立刻红并点名；
   还原 → 门绿。门能抓住"标注丢了"，但**抓不住"标注还在、逻辑改了"**。
3. 本段第三段交付（`4ae05ad`）里已经踩过一次：我把短路条件写成 `env && typeof env === 'object' && …`，
   类型门照样绿，行为却比原代码窄了一点，靠逐行读 diff 才发现。

一句话：**门是下限，不是保证。** 判"没改行为"必须靠人对着原代码逐条比对（见 §4）。

### 3.1 全局（`c9253b5`）：6 → 0

- `util/common.ts`：`z.ZodError` → `import type { ZodError } from 'zod'`。

  命名空间里没有类型成员 → 当类型用报 TS2749。`sortBy` 回调补 `(issue: ZodError['issues'][number])`。
- `util/mvu.ts`：`T extends z.ZodObject` → `import type { ZodObject }`。
- `global.d.ts`：`declare namespace z` 补 `ZodType` / `ZodObject` / `ZodError` 三个类型别名。
  **只 `declare`，不产生任何代码**（`.d.ts` 里没有运行时形状可改）。
  顺带解掉 `@types/function/variables.d.ts:204` 那条（它用的是 `z.ZodType`，本来就想这么用）。

## 4. 成功路径不变（逐条对照，不是"看起来没变"）

1. **无一处改分支条件、调用顺序、参数个数或默认值。** 全部改动是：类型标注、`import type`、接口声明、
   变量显式类型、以及三处"把内联表达式提成命名常量"（值不变）。
2. **`时间提示` 的签名和调用点原样**：三个形参都在，`_worldbook` 只是改名表示"刻意不用"——
   函数注释本来就写着"只从正文与上下文提取，不读世界书"。
3. **`pad(n: string)` 是纠正标注，不是改类型**：4 处调用全部传 `matchAll` 捕获组（本来就是 `string`）。
   原标注 `number` 才是错的（`String(n).padStart` 对 number 和 string 都成立，运行时无差别）。
4. **`prompts.ts` 删的 `const 预填充` 从未被读过**：删前删后 `messages` 数组的构造完全相同
   （`303-304` 的收尾判断只看 `messages[末].role === 'assistant'`）。入参 `预填充` 仍留在接口上，因为调用方还在传。
5. **`场景判断段` 提取是纯搬迁**：三元条件、模板字符串内容、`role: 'system'` 全部逐字复制，
   只是从数组字面量里搬到一个带类型标注的常量里，再 `...场景判断段` 展开回同一位置。
6. **`GenerateToolCallResult` → `GenerateDetailedResult` 只改类型名**：`host.ts` 里
   `raw: config => generateRaw(config)` 和 `stop: generationId => stopGenerationById(generationId)` 一个字没动。
7. **`resetChatCaches` 是删死代码**：全仓搜不到任何调用点，它引用的变量也不是本文件可见的。
   删它不改变任何运行时行为（它本来就没被调用过）。
8. **`migrateSettings(raw: unknown)` 的 `unknown` 是放宽不是收紧**：原来隐式 `any`，
   现在显式 `unknown` + 函数内 `raw as Record<string, any>` 收窄一次。运行时一字未变。
9. **全量旧行为**：145 文件 / 断言 4574 全绿，含直接驱动这些文件的
