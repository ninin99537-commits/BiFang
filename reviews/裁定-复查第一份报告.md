## 总则（先定，避免每条都吵一遍）

判「成立」不等于「马上改」。本项目的病是**说的和做的不一样**，修法有三种，成本差一个数量级：

| 修法 | 成本 | 何时用 |
|---|---|---|
| **改文案**（让提示词说真话） | 最低，零行为变更 | 代码行为其实更好，只是提示词在吓人 |
| **加出声**（缺了记拒绝/沿用，不改行为） | 低 | 字段确实该有，但强制会拖垮整轮 |
| **改行为**（加校验/改判据） | 高，要真机验 | 缺了会真的坏事 |

**默认走前两条。** 理由是：这套代码已经在真机上跑过 113 快照，任何改行为都要重付一次真机验证的钱，而文案与出声是免费的。

## 发现 1 · 「只写一条新回响会把旧的回响刷掉」—— 成立（提示词说谎）

**我的复核**：`账本数据.ts:510-515` 的 `合并证据` 确实是 `旧值先入 Map → 新值覆盖同键 → 取 values`，即**增量并集**；`:561` 用在 `中间回响`。所以提示词 `prompts.ts:97` 那句是**不存在的灾难**。

**裁定：成立。修法 = 改文案，不改代码。**
代码的行为（并集）比提示词许诺的（会被刷掉）更好，且 P0.95 的漏写沿用本来就把没写的字段保住了。改 `prompts.ts:97` 的①，把"只写一条新回响会把旧的回响刷掉"换成真话（例如"中间回响是增量合并，你不写的那条不会消失；但**重复写同一件事**会让它变成日记"）。
**不成立的部分**：报告把它列成"契约不一致"，隐含代码该改。**代码不改** —— 并集是对的。

## 发现 2 · 回响配额「每章 3 条」代码不查 —— 成立，但**不按章改**

**我的复核**：`提醒.ts:535` `回响条数告警 = 6`；`提醒.ts:545-551` 唯一判据是 `(条.中间回响 ?? []).length >= 6`，无章号分组。`README.md:1459` 自己承认是提示词纪律。

**裁定：成立，但修法 = 统一口径，不做按章计数。**
按章计数的前置条件是"每条回响知道自己属于哪一章"，而 `中间回响` 现在只有 `记忆引用 + 楼层 + 公开摘要`（`schema.ts` 证据引用形状），没有章号。要按章算，得给每条回响加字段 + 迁移老账本 —— 这是**契约变化**，为一个"目标值"付这个代价不值。
改法：`prompts.ts:96` 把两个数的关系写成一句人话（3 是目标、6 是病态告警、代码只查 6），**代码不动**。
**这条我记在 P2 之后，不进本批。**

## 发现 3 · 「时间推进天数 / 当前时间」每轮硬要求但校验器不查 —— 成立

**我的复核**：`update.ts:40` `const 缺 = ['上一幕核验','下一幕'].filter(...)` —— 只有两个锚点。`账本数据.ts:968-971`：缺失时 `推进天数 = 0`、文本沿用旧值，**全程无声**。

**裁定：成立。修法 = 加出声，不加校验。**
理由：把它加进校验器 → 模型漏一次就整轮失败重试，而这两个字段的缺失后果是"故事内时间停住"，不是"账本被写坏"。**用整轮失败去换一个时间刻度，代价不对等。**
改法：`账本数据.ts:968` 附近，`时间推进天数` 与 `当前时间` 都没给时，往 `沿用` 通道记一条（形如 `世界时间 时间推进天数/当前时间`），复用 P0.95 的汇总行。这样它在 `代码调整` 里可见，但不拦。
**这属于 P0.95 的同类补齐，可以单独小批交。**

## 发现 4 · 命运必演「再 3 轮」vs 代码「总计 3 轮」—— 成立，但**是文案病**

**我的复核**：`引擎规则.ts:248` `既成事实撤下轮数 = 3`；`:289-295` `未执行轮 + 1 >= 3` 就撤。用例 `daoyan-第二轮优化.test.ts:76-78` 输出 `第 3 轮: 既成事实` / `第 4 轮(未执行轮到 3) → 撤下`。

**裁定：成立，但改文案，不改计数。**
报告说"按字面是既成事实写法发出后还要再等 3 轮，总约 5 轮"。**这句是对的**，同一句话里"再 3 轮"和"（脚本计到第 3 轮）"自相矛盾 —— 括注说的是总计，正文说的是再加。模型读哪一句都可能。
改法：`prompts.ts:184` 只留一个时间轴的说法（"脚本从第一次没演出来起算，第 2 轮改既成事实，第 3 轮撤下"）。
**为什么不动代码**：撤下轮数是"多久算导演没接住"的产品判断，3 轮已经在真机上跑过；改它等于重付真机验证的钱，而收益只是让提示词不用绕。

## 发现 5 · 幕纲「3~5 幕 / 至少一幕生活幕」无校验 —— 成立，**加一条提醒**

**我的复核**：`提醒.ts:731` 只在 `幕纲.length === 0` 时催补；`引擎规则.ts:132-137` `是生活幕()` 只看当前那一行。全事件幕、2 幕、6 幕都不触发任何信号。

**裁定：成立。修法 = 加一条提醒（不动 schema 枚举、不动长度约束）。**
理由：幕纲是模型自己的骨架，用 schema 卡死会让老账本读回失败；而"全事件幕"恰恰是最该被看见的失效（整章没有喘息）。
改法：`提醒.ts` 的 `幕纲现状` 那条旁边加一个判据 —— 幕纲非空且**没有任何一行**匹配 `类型: 生活` 时，提一句；幕纲数不在 3~5 时也提一句。只出声，不改账本。
**这是最便宜的一条，可以并入发现 3 的小批。**
