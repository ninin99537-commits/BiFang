# 缺陷：P1-8 壳去重在真机上**完全没生效**（查错了 document）

日期：2026-11-13
发现人：opencode（需求方，真机 CDP 验证）
状态：待 dsh 修
严重度：**高** —— P1-8 的代码验收（32 断言全绿 + 4 个变异全部命中）是**假绿**，真机行为与修复前完全一样。

---

## 一、一句话

`悬浮球界面.ts:39` 把**脚本 iframe 自己的 `document`** 传给了 `清掉同id壳`，
而壳 iframe 是 `$('<iframe>').appendTo('body')` 插到**父文档**（酒馆顶层页）里的 ——
于是去重在真机上永远命中 0 个，重复壳原地不动。

## 二、真机证据（用户自己的 Chrome，聊天 `最后生还者_2026-08-04`，v25）

### 2.1 壳在父文档，不在脚本文档

在**脚本 iframe** 里执行（`node tools/酒馆调试.mjs iframe -f tmp/cdp/probe-wrongdoc.js`）：

```
脚本id前8              : 0f8bbb9a
自己doc命中数          : 0          ← 清掉同id壳(document, ...) 查的就是这里
壳所在doc是父doc       : true
壳所在doc命中数        : 2          ← 真正的壳全在这里
$body选择器解析到      : BODY@父
```

`$('body')` 在脚本 iframe 里被 jQuery 解析到的是**父文档的 body**（实测 `$body是父body: true`），
所以 `.appendTo('body')` 把壳插进了父文档。这是酒馆助手的既有行为，不是我们的 bug。

### 2.2 逐字复现调用点的函数体，现状 vs 对照

在脚本 iframe 里把 `壳去重.ts` 的函数体逐字照抄，用两种 doc 各跑一次
（`tmp/cdp/repro-wrongdoc.js`）：

| 步骤 | 同 id 壳数 |
|---|---|
| 起始（父文档里） | 1 |
| 人为插入 1 个重复壳 | 2 |
| **`清掉同id壳(document, id)`（现状）** → 返回 0 | **2（原地不动）** |
| `清掉同id壳(父doc, id)`（对照）→ 返回 2 | **0（全部拆掉）** |

结论：**只差 `doc` 这一个参数**，函数体本身是对的。

## 三、为什么 162 个用例全绿还是没抓到（假绿的成因）

`tests/daoyan-J批-静默失败.test.ts:84` 的假 doc 是**外部注入**的：

```ts
const 假doc: any = { querySelectorAll: () => 元素表 };
check('同 id 的两个都被拆', 清掉同id壳(假doc, 'dj-1'), 2);
```

用例验的是「**给一个能查到壳的 doc，函数拆得对不对**」——
这是真的，也值得留。
但它**从没验过「调用点传进来的 doc 到底是不是壳所在的那个 doc」**。

这是**接线**（wiring）问题，不是**逻辑**问题。
纯函数抽得再干净、变异再全，只要没人验调用点的实参，接线错了照样全绿。

> 与本房间已公开的第 8 次踩坑（「判据本身想当然」）同型：
> 断言写的是我**以为**的输入，而不是**真机实际**的输入。

## 四、影响面

| 现象 | 真机是否发生 |
|---|---|
| 重复加载后出现第二个球 | **会**（去重没生效） |
| 父窗口 resize 监听累积 | **会**（旧 app 没 unmount，`onUnmounted` 不跑） |
| 量球定时器 / 观察器泄漏 | **会** |
| `pagehide` 只清自己那一个壳 | 是，所以重复壳会**留到下次刷新** |

真机现场已经能看到：序 0 `e43536b9` 那个**僵尸壳**（有 app、无 pinia、无 `dj-orb`、尺寸 `0×0`、`pointer-events:none`）就是历史上重复加载留下的残留，一直没被清掉。

## 五、建议修法（给 dsh）

调用点把 doc 换成**壳真正所在的 document**。壳是 `.appendTo('body')` 插的，
而 `$('body')` 已实测解析到父文档 body，所以：

```ts
// 悬浮球界面.ts:39 附近
const 壳文档 = ($('body')[0] as any)?.ownerDocument ?? document;
清掉同id壳(壳文档, String(useHost().vars.scriptId()), 建壳卸载器(壳的app));
```

**不要**改成在 `清掉同id壳` 内部自己去 `window.parent` 找 doc ——
那会把纯函数重新绑回平台，可测性又没了。接线归调用点，逻辑归纯函数。

### 配套要求（缺一条都算没修好）

1. **必须有一条用例真的盯接线**。现在 `悬浮球界面.ts` import 了 `.vue`，用例拉不进打包图，
   所以接线没法直接测。两个可选做法：
   - **A（推荐）**：把「算出壳文档」也抽成 `壳去重.ts` 的导出纯函数，
     例如 `export function 取壳文档(取body: () => any, 兜底: Document): Document`，
     调用点写 `取壳文档(() => $('body')[0], document)`。用例喂 `() => ({ownerDocument: 假父doc})` 断言拿到假父doc。
   - **B**：在 `壳去重.ts` 里加一条源码断言（读 `悬浮球界面.ts` 文本，断言第 39 行附近不再出现 `清掉同id壳(document,`）。
     B 更脆，但能挡住回退。
2. **变异必须红**：把修好的那行改回 `清掉同id壳(document, ...)`，至少 1 条用例变红。
   做不到 = 用例没测到接线。
3. **构建标记升 v26**（源码改了，指纹必变）。

## 六、顺带确认的两件事（不是缺陷，不用改）

1. `#dj-orb-force-style` 那条强制样式也被插进了**脚本自己的 head**，父文档里没有
   （实测 `forceStyle在父doc: false`）。但壳的内联 style 里已经带了 `border:none`，
   computed 也是 `none` —— 那条规则在真机上**是多余的**，不影响观感。留着即可。
2. `copyStylesTo` 读的 `document.head` 是脚本自己的 head，这是**故意的**（把脚本 iframe 的样式
   复制进壳文档），不是同一个错。
