# 剧情导演 · 剧情编排系统

一个运行在酒馆助手 (Tavern Helper) 中的脚本项目。同族第三块拼图：**彼方管"人"、烟火管"世界"，剧情导演管"戏"**——它不给主 AI 新设定、不记录世界事实，只做剧情的编排：伏笔、冲突、节奏、挫折与反转，让任何世界观（修仙/科幻/现代都市）都能写出电视剧/小说/电影那样的跌宕起伏。

## 为什么需要它

主 AI 有三个**结构性**缺陷，各对应一个机制：

1. **视野缺陷**：只看得见最近几层楼——第 5 楼埋的伏笔，第 40 楼早已出了视野。→ **剧情账本**（外置的长线记忆）。
2. **迎合缺陷**："舔玩家"，除非用户明令否则绝不写失败。→ **导演指令**（外部剧本的既定安排；演员不为剧本里角色的死亡负责）。
3. **结构缺陷**：平铺直叙，没有"压制→爆发→喘息"的波形。→ **导演引擎**（代码层结构规则）。

## 工作原理

每次 AI 完成正文回复后（频率可配，默认每轮）：

```
正文生成完成（防抖 800ms，连发只推最后一条）
      ↓
导演引擎（独立 OpenAI 兼容 API）读「剧情账本 + 最近正文 + 世界书」
      ↓
输出「账本更新 + 上一幕核验 + 下一幕指令」
      ↓
代码层结构规则调整节拍 + 装配本幕指令 → 写入楼层快照
      ↓
双层注入：编剧备忘（世界书常驻条目） + 本幕指令（生成前注入）
```

### 剧情账本（四本账 + 一个读数）

- **章回**（活跃 ≤1）：章号/主题/计划高潮/进度，按剧情事件分章、不以楼层计数。
- **伏笔**（≤8）：`{编号, 内容(冻结), 埋设层, 状态, 回收窗口, 关联冲突}`。状态机 `埋下→潜伏→发酵→已引爆→已消亡`；**编号由脚本签发、全局单调递增永不复用**；**内容写下即冻结**（只改状态，防"玩偶变蛋糕"）。
- **冲突**（≤4）：`{名, 对立面, 赌注, 强度, 阶段, 下一步, 顶回次数}`，阶段 `铺垫→升级→僵持→决战→收束→已收档`。
- **角色弧线**（≤5）：`{角色, 缺口, 阶段, 下一步契机}`，阶段 `…→闭环`。
- **张力读数**：由**代码按节拍增量表折算**（高潮 +4、受挫 +2、余波 −3……），AI 报的 0~10 仅按 30% 权重校正。

### 指标口径（§3 判据 · 别把它算错）

- **伏笔回收率 = `指标.累计了结 / 指标.累计埋设`（队列口径）**：同一批伏笔的比。
  `累计埋设` 在**签发新伏笔**时 +1（单调、不随章节清零）；`累计了结` 在某条伏笔**首次**转入 `已引爆`/`已消亡` 时 +1，**按编号去重**（同一条翻转多次只算一次）。
- **绝不拿 `章节统计.埋设数/回收数` 求和相除** —— 那两栏是"**哪一章**埋下 / **哪一章**了结"，
  第 2 章回收第 1 章埋的伏笔会让分子凭空多、分母不动，于是算出 **111%**（真机踩过）。
  它们只作"本章活动量"看。
- **迁移播种**：老账本没有这两个计数器时，装载时用**现存伏笔**播种（`累计埋设 = 现存条数`、`累计了结 = 现存终态条数`）。
  ⚠️ **只能以现存条目为准**：此前已被容量淘汰（伏笔上限 8）或早已删除的历史项**无法计入**，所以早期账本的分母会偏小。
- 数据异常（`累计了结 > 累计埋设`）**不静默夹断**：标记 `伏笔回收率异常`、日志打印两个原始数字，面板显示 `>100%?` + 原因。
- **`判据.起伏次数`** 由 `章节统计` 聚合（含进行中的那一章），活指标与结算卡都用它 —— 免得"读终值再重算"。
- **`指标.终值`**：剧终那一刻把 `计算判据()` 的结果快照进去（**写一次、只读不重算**），同时打一行成绩单进日志页；
  「清除已剧终」会清空 `终值`（恢复游玩后挂旧成绩会误导），但**日志页那一行留着**，随时可回看。

### 导演引擎（五条代码层结构规则）

1. **张力曲线**：连续 3 幕高张力 → 强制喘息幕；连续 3 幕低张力 → "山雨欲来"（静中埋险）。
2. **契诃夫之枪**：伏笔逾期优先回收；已失去意义的**允许自然消亡，不硬造**。
3. **收束调度**：章回逼近收束 → 未回收伏笔向本章高潮汇聚。
4. **高潮后必有代价**：高潮幕之后强制"战后余波"（**仅档 3/4**）。
5. **执行核验**：核验上一道指令是否被真正执行（**只按「必演 + 节拍」判**，硬性要求里的演法细节不同不算未执行）；
   未执行则把下一道收成**单点目标**——最多两轮，之后只演那一个点，不升级、不降目标、不把决定权交回玩家。

### 导演指令 = 外部授权

注入给主 AI 的不是事实，是**编排**（节拍 + 硬性要求 + 伏笔现场 + 禁止事项）。挫折/死亡由外部剧本既定，主 AI 只是执行，从而绕开迎合倾向。指令头部渲染当前**强度档位**与**红线**；其中**节拍是这一幕的结构要求**（要玩家付出什么），剧情参考/伏笔现场/不建议写才是可自由发挥的演法建议；玩家冲突处理**按档缩放**：档 1/2 玩家行动正常生效、指令让位；档 3/4 才允许"戏剧性失败/变形"。

## 用户控制

- **强度滑杆 4 档**：1 轻松日常 / 2 平稳叙事 / **3 跌宕起伏（默认）** / 4 残酷。
- **红线**：钉死不可触碰项（默认无红线，"完全交给剧本"），优先于一切指令与档位。
- **跳过本幕**：一键作废当前指令（下一幕重新生成），并重置核验升级计数。
- **连败自动让步**：同一冲突连续 2 次玩家被顶回，第 3 次让玩家赢。
- **死亡抉择**：检测到主角死亡时弹窗三选一（视角转移 / 世界观内复活 / 剧终结算），无默认项；**未抉择前暂停注入**新指令。
- **做全书结算**（账本页底部，不依赖死亡的第二条结局路）：两段式 ——
  ① 确认后账本记 `收官请求`，**下一道指令由代码编排为收束幕**（回收剩余伏笔、收束主线，节拍取 `兑现伏笔`）；
  ② 演完后由你在面板**确认剧终**（也要二次确认）才停摆。**收官请求 ≠ 已剧终**：期间引擎照常推进、账本照常更新。
  重复点击幂等（`请求收官` 只认第一次，攒不出第二道收束幕）；「清除已剧终」会把 `收官请求` 与结算快照一并清掉，否则会一直出收束幕。
- **防剧透**（默认开，**两个独立开关**）：`折叠未引爆伏笔` / `折叠章回计划` 各自可关。
  **点被折叠的那一行即可临时揭示**（只展开那一条，再点收回；切页签/刷新全部收回，**不写盘**）。
  折叠**只发生在显示层**：账本里的伏笔内容、计划高潮与发给引擎的文本一条都不少（零截断红线）。
  旧的一刀切键 `防剧透` 保留为兼容来源（不再显示在 UI）：新键缺失时用它播种，新键存在则以新键为准。
- **冷启动**：开局前 3 轮只记账不下令，第 4 轮起注入指令。
- **平静模式（2026-11-08，默认关）**：**只记账、不下令**。开着的时候引擎照常跑、章回/伏笔/张力/命运照常更新，
  但**不生成也不注入本幕指令** —— 正文 AI 拿不到节拍、剧情参考、「本幕已确定」，也不会被催着收线，
  这一段由你写。世界书里仍保留「编剧备忘」（谁死了、谁走了、什么不能反悔），防的是把死人说活。
  - **章号冻结**：伏笔的「最早章/最迟章/回收窗口」全按章算，章停住它们就不会因为你过日子而过期；
    所以关掉开关时不会出现"一批线同时到期"的清库存。
  - **必演/核验计数天然冻结**：平静期根本不走 `构造本幕指令`，所以 `装配必演` 不被调用，
    命运事件的「未执行轮」不会因为"我们没下发"而上涨（否则平静三幕会把一条必演静默作废）。
  - **关掉平静的第一轮也不核验**：那一轮 `上一道未下发 = true` —— 旧指令在平静期压根没给正文 AI 看过，
    拿"没演出来"去升级或改写目标都是错账；必演同样沿用但**不累计未执行轮**，升级计数清零。
  - **指标不记"未执行"**：平静期那道指令没下发过，`维护指标` 的指令执行核验整段跳过（否则平静 20 幕 = 20 次错账）。
  - **章回冻结发生在 `应用引擎输出` 的入口**（不是在 update 里事后覆盖）：否则 `维护指标` 会先用导演给的新章号
    结算一章、重置累计器，下一轮章号又"回落"，统计就乱了。
  - 与「关掉自动接管」的区别：那个是**完全撒手**（不跑引擎、什么都不注）；平静模式是**还在记账，只是不发话**。
  - **切开关当场对齐**（2026-11-11）：指令立刻重注；世界书「编剧备忘」按方向重写 —— 打开时写"平静版"，
    关掉时**只在平静一场都没跑过时才写"正常版"**，跑过就不写（那一段本来就没有剧本，"平静版"才是实话，
    下一次推进成功会重写成正常版）。备忘里另有一条失效条件（见到【本幕参考】就以它为准），漏了重写也不会反过来按住指令。
  - **关掉后的第一轮不复活旧编排**（2026-11-11）：平静期手上的 `当前指令` 是平静前那一道（实测隔着 36 场 / 74 层正文），
    它一场都没下发过。所以关掉开关的**第一段正文**只带红线，等下一次推进生成新指令再接着下令 ——
    面板会当场说清"手上那道是平静前的旧编排，这一轮不再注入"。
  - **红线仍然注入**：红线不是编排，是用户钉死的「不许写什么」。撤掉它等于"过平静日子就可以写性暴力"。
    所以平静期 `应注入的指令文本` 只保留一个红线块（[注入.ts](src/剧情导演/注入.ts) `平静期注入`），没有红线时才真的是空串。
    已剧终 / 总开关关 时连红线也不再注（顺序有意：那两条压过平静）。
  - **平静期不能「跳过本幕」**：标成 `已跳过` 会让 `装配必演` 读旧指令时被 `!已跳过` 挡掉 —— 那条命运必演就**静默丢了**。
    所以命令层直接拒绝，面板同时禁用按钮。
  - **群聊里连红线也不注**：插件的群聊策略是"零影响"，不该因为保留了红线就变成"悄悄还在管"。
    判断放在 `应注入的指令文本` 的入口（剧终之后、平静之前）。
  - **平静场数只在真的前进时 +1**：点「重新推进」重算同一楼不算又过了一场（否则点几下按钮就"已平静 5 场"）。
  - 球态沿用「待命」（不新增第六个球的视觉态），状态条另给 `calm` 级别（中性边 + 金色标签）。
- **群聊首版不支持**：检测到群聊即暂停并提示。

## 配置

### 接口

- **独立接口**：任何 OpenAI 兼容服务（地址末尾自动补 `/v1`），「获取模型列表」拉取后下拉选择。
- **直连（默认开，2026-11-07 学彼方）**：导演自己在脚本 iframe 里 `fetch {地址}/chat/completions`，
  **完全不经过酒馆的生成管线** —— 预设、世界书、其他扩展都碰不到请求体，也绕开酒馆自己的超时。
  关掉则回到「交给酒馆服务器转发」（`generateRaw`），浏览器不碰跨域。
  - 直连需要接口允许浏览器跨域（CORS）。**连不上时自动降级成转发**，只提醒一次，并在设置页留一行状态；
    关掉再打开「直连」开关即重新尝试（`重置直连降级()`）。
  - **401/400/超时不降级**：那是配置或上游的错，换条路也一样，偷偷换只会掩盖真问题。
  - 「获取模型列表」跟着走同一条路（直连就浏览器请求 `/models`），免得"能拉列表不能发请求"。
  - 直连超时固定 300 秒（含流式读取）；流式按 SSE 事件块解析，允许跨行 `data:` 与跨网络分片。
  - 请求体就是导演拼出来的那份：**不再拆 `user_input`**，消息数组原样发出（转发那条路仍要拆，
    否则 `generateRaw` 会追加一条空消息）。
  - 每一次真实请求各打一行日志（`请求 #N 发出 · 直连/酒馆转发 · 提示 X 字`），重试也各打一行。
- **流式 / 预填充 / 温度 / 最大输出Token**。

### 导演

- **自动接管**、**更新频率**（每 N 条回复推进一次）、**读取最近回复数**。
- **同人偏离度**：`关闭`（默认，**不注入任何原著约束**，原创卡用）/ `严格贴合`（节点按序发生，主角只能改过程与代价）/
  `允许偏离`（主线按序、支线随主角行动改写，改写后按新结果续推）/ `自由演绎`（索引只作背景）。
  开启后引擎读世界书里的**剧情索引**（`[编码] 时间｜概括`，蓝灯）当原著时间线；被撞毁的原著线改「已消亡」，不拽回原著。
- **提示条**（可观测性）：`全部（含开始）` / **`完成与异常`（默认）** / `仅异常` / `关闭`。
  **事件用提示条、状态用悬浮球** —— 选「关闭」只是不出声，球照样显示 编排中/出错/离线/剧终。
- **快照保留份数**（默认 **30**，可调 1~100）：删楼时账本可回退的楼层数；每份约几 KB~十几 KB，调大聊天文件变大。
- **高级（节奏与冷启动）**：**接管轮数**（默认 **4**：前 3 轮只记账不出指令，第 4 轮起编排本幕）、
  **连续高/低张力阈值**（默认各 **3**：连续 N 幕高张力强制喘息幕 / 连续 N 幕低张力安排「山雨欲来」）。
  这两个参数直接决定引擎的代码层规则，改完当轮生效（面板冷启动提示与引擎判定**读同一个值**）。
- **提示词开关**：破限 / 头部填充（可自定义文本）/ 防截断 / 预填充。
- **引擎读世界书**（与主 AI 相同激活逻辑）、包含全局世界书、世界书排除。
- **标签过滤**：处理发给引擎的回复（排除/只读指定标签）。

### 注入

- **事实层**：把常驻条目「**编剧备忘**」写进**按可用性解析出来的**世界书（蓝灯常开、防递归、切聊天重写、空则删）。
  落点顺序：① 角色卡主世界书（**先探测存在性**）→ ② 角色卡副世界书里**已有我们条目**的那本 → ③ 聊天世界书 → ④ 取/新建**专属聊天世界书**。
  **不盲写主世界书、不修改用户角色卡**：卡里 `extensions.world` 常会指向**未安装/改名**的世界书（链接悬空），
  这时 `getWorldbook` 会抛错——旧版直接写主世界书，于是**从来没写成功过**且错误对象是 `{}`（表现为静默降级）。
  现在悬空会被识别并**明确记一行"已回退到 X"**，全部目标不可用时**报出可读原因**（日志页 + 弹窗），不再伪装成正常。
- **只留一份**：落点会随绑定变化（悬空期落在聊天世界书 → 绑定修好后写回主世界书），所以**写完后会清理别处的旧副本**；
  关闭注入/剧终时**所有候选都撤**。否则主 AI 会同时读到两份、其中一份永远是陈旧的。
  设置页那个开关的文案与之一致：**优先写主世界书，不可读时自动回退聊天世界书，实际落点见日志页**。
- **指令层**：`injectPrompts` + `GENERATION_AFTER_COMMANDS`（`in_chat`, depth 0），生成前**幂等重注**，只读内存里已就绪的指令，**绝不 await 慢 API**。

### 与记忆插件共存（防混淆）

世界书里记忆插件提供的 `<记忆回溯>` 段落是**内容记忆**（剧情历史概要），不是世界设定、不是行动指令——引擎**不从中领取"必须推进的任务"**，**执行核验只针对最近正文**。导演的账本是**结构记忆**（戏演到哪了），两者互补不冲突。

#### 两级记忆读取（2026-10-27 长篇改造 · 阶段 A）

记忆插件的条目契约（`记忆检索.ts` 里只读不写）。**以下已用真机数据核对过**（2026-10-27，世界书「奇异人生时间线档案」，265 条）：

| 级别 | 条目名 | 灯 | 作用 |
|---|---|---|---|
| 目录 | `TavernDB-ACU-CustomExport-纪要索引` | 蓝灯（`strategy.type='constant'`，`at_depth 900`） | 记忆插件按当前剧情**动态**选出的事件概览 |
| 档案 | `TavernDB-ACU-CustomExport-纪要-N` | 绿灯（`strategy.type='selective'`，`at_depth 999`） | 每个 AM 一条完整纪要；AM 放在 `strategy.keys` 里 |
| **包裹** | `TavernDB-ACU-CustomExport-纪要-包裹-上` / `-下` | 蓝灯 | **标签与表头是独立条目**（见下） |

- **AM 才是事件引用，标题数字不是**。定位只认 `strategy.keys` 里的 `AM\d{4,}`；标题里的数字不参与匹配，
  所以「纪要-1」里装 `AM0187` 也不会读错。标题像纪要但没有 AM 关键词的条目**记进诊断、不当证据**。
- **包裹标签是独立条目**（真机核对到的关键结构，设计文档没写）：
  - `纪要-包裹-上` 的正文是 `<记忆回溯>` + `# 纪要表` + **表格列头** + 分隔行；
  - `纪要-包裹-下` 的正文只有 `</记忆回溯>`；
  - 每条 `纪要-N` **只存一行数据**，不带表头也不带标签。
  ⇒ 所以：① 包裹条目**不算**纪要条目（它们没有 AM，否则每条日志都会多一条假诊断）；
  ② 渲染时必须把「包裹-上」里的列头**补在每条正文前面**，否则导演看到的是一行裸数据，认不出哪一列是编码索引。
- **索引用于发现新联系，账本 AM 用于履行旧义务**。已登记在账本的 AM 即使当前 250 条索引里已经不出现，
  仍按关键词直接调档——这是跨几十章回收长伏笔的关键，**不依赖向量索引的当前可见性**。
- 平台路径是 `getWorldbook(name)`（返回**全部**条目，含未激活的绿灯），不是 `getWorldInfoActivatedData`
  （只返回被激活的）——后者只能读索引，读不到没被关键词激活的旧纪要。
- **零截断**：索引整篇给导演；每条被选中的纪要**整篇**给导演（真机用例逐字比对原文）。`记忆检索.ts` 里没有
  `.slice`、没有省略号、没有"最大字数/最大条数"。规模控制只发生在**选哪些完整条目**（`选证()`），不发生在条目内部。
- **不设条数上限**：一轮需要 100 条就完整读 100 条（用例 `daoyan-phase-a` A8/A9 逐条比对原文）。
- 缺失 / 重复 / 歧义**显式报告**：缺失的引用进「证据缺失」块（依赖它的关键回收降级为待核）；
  同一 AM 命中多条时把**每一条的完整正文**都给导演，代码不替他挑一条冒充。
- 导演可从当前索引用 JSON 字段 `候选证据: ["AM0004"]` 申请补充；这些 AM 进**待读队列**，
  下一轮完整读取。队列长度是**调度**，不是上限，绝不因"太长"被截断。
- 真机样例固化为 `tests/fixtures/memory-plugin-真实样例.json`（索引 + 包裹上下 + 6 条纪要原文），
  用例 `daoyan-phase-a` A20/A21 直接跑这份真实数据。

## 数据存储

- **设置**：全局变量（键 `剧情导演_settings`）——接口配置等敏感信息**导出脚本不会携带**。
  **写回纪律（P1 事故后立的规矩）**：① **深合并子字段**（`接口`/`导演`/`标签` 等对象逐字段合并，**不是整块替换**）；
  ② **只写用户真正改动过的字段**（与"成功读到时的基线快照"比对，初始化/解析填充不落盘）；
  ③ **读失败绝不写回**（存储抛错/格式坏/解析失败 → 关闭写回闸门，宁可这次改动不生效，也不用默认值覆盖真数据）。
  三条都为了同一件事：**陈旧或残缺的内存副本不许覆盖存储里的密钥**。
- **剧情账本**：**楼层变量快照**（删楼/重roll/切分支自动回退，保留最近 N 份）；聊天变量（键 `剧情导演`）只存轻量索引（快照楼层 + 清空层）。严格按聊天隔离。
- **界面偏好**：全局变量（键 `剧情导演_界面`）——悬浮球位置/面板位置/主题；**同样只写改动过的字段**并与存储里那份合并（`insertOrAssign` 是整键替换，直接写会冲掉别的窗口刚改的值）。
- **离线熔断与已剧终**：聊天变量 meta（与「快照楼层索引」同一个键内）——空密钥/接口失败这类故障发生在**账本落盘之前**，
  存快照必丢，所以连败次数、最后失败原因与时间、自动暂停、已剧终都存这一层；**已剧终与账本字段双写**，
  删楼/回退撤不掉它（清空账本才会连它一起重置）。`指标`（指标账）随账本进楼层快照，删楼即回退。
- **零截断原则**：所有发送内容（引擎输入/编剧备忘/本幕指令）一律不截断；规模控制只做在源头（账本容量上限、读取范围）。结构键（章主题/对手名/角色名等短字段）有上限=格式守卫，内容字段（伏笔内容/赌注/下一步/契机/高潮事件/指令文本）零截断。

## 界面（风格 B「剧本批注」）

一本摊开在暗处的剧本、旁边搁一支红笔：**暖墨灰纸面 + 唯一的朱红**，衬线标题，层次靠**边线与留白**而不是阴影与圆角。

- **规范源码**：`docs/mockups/剧情导演-风格对比.html` 的 `.sB` 块（值照抄）；施工图 `docs/剧情导演-前端改版-风格B实现说明.md`；
  契约由 `tests/daoyan-style-b.test.ts` 钉住（改漂了会被用例抓住）。
- **颜色只在 `主题.ts`**：面板 CSS 一律 `var(--dj-*)`、**零硬编码色**，深浅两套主题键完全一致。
  语义色分工：**危险/剧终/数据异常 = `seal`（朱红）· 警告/强度 = `gold` · 成功/已执行 = `good` · 离线/冷启动 = `inkFaint`**；
  墨色五档 `inkStrong / ink / inkDim / inkFaint / inkGhost`（不再被一个 `seal` 一词到底）。
- **数字必须能被扫读**：数字容器一律 `var(--dj-num)` + `font-variant-numeric: tabular-nums`（指标、张力、核验、明细）；
  字号收敛成五级：16 指标数字 / 17 标题（衬线）/ 12.5 正文 / 11.5 次要 / 10 标签。
- **圆角一律 2px**（球仍是 40×40 的圆），**阴影只留一层**（画在 iframe 上，面板自身不叠第二层）。
- **设计在 460 名义宽下验证**：面板契约是 `共用/面板机制.ts` 的 `面板宽/面板高 = 460/620`（**名义上限**，随视口取 min；窄屏 <700 走另一支），
  它写成 `.dj-panel` 的内联宽高、`box-sizing: border-box` → 量的是**面板本身**。对比稿画布写的 522 **不是契约**（别照抄）；
  真机量到的 iframe 更大，那是 `applyFrame()` 的"球∪面板 + 每边 4px"联合矩形，与面板尺寸不是一回事。
- **图标是内联 SVG**（`currentColor`、零依赖，不引 fontawesome/远程资源/远程字体）；卡片头用 `§` 批注记号而不是图标。
- **动效只回答动作**：页签/按钮/卡片 150ms 过渡；关键帧只有两条 —— 球的「编排中」呼吸环与状态条的回扫细条（都 1.6s）。
  `prefers-reduced-motion` 下动效全关，并把呼吸环换成**静态**朱红环（**换呈现，不换通道**）。
- **重点卡靠左边线分级**：普通卡左 2px `lineStrong`，判据卡与指令卡左 2px 朱红（用 `:has()` 选，不动 DOM）；
  状态条左 3px 用语义色 + 一个同色圆点。
- 仓库硬约束：禁 `vh`、无 `min-height`；**不新增滚动容器**（`overflow:auto` 只有既有的 `.dj-body` 与 `.dj-pre` 两处 ——
  改成 `hidden` 就是用 CSS 裁正文，违反零截断）；`position:absolute` 三处（球、面板、页签选中下划线的伪元素，
  最后一处照的是规范稿 `.sB`）。本插件是**独立全屏 iframe 浮层**（不是嵌在楼层里的界面），故 `fixed/absolute` 属形态必需。

## 可观测性（不用打开面板也知道在干什么）

起因是用户的一句话：「插件没弹窗，我不知道什么时候更新、什么时候更新完了、什么时候更新出错了，我还要进插件里看。」
排查结论是**机制在、事件不全、通道太弱** —— 于是定下：**状态用球（常驻、安静），事件用条（短暂、可关）**。

- **悬浮球五态**，优先级 `剧终 > 离线 > 出错 > 编排中 > 待命`（判定与 hover 文案都是纯函数，见 `球状态.ts`；面板只做绑定）：

  | 态 | 何时 | 呈现（环都在球**内**画，直径/层序/iframe 尺寸不变） |
  | --- | --- | --- |
  | `剧终` | `已剧终` | 朱红细环 2px + 字形转灰 |
  | `离线` | 熔断自动暂停 | `inkFaint` 虚线边 —— **离线不是危险，不用朱红吓人** |
  | `出错` | 上次推进失败、还没成功过 | 朱红环 3px，**常驻到下次成功**；期间用户点重推也保持（不被「编排中」顶掉） |
  | `编排中` | 引擎调用进行中 | 1.6s 呼吸环（reduce 下换静态环）；hover「正在编排本幕…」 |
  | `待命` | 其它（含冷启动记账） | 现状外观；hover 报最近节拍与几分钟前，或冷启动轮次进度 |

- **提示条四档**（`导演.提示条`，默认**完成与异常** ⇒ 每轮最多一条）。闸门设在 `toast.ts` 的 `showToast` 出口，
  所以「开始推进 / 完成 / 失败 / 熔断 / E1 未送达 / 快照没落盘」这些**既有调用点自动受同一档管**，不必各写一遍判断。
  「全部」才会每轮多一条 info；**「关闭」只静音事件，球状态照常工作**（球的判定不经过提示条这条通道）。
- **用时可见**：推进开始记时刻，完成提示与失败详情都带**用时**（`编排完成：本幕节拍 → 兑现伏笔 · 用时 48s`），
  慢的时候用户知道是在等、不是卡死。档位同步有三个入口：启动时（`index.ts`，面板没打开也生效）、每轮推进（`update.ts`）、设置页 `@change`。
- **面板辅助通道**：`编排中` 期间状态条下补一条**不确定态细进度条**（只表示“在跑”，不表示真实百分比）。
- 规格：`docs/剧情导演-可观测性-提示条规格-v1.md`；用例：`tests/daoyan-orb-status.test.ts`。

## 2026-10-20 — 导演指令禁令：杀掉导演自己写出来的八股

- **触发**：主 AI 写出「以专业医师的冷酷语调精准报出」这类句子。查下来的根因不在主 AI（它那边已经有
  一份反八股约束），而在**导演下发的指令本身带八股**：`下一幕.硬性要求` 写了「以……的语调」这种状语，
  演员照着执行，正文就长成那样。导演此前对**自己输出的文字**没有任何文风约束。
- **做法**：新增 `八股禁令.txt`（纯文本，`?raw` 引入），`prompts.ts` 剥掉 `<导演指令禁令>` 包裹后得到

- **规则内容**（管"下一幕"三个字段）：
  - 只写"谁做了什么、什么条件下、结果是什么"；禁「以……的语调/口吻/姿态/神情」状语，
    反例直接点名「以专业医师的冷酷语调精准报出」；
  - 禁给人物定性（精准/专业/冷酷/不容置疑），禁「是那种……的」「不是……而是……」句式；

  - 词与句：禁「那种/那层/这般/如此/极其/然后/像是/勾勒/弧度/指节泛白/喉咙滚动」，身体部位用日常说法，
    不用破折号与括号补注，不连续两句以上排比，指令里不用比喻；
  - 硬性要求三到五句、每句可核验；伏笔现场只给方向或编号；禁止事项写具体的事不写形容词。

## 2026-10-21 — 上游换了个污染形状(finishReason 前缀) + 移动端拖动跟手的三处漏

### 一、解析：元信息前缀 + 失败诊断

- **症状（真机）**：报 `AI 没有返回 JSON 对象`，原文头部是
  `finishReason: STOP` / `finishMessage: Model generated function call(s).` 两行，然后才是 `{"章回":…}`，
  共 1454 字。
- **先排除的错判**：这两行**不是**直接原因 —— `sliceBalancedCandidates` 从第一个 `{` 起扫，前面那段散文会被跳过。
  真正的失败是"一个完整候选都没切出来"= 最外层 `{` 扫到末尾没闭合（`解析.ts` 的 `if (!closed) break;`）。
- **它暴露的根因**：`finishMessage: …function call(s).` 说明模型走的是**函数调用**，上游把元信息 + arguments
  一起当正文塞进了 content；`finishReason: STOP` 而不是 `MAX_TOKENS`，说明**不是 60000 token 用完**，
  而是上游把 tool_call 的 arguments 截断/丢尾了。
- **改动**：
  - `共用/去信封.ts` 新增 `剥元信息前缀()`：剥掉开头连续的 `键: 值` 行（ASCII 标识符、值里不含 `{`），
    **守卫是"前缀之后必须紧跟 `{`"** —— 散文（`Note: 见下\n这段正文`）与裸 JSON 都不会被误伤；
    没命中就一个字节都不改。`去信封()` 先剥元信息再剥信封，两层污染可以叠加。
  - `解析.ts` 新增 `括号诊断()`：`诊断: '{' N / '}' N / '"' N`，引号奇数时标「字符串状态被打翻」，
    左括号多时标「截断」。**原文案原样保留在前**，既有断言按前缀匹配不受影响。
- **补测试**：`tests/去信封.test.ts` 新增 `[5]` 组（9 断言，含"中文散文/散文后不接 JSON 都不动"的守卫用例）；
  `tests/daoyan-envelope.test.ts` 新增 `[3]`（元信息 + 信封端到端）与 `[4]`（截断与引号奇数两种诊断）。
- **诚实边界**：真机那次只有 1454 字、且用户只贴了头部，**没有拿到完整原文**，所以"上游真截断"仍是
  根据 `finishReason=STOP` + 字数远低于上限推出来的，不是逐字复刻验证过的。

### 二、移动端拖动：三处只有触屏才会撞上的漏

- **症状（别人报的）**：「跟随触摸走，我手移到哪里他就跑到哪里」。
- **根因（三条叠在一起，桌面鼠标一辈子撞不到）**：
  1. `onOrbPointerDown` 手写 `rect.left + e.clientX` 当起点，而 `onOrbMove` 走 `parentClient()` ——
     两边对"事件来自哪个窗口"的判断一旦不一致，差出来的就是一整个 iframe 原点，球整块跳走再偏着跟手；
  2. 导演的 `.dj-orb` / `.dj-head` **没有 `touch-action: none`**（界面重做时漏掉的，烟火那份一直有）——
     浏览器把手指移动判成页面滚动，球跟着滚动的页面跑；
  3. 没听 `pointercancel` —— 手势被浏览器接管后 `onOrbUp` 不执行，`isDragging` 永久卡住。
- **改动（共用层，烟火同享）**：`面板机制.ts` 的球/面板拖动统一走 `parentClient(e)` 取起点；
  两处都挂 `pointercancel`（收尾时一并摘掉并复位 `isDragging` / `isPanelDragging`）；
  两处都 `setPointerCapture`（手指移出 40×40 iframe 也不丢事件，宿主不支持时 try/catch 兜住）；
  补主键守卫（鼠标右键/中键不拖）。导演 `.dj-orb` / `.dj-head` 补 `touch-action: none`。
- **补测试**：新增 `tests/panel-drag-mobile.test.ts`（18 断言，五组：同一坐标换算 / pointercancel 收尾 /
  setPointerCapture / 主键守卫 / touch-action 必须在球与面板抓手上），并把烟火当"原本就对"的对照组。
- **验证**：`pnpm test` **81 个用例文件全绿**（含新增 1 个）；`TAVERN_ENTRY=src/剧情导演/index.ts pnpm build`
  与 `TAVERN_ENTRY=src/烟火_世界运转/index.ts pnpm build` 均 exit 0（只有体积 warning）。
- **诚实边界**：① 三条根因里 **①③ 是代码事实，②是推断** —— 没有真机录屏能证明那次到底是哪一条先触发，
  所以三条一起修；② 断言全部是**源码级**的（扫函数体与样式块），没有触屏端的端到端回放。

## 2026-10-26 — 同人偏离度：原著约束块（四档，默认关闭）

同人卡要引擎按原著推进，而 user 的介入必然改变走向（蝴蝶效应）。这一批只做"约束"这一层。

### 不做的三件事

- **不做搜索**：引擎走 `generateRaw + ordered_prompts`，纯补全、没有 tool calling，酒馆服务器也不给脚本
  暴露搜索接口；要做就得在 `共用/模型往返.ts` 那条三插件共用接缝上开二元子，代价远大于收益。
- **不新增「原著锚点」字段**：剧情索引是主世界书里的**蓝灯**条目，`读书.ts` 与主 AI 用同一套激活逻辑，
  引擎本来就每轮读到它。手填时间线是重复输入。
- **不新增「主角定位」字段**：主角是否原著人物，从人设读得出。

### 做法

- `schema.ts` 新增 `偏离度`：`关闭 / 严格贴合 / 允许偏离 / 自由演绎`，默认 **关闭**。
  **关闭就是总开关**（整块不拼），不再另设「同人模式」布尔值 —— 两个开关表达同一件事会互相打架。
- `prompts.ts`：`SYSTEM_PROMPT` 拆成 `_HEAD` / `_TAIL` 两段（原常量仍导出，等于两段拼接），
  `build原著约束(档)` 插在【结构记忆】与【四本账】之间；关闭时返回空串，拼回去与原文本逐字节一致。
  块内容：编码格式不统一只作标识且不得编造 / 按索引排列与时间判先后 / 优先推进下一个节点 /
  人在索引里以其设定为准不得 OOC / 未发生节点不许提前与剧透 / 主角不在索引里按原著之外的人处理 /
  被撞毁的原著线改「已消亡」，不得把剧情拽回原著。
- `取料.ts` 把 `设置.导演.偏离度` 交给引擎；设置页「导演」卡新增同名下拉（四档可见）。
- 块内**只写要求、不写理由**（与 `八股禁令.txt` 同一条纪律）。

### 验证

  「发送路径不含 slice/substring」当场抓住 —— 改成两段常量拼接，守卫没有放宽。

  返回 `未到 / 可催办 / 已过最迟 / 无窗口` 四态。
- **最早章未到 → 代码完全不催、不改节拍**。旧 `引擎规则` 自己解析窗口文本后无条件把节拍改成「兑现伏笔」，
  这就是"刚埋下就催"的来源。
- **最迟章到 ≠ 必须下一幕引爆**：只进"评估/催办"，且新增 `最近催办章` **节流**（同一章只催一次）。
  想让它继续潜伏就写 `延期原因` + `延期到章`，到期前不再催。
- **收束调度不再取数组第一条发酵/潜伏**：改为从 `取兑现候选()` 里挑（窗口已开 + 本章未催办 + 按紧迫度排序）。

### 持久后果（用户问题② 的根因）

- 新增结构化 `持久后果`：`{ID, 内容, 来源证据, 状态(持续/已缓解/已解除/误记撤销), 消退证据}`。
  纯字符串的 `永久后果` 保留作**迁移来源与显示兜底**。
- **普通挨打/疼痛/疲劳/尴尬一律不该进持久后果**（提示词明写）；已经误记的可以 `误记撤销` + 证据清除。
- **状态从「持续」改成别的必须带消退证据**，否则代码拒绝并保留原状态。
- 措辞从"不可复原"改成**"不会因无事件而自动消失；可经治疗/赎还/和解/剧情修笔有证据地改变"**。
- `已缓解/已解除/误记撤销` 的后果**不再进**「必须保留」与蓝灯备忘。

### 命运册对账（不再"只增不删"）

- `永久后果/承诺与债务/未竟计划/独立目标` 改为**对账**：漏返回 → 保留；显式给值 → 以新值为准；
  **从有到空必须有证据**（防模型悄悄把"破产"抹掉）。
- 关系未解矛盾给和解路径：真正的和解事件可以消退，不再永远注入"一句道歉不得自动复原"。

### 证据生命周期与锚点

- `兑现证据` 属于**某一次尝试**，新增 `兑现尝试[]`。终态被撤销（误标/重新规划）→ **清空兑现证据**并记一次 `已撤销`，
  否则旧误标证据会替后续新尝试自动放行。
- 新增 `证据链.盖章证据()`：**已核/待核由代码的检索结果决定**，模型自报 `定位:"已核"` 一律被覆盖。
  歧义 AM（命中多条）**即使读到也不算已核**；读取失败时全部降级。
- 状态变更的证据必须**指向本轮锚点楼层**，旧 AM 可以当埋设/回响证据但不能冒充本轮新事实（记拒绝）。

### 其他修复

- **幕后真相修订守卫**：改写必须带新的 `真相修订原因`，否则保留原真相并记拒绝。公开线头仍然冻结。
- **续演视角校验**：导演给的不存在/不可行动的视角不接受；没给时只从"能承接未竟线"（有未竟计划/独立目标）里挑，
  不再"命运册第一个活人"；一个都没有 → 空串交给玩家裁决。
- **镜头外真实链路**：命运册新增 `位置` 与 `最后推进幕`（**幕计数**，原先误用楼层号与幕数相减）；
  采集时传入 `在场`（当前视角/续演视角）；候选在写账流程里**逐条校验**并把 `最后推进幕` 推进到当前幕；
  镜头外行动只作"计划/幕后推进"，**不伪写成观众已看到的公开证据**。
- **待读队列**：`候选证据` 必须在本轮**真实索引**里才入队（索引外只作可见诊断 `筛索引外申请`）；
  `已读次数` 真正递增；拿不到索引时一律不入队。
- **蓝灯注入收敛**：公开线头、冲突名/赌注/阶段、弧线阶段**不再常驻**（"读者公开 ≠ 正文 AI 每轮都需要"）。
  备忘只留当前视角、持续中的后果、未解关系 + 条数级连续性提示；本幕该碰什么由「本幕指令」指认。
- **红线升级为结构化闸门**：设置新增 `保护角色`（角色 ID 列表）。命中者的死亡/离开/失踪与新增持久后果被**代码拒绝**。
  自由文本红线仍只是提示词约束（README 与面板都写明这一点，不再假装代码能解析中文）。
- **快照迁移补全**：`规范化指令` 原先丢弃 `本幕揭示` / `必须保留` —— 删楼回退重载后演员的硬约束会凭空消失。已修。
- **执行核验**：`上一幕核验` 缺省**不再默认成功**（三态：明确 true / 明确 false / 缺省按未执行并标注来源）；
  封顶后不再反复加码，改为**收成单点目标**（2026-11-11 之前是"降低单幕目标 + 把决定权交回玩家"，
  那一版会把"可以交回玩家"塞进给正文的文本；改法见文末 2026-11-11 核验口径那节）。
- **节拍不再强行复位**：导演给了明确 `硬性要求`（说明本幕有具体因果意图）时，"高潮后必余波 / 连续高必喘息"
  只写建议、不改节拍。

### 2026-10-29 反舔与长线配套（账本层 · 全部"记账 + 提醒"，不命令正文）

**原则**：代码判断不了"这一句算不算舔用户"（纯语义），所以只做两件事 —— **记账**、**把可数的事实提醒给导演**。
正文收到的仍然只有「本幕参考」（演法自由），**后果不因玩家不满而取消**。

| 字段 / 机制 | 谁维护 | 作用 |
|---|---|---|
| `代价[]` + `连胜无代价` | 导演声明 + 代码记账 | 每次"赢"要付代价。代价必须带 `持久后果ID` 指向 `角色命运.持久后果`；**没有落点 → 存疑，不清零连胜**（嘴上代价不算） |
| `冲突.最后行动幕 / 最后行动天` | 代码回写 | 对手多久没主动出手。按**幕**（= 已分析轮数）与**故事内天数**计量，**不用章**（一章可能几十上百层） |
| `世界时间 { 天数, 文本 }` | 导演声明天数，代码累加 | 故事内时间的唯一刻度；天数只增；文本与累计天数不一致时提醒纠正 |
| `当前节拍 { 节拍, 已持续轮 }` | 导演输出 `节拍结束` + 代码 | **节拍是戏剧功能单位，不是楼层**：一轮可能只是节拍的一小段；未结束只累加轮数，不刷满节拍史、不重复折算张力 |
| `章回.幕纲 / 当前幕号` | 导演 | 3~5 幕骨架；越界幕号由代码 clamp |
| `伏笔.误导说明 / 误导证据` | 导演 | 红鲱鱼（fair-play：回看必须找得到）。只在**待兑现**时催，最多 2 条 |
| `读者领先 { 事项, 哪些角色还不知道, 建立幕, 最后更新幕 }` | 导演 + 代码时间戳 | 信息差（读者知道、角色不知道）。漏输出=保留；**6 幕没更新**提醒"该揭穿还是继续" |
| `结构提醒()` | 代码 → 导演输入 | 把上述事实 + 节奏（高点堆叠 / 长低张力 / 缺低谷 / 中点 / 结局前崩塌）整理成事实清单，最多约 12 条 / 900 字 |
| 跨轮不升级 | 代码规则 | 节拍已第 2 轮且"未执行"时**不升级**，只提示"仍在演" —— 因为导演只看得到最近三层，误判概率高 |

**仍然无法保证的**（如实记录）：
- 代价是否"真的是代价"仍靠模型判断；代码只核对它有没有落点。
- "上一幕是否执行"只能从最近三层推断；跨轮软化只降低误判后果，不能消除。
- 信息差不会自动过期（靠提醒，不靠删除）；误导提醒在补上之前会持续出现（已限流到待兑现 + 2 条）。

### P4 · 角色不能全知（2026-11-06）

- 病根：导演是全知的（书纲/幕后真相/整本账本），角色不是。导演把自己知道的当成角色知道的，
  就会出现"角色 A 汇报了一件 A 没参与也没听说的事"。
- **判断权在模型，不在代码**。第一版做过关键词闸门（提到某人 + 有"汇报/依据/使用"这类动作就拦），
  用户否掉了，理由成立：同一件事有无数种说法（知会、提了一嘴、顺口说了、用代词），关键词查不出来；
  而硬拦还会把本来正确的必演一起丢掉。那个 `检查全知()` 已删。
- 现在的分工：
  - **导演自查**：输出里多一个 `知情核对`，每条写 `{角色, 这件事, 知道吗(知道/不知道/不确定), 证据, 处理}`。
    每安排一件要角色知道的事，先自问三句：他知道吗 / 证据是什么 / 不知道这一幕怎么办。
    **证据写不出具体的，按「不知道」算**；`处理` 写换人、先演"得知"、或干脆不提。
  - **自查不依赖 `<cb>`**：`<cb>` 有时没有、也覆盖不全。提示词写明"有就对照，没有就靠自己的账"，
    并另给一份【自查"这件事他知道吗" —— 证据去哪找】清单（`知情.渲染证据来源`），按可靠程度排：
    ① 本轮正文（他说过/做过/在场吗）② 记忆纪要的 AM 条目（引用编号最有力）
    ③ 账本自己的记录 —— `角色命运.已知事实引用`（带条目数与原句，空着也说出来）、
    `伏笔.知情角色`、`读者领先.哪些角色还不知道`、`前情`（当初埋下时的公开摘要）④ `<cb>`（有就以它为准）。
    末尾写明：证据要能回查（AM 编号 / 第几场 / 账本哪一栏），"他应该知道""这么久了肯定听说了"不算证据。
  - **代码只做材料与传递**：`知情.解析不知情` 把 `<cb>` 拆进镜头外推进块（那个 NPC 自己的清单）；
    `知情核对` 原样收进 `指令.知情核对`，随本幕指令下发（`【本幕知情核对】…`，标"不知道"的连处理一起给），
    并摊在本幕页给用户看。
- 结构上仍有三道轻保险（都不是语义判断）：
  `规范化知情核对` 只收拾格式、去重、封顶 8 条，没写"知道吗"的一律按「不确定」；
  写着"不知道/不确定"却没写 `处理` 的，在指令里补一句【自查没写完】提醒正文别让他们接触这件事；
  同一批缺口下一轮会出现在 `结构提醒` 里（写完了就不再提）。
- 诚实边界：导演自查可以敷衍（写个"他猜到的"）。代码不校验，只在面板上摊开 —— 敷衍看得出来，
  但拦不住。真要拦，只能再花一次模型调用做独立审查（用户当前选择不做）。

## 2026-11-08 — 平静模式（只记账不下令）+ 三处用户实测修复 + 熔断自愈

### 一、平静模式

用户原话：「开了插件之后就会一直强制高潮、低谷之类的，不能有平淡的生活了」，
以及关键的一问：「要是让他写的话，剧情岂不是又会和她写的一样了？」

**诊断**：问题不是"强制高潮"，是**代码不允许平静超过 3 幕**：
张力曲线连续低 3 幕 → 强制节拍改成「阴影」（"静中必须埋险"）；
节奏提醒连续低 3 场 → 注入"别让剧情平着走"；
契诃夫之枪到最迟窗口 → 强制节拍改成「兑现伏笔」。
更根本的是七个节拍里**没有一个是"什么都没发生"** —— 低张力那三个（小胜/阴影/余波）全是事件。
四档强度只调**后果严重程度**，不调**事件密度**，所以把滑杆拉到「轻松日常」也照样每 3 幕被推一把。

**做法**：不做"加一个日常节拍"（那只是把"被逼着跌宕"换成"被逼着温馨"，决定权还在引擎手里），
而是把插件一直在做的两件事拆开：**记账**与**下令**。

| | 正常 | 平静 |
|---|---|---|
| 调引擎、更新章回/伏笔/张力/命运 | ✓ | ✓ |
| 生成并注入本幕指令 | ✓ | **✗** |
| 章号推进（伏笔窗口的刻度） | ✓ | **✗ 冻结** |
| 必演未执行轮 / 核验升级次数 | 会涨 | **天然不动** |

- 注入层：`应注入的指令文本` 在平静模式直接返回空串。正文 AI 只从「编剧备忘」（世界书常驻）看到公开后果。
- 引擎层：`update.ts` 平静分支**跳过 `构造本幕指令`**。这是"冻结计数"的实现方式 ——
  `装配必演` 不被调用，所以「未执行轮」不会因为"我们没下发"而上涨。
  若只做"不下令但仍构造指令"，平静三幕会把一条命运事件按 2 轮改既成事实、3 轮撤下，**静默作废**。
- 取料层：平静期 `结构提醒` 传空数组，不给导演任何"该推进了/该收线了"的提醒；
  `buildDirectorMessages` 增加【平静期 · 这一段只记账，不下令】块（不安排必演、不推进章回、不催伏笔）。
- 状态层：`计算运行状态` 新增 `calm` 级别，优先级 剧终 > 离线 > **平静** > 冷启动 > 运行中
  （平静压过冷启动 —— 平静期本来就不下令，再显示"再攒 N 轮"会让人以为坏了）。球的五态不变。

**伏笔为什么不用封存**：按"场"计的地方有八处（埋设场、最后回响场、跨度、回收窗口、矛盾起始场、
最后行动幕、镜外推进幕、章长阈值），冻结要逐个改判定，漏一处就是"永远不到期"的僵尸伏笔；
叙事上，伏笔本来就是"会到期的东西"，允许无限拖延会在关掉开关时一次性爆开。
改为**章号冻结**：窗口按章算，章不动 → 窗口不动 → 不会积压，而账本一条不少。

### 二、「重新推进」的语义修正

旧实现无条件 `discardSnapshotAt(锚点楼层)`。当最新一层根本没被推进过（自动推进被跳过/失败/熔断）时，
锚点还停在**上一轮**，于是撤销的是上一轮成功的账 —— `已分析轮数` 先 −1 再加 1，**原地打转**，
冷启动永远攒不满（用户："难怪我已经推了好几层了，还是一直卡在冷启动 3"）。

现在按 `取撤销楼层(锚点, 最新楼)` 判定：**锚点停在最新正文上才撤**（这一层真推过），
否则直接当普通推进跑。读不到最新楼层也返回 −1（推进本来就会失败，别顺手破坏账本）。

### 三、导演台可编辑

导演台展示的字段全是引擎产物，以前只能看 —— 连"本幕已确定写错了想改一行"都做不到。
新增「改这一层」：节拍（下拉枚举）/ 本幕已确定（文字 + 镜头外 / 按既成事实写）/ 硬性要求（多行）。
走 `命令.改当前指令` → `应用指令补丁` → 提交（**重注本幕**），下一段正文即按改后的演。
- 只开这三个**真进注入**的字段；编号、代码调整、核验升级次数、知情核对归代码所有（手改会让核验与日志对不上）。
- `本幕已确定` 清空 = 删掉整条（留空壳会让注入出现光秃秃的【本幕已确定】）。
- 被「跳过本幕」作废的指令，一改就**恢复生效** —— 否则"改完什么都没变"看着就是坏了。
- 草稿与账本分离：边打字边重注入没有意义，点「应用到这一层」才写回。

### 四、熔断不再死锁

用户贴来的日志（不是本机的，是别人那份）：

```
[06:12:56] warn [剧情导演] 引擎已自动暂停(连败达阈值), 自动路径跳过
[07:32:xx] warn ... （一路刷到 07:32）
```

**机制是对的，实现有三处缺陷。** 熔断本身：接口连败 3 次 → 暂停自动推进，别每轮白烧 token
（一次推进内部还会先重试 3 次，那是另一层；熔断数的是**推进次数**）。问题在：

1. **死锁**：暂停后自动路径直接 `return`，而复位只认"成功一次" —— 不跑就不会成功，不成功就不复位。
   唯一出口是面板「本幕」页那个「恢复自动接管」按钮，而自动路径只 `console.warn`，不弹提示，等于没有。
2. **半死**：注入没停，正文仍拿着一道越来越过期的指令往下演，账本却已经停了。
3. **文案误导**：面板写"已自动暂停自动接管"，读起来像程序改了用户的「自动接管」开关 —— 其实没动，
   那是 `离线.自动暂停` 这个独立标记，只在自动推进路径上多拦一道。

修法三条：

- **冷却自动放行一次**（`运行状态.ts` 的 `熔断冷却毫秒 = 10 分钟` / `熔断可放行`）：暂停超过 10 分钟，
  自动放行一次试探。成功照常 `清推进失败`（自愈）；失败照常 `记推进失败`，`最后失败时间` 把冷却重新推后 ——
  天然就是"每 10 分钟最多试一次"。没有 `最后失败时间` 的老数据直接放行，不把人锁死。
- **首次暂停弹一次提示条**：`index.ts` 里模块级 `已提示熔断` 控制，只在刚进入暂停时弹，
  文案给出「恢复自动接管」按钮位置和冷却时长。不再每轮 toast（那会训练人忽略提示）。
- **熔断期间只剩红线**：`应注入的指令文本` 里加一道 —— 引擎停了就别再下过期的令。
  红线保留（`红线块(settings, 原因)` 现在被平静模式与熔断共用），因为它和"引擎坏没坏"无关。

**这一轮又补了五处**（都是"状态组合"没想全）：

| 漏洞 | 修法 |
|---|---|
| 「自动接管」关 + 平静 → 红线仍注入，破坏"完全撒手"语义 | 自动接管判断提到平静之前 |
| 等死亡抉择 + 平静 → 红线仍注入，暂停不彻底 | `暂停注入 \|\| 待决死亡` 提到平静之前 |
| 恢复后再次熔断不再弹提示（模块级 flag 不复位） | 读到"没暂停"就重置 `已提示熔断` |
| 离线态只写"连败 3/3"，不写多久后自动试 | 明细补冷却剩余分钟 + 立刻恢复入口；平静也开着时补一句 |
| 平静期调引擎只是为了记账，球却显示"正在编排本幕" | 悬停文案按平静分叉 |

**注入顺序现在钉死为**：总开关 → 已剧终 → 群聊 → 自动接管关 → 暂停注入/待决死亡 → **平静** → **熔断** → 无指令/已跳过。
前五条都是"用户明确说过别管"或"这一刻不该有东西"，压过平静；平静与熔断同级（都只剩红线）。

  章号往前推 —— 这是有意的。

## 2026-11-11 — 核验口径：节拍不再是"参考"，升级/封顶不再给正文放行条

用户实测原话：「就是一直未落实」。现场是四道指令连判"上幕未落实"（核验升级 0→1→2 已封顶），节拍连着四场 `受挫`，最后一道指令自己写着"只要求完成最小的那一步…可以把选择交回玩家"。

### 一、先排除了"注入坏了"

在酒馆页面里直接读运行态：`extension_prompts["daoyan-act-<scriptId>"]` = `in_chat / depth 0 / role system`，内容就是当前那道指令，而且每次推进后都换成新的。**注入层是通的**，问题在文本内容与判据。

### 二、真病因：注入按"建议"发，验收按"命令"判

| 层 | 旧行为 |
|---|---|
| 注入 | 节拍渲染成「1. 本幕节拍**参考**」，落在"第 1~4 项是导演给的**演法建议**…不必逐字照做"的伞下 |
| 核验 | 导演提示词 Step 1 拿整道指令判执行，典型例句就是「要求受挫, 实际又赢了 = 未执行」 |
| 结果 | 正文按 2026-10-29 要来的软化办 → 导演每次判没演 → 升级 → 封顶 → 指令越写越软 → 更不演 |

**2026-10-29 那次软化本身没有错**（用户要的是"能跨日"，而当时的导演指令会拿节拍卡住时间），错在**软错了层**：它软掉的是演法，却顺手把与"演法"同级的节拍也软掉了，而节拍恰恰是核验的判据。

### 三、四处改动

1. **节拍从豁免里摘出来**（`prompts.ts`）：第 1 项改写成「这一幕的结构要求：受挫 —— 主角计划遭遇实质性挫折, 损失真实且本轮不得自行挽回…结果不能换成相反」；"不必逐字照做"只修饰第 2~4 项（剧情参考/伏笔现场/不建议写）。节拍的语义收成**一份**（`引擎规则.ts` 的 `节拍结构`），导演提示词与给正文的指令共用，防两处漂移。
2. **升级话术换成正文能执行的**（`引擎规则.ts`）：`【上幕未落实·换个写法】…**这次换个实现路径**` → `【这一幕只做一件事】…只把「必演」/节拍要求的结果推到最小的一步`。理由是 ③：正文 AI 只看得见**当前**这道指令，没有"上一版写法"可比，"换个路径"对它无从执行。
3. **封顶不再把决定权交回玩家**：`…若仍然做不动, 就停止推进并把选择交回玩家` → `【这一幕只演这一件事】…不铺垫、不开新线、写完就收`。原来那句是写给导演看的元话术，正文读到"可以交回玩家"只会更不敢演。同理，核验缺省（模型没明确回答）不再塞进给正文的文本——它已经记在 `核验.说明` 里。
4. **把"这一幕确定发生什么"变成必填**：导演提示词新增一条硬规矩——**确定要发生的事只有写进「下一幕.必演」才会被当真**（只写进硬性要求＝只算演法建议，核验也不按它判）；Step 3 同一句。另外 `取料.结构提醒` 在"上一道指令没有必演"时把这件事摆回导演面前。这一条针对的正是现场那三份 `必演=null` 的指令：**唯一硬的槽位空着，唯一能判的节拍又被标成了参考**，那三轮在结构上不可能通过。
5. **核验口径写明**（`prompts.ts` Step 1）：只按「必演 + 节拍」判；硬性要求里的细节写得不一样**不算未执行**；上一道没有必演就只按节拍判。

## 2026-11-11 — 平静接缝：切开关当场同步备忘；关掉平静不复活旧编排

平静模式本身没问题（`平静场数` 记着、章号冻着、必演/核验计数冻着）。出问题的是**关掉它的那一刻**，接缝上有两处：

1. **世界书「编剧备忘」不跟着开关走**。备忘是按当时的开关状态**一次性写进世界书**的，而重写只发生在「推进成功 / 切聊天 / 删楼swipe / 总开关」——切开关本身不写。于是关掉之后，正文仍然读到 `**当前是平静期** … 上一条指令提到的东西也不必执行`，而注入层已经开始下令。**备忘是蓝灯常驻、每轮都读，而且明确叫演员忽略指令**，所以正文听它的。这个窗口能挂很久：推进被短回复(<500字)/更新频率/熔断跳过时都不会重写。
2. **关掉后注入的是"平静前那道旧编排"**。平静期**不构造**指令，`账本.当前指令` 一直是平静前那一道（实测：`编号6 / 生成楼层1399`，距今 74 层正文、36 场平静）。它一场都没下发过，章号也冻着不会往前走——注回去等于让正文去演几十场之前那一幕（那道的内容是"换黑水桶、背靠背守夜"）。

### 修法

- **开关绑 `@change`**（`悬浮球界面.vue` 的 `切换平静模式`）：`renew本幕指令(...)` 每次都做；备忘**按方向**决定写不写——
  - 打开平静 → 写"平静版"（这一轮确实没有本幕剧本）；
  - 关掉且 `平静场数 = 0` → 写"正常版"（平静一场都没跑过，手上那道指令还有效，备忘该指向「本幕剧本」）；
  - 关掉且 `平静场数 > 0` → **不写**：这一轮注入层只出红线（旧编排作废），"平静版"备忘才是这一轮的说实话；
    正常版会说"本幕要推进什么，见「本幕剧本」"，而那时并没有剧本。下一次推进成功时 `update.ts` 会重写成正常版。
  - 总开关关着时直接 return（那时该零影响，一个字节都不写世界书）。
  - **一条规矩**：备忘写"平静/正常"必须与"这一轮注不注指令"同源，否则同一个事实就有了两个版本（这次的根因就是这个）。
- **注入层新增 `平静前指令作废(data)`**（`注入.ts`）：`平静场数 > 0` 就认定"手上那道是平静前的旧编排"，这一轮**只出红线块**，等下一次推进生成新指令。判据特意用 `平静场数` 而不是"关掉开关的时刻"——它是账本里唯一能跨刷新/跨会话存活的证据，而它的清零时机恰好就是新指令生成那一刻，窗口自己会关。
  - 位置在 `没有指令 / 已跳过 → 空串` **之后**：那两条的既有语义是"一个字都不注"，不能被这个新分支改成"只注红线"。
- **面板与注入同一个判断**：「指令预览」空着、球上的必演提示点熄掉、**导演台整块收起**（否则台上还摆着"本幕已确定 …"，是假信号）、空态文案改说"手上那道是平静前的旧编排，这一轮不再注入"，而不是落到 default 去说"指令已跳过"（它没被跳过，只是过期了）。停用/剧终/离线/上次编排失败仍然压过这句话。
- **备忘自带失效条件**（`prompts.ts`）：平静备忘末尾补一句"一旦上下文里出现【本幕参考】，说明平静已经结束，以它为准，本条作废"。这样即使漏了一次重写，也不会反过来按住指令。
- **推送末尾的双层注入改用"此刻"的设置**（`update.ts`）：引擎那半段仍用发起时的快照（它是一次请求的参数），但"现在往上下文里注什么"必须按现在算——一次推进几十秒，期间用户切了平静模式，用旧快照会在平静期把指令注进去、或把备忘写成相反版本。

## 2026-11-11 — 自查批次一（注入 / 命令 / 管线 / 数据层）：三处"口径不统一"

逐层对了一遍代码（`注入` → `导演命令` → `update` → `引擎规则`+`prompts` → `账本数据`+`证据链` → 面板写入点），修掉三处，另记两处**故意没改**的。

### 修掉的三处

1. **指标不吃"没下发过"的核验**（`账本数据.ts` + `update.ts`）：平静刚结束那一轮，开关已经是 `false`，但被核验的那道指令**一场都没给正文看过**。原来只有 `平静` 一个开关在管"记不记这笔"，于是那一轮照样记一次"未执行" —— 而引擎侧的文本明明写着"本场不做核验"。现在 `应用选项` 多一个 `上一道未下发`，由 `update.ts` 算一次（`平静场数 > 0`），**核验文本 / 升级计数 / 指标**三处共用同一个值。
2. **休眠刻度不再每轮被刷成当前章**（`账本数据.ts`）：`最后推进章` 原来无条件写成"当前章号"。它正是 `取休眠伏笔` 的基准，于是"久未推进"永远算成 0、审计里的"平均休眠章数"恒为 0 —— 长线伏笔的休眠提醒等于被关掉了（`窗口停滞` 那条通道还在，所以不是全瞎，但漏掉一半）。现在只有这条线**本轮真的动了**（状态变了 / 多了中间回响 / 多了兑现证据）才推指针，否则沿用旧值。
3. **面板与球的熔断状态会自己刷新**（`悬浮球界面.vue`）：`离线` 那个 ref 以前**只在点按钮时**刷新。推进连败熔断后，球还写着"运行中"，用户看不到"已自动暂停"，也就不会去点「恢复自动接管」—— 而"让人知道"正是熔断存在的理由。现在两个刷新点：一次推进结束（成功/失败都写 chat meta）、面板打开。

### 这一批记下、下一批已改掉的三处

（原来是"发现但没改（要你拍板）"，用户当场拍板"123 都修，而且不要有任何的代码截断"，改法见下面「自查批次二」。）

- **补读窗口会静默跳读**（`取料.ts`）：`未读 > 补读上限(8)` 时只取**最近** 8 条，中间那几层再也没人读到，而 `处理到楼层` 照样跳到最新层 —— 它们被永久标记成"已处理"。代码注释写的是"多读到上次之后的全部"，实现是"只读最后 8 条"，两者不一致。

- **`快照.saveData`（面板手改落盘）会把锚点挪到最新楼层**：它按 `lastMessageId` 写快照，所以"只改了一个字段"也会让 `锚点楼层 = 最新楼`；「重新推进」于是认为这一层推过（撤掉重来），删楼回退的粒度也跟着错位。

### 三、已修：世界书条目签名误删用户条目（A 案，2026-11-13 用户拍板）

**原缺陷**：`is导演条目` 的判定很宽 —— 名字/备注里含「剧情导演」、或**内容以 `【导演` 开头**，都算"我们写的"，然后会被 `清理别处的副本` / 启动清理 / 面板「清理世界书」**删除**。用户自建的《我的剧情导演笔记》《剧情导演参考》《关于剧情导演的设定》、以及备注里带「剧情导演」的 NPC 卡，**全部会被自动删掉**（`tmp/prove-wb.mjs` 实测 4/4 中招）。这不是误报，是数据丢失。

**现在只认四条精确标记**（任一成立才算我们的）：
1. `extra.daoyan === true`（我们写入时打的标记）
2. 名字或备注**恰好等于** `【剧情导演】编剧备忘`
3. 内容以 `[剧情导演 · 编剧备忘]` 开头（`buildInjectionPrompt` 的第一行）
4. 内容以 `【本幕参考】` 开头（旧版指令层条目，确实是我们写的）

**代价（必须记着）**：旧版本留下的 `【导演】角色状态`、`导演指令 · …` 这类条目**不再被自动删除**，而它们**仍在注入**。所以补了两个"只说不动手"的出口：

- `列出疑似旧条目()` —— 用**收窄后的宽松规则**（只在它里面用）扫出疑似项，**只列不删**；
- 四个调用点（启动清理、面板两个入口、创建新条目前）都会提示「插件不再自动删除，请在酒馆世界书里手动清理」。启动路径**只提示一次**（模块级标记），否则每次启动都弹等于噪音。

取舍理由：**宁可漏删，绝不误删**。自动删除用户数据是不可逆的，而"没清干净"用户可以手动收拾。

- **防剧透**：纯显示层，折叠只决定渲染哪段文案；揭开按"哪一条"记，只在内存。

## 2026-11-12 — 节奏：日常节拍 / 幕型 / 掐杂兵

用户原话：「感觉好紧凑，打完一个又来一个，一堆杂兵，打完一个杂兵又来一个杂兵」。

### 一、诊断：不是视野问题，是"没有'什么都不用发生'这一档"

账本本来就是为"看穿几十层"设计的（章回/幕纲/伏笔/冲突/书纲/命运册），导演每轮拿到的是全书结构。真正的病是三条：

| 病 | 证据 |
|---|---|
| **张力曲线是二值系统，没有"零"** | 7 个节拍**全部**落在高（受挫/反转/兑现伏笔/高潮）或低（小胜/阴影/余波）两个桶里。连续 3 幕必强制改拍，改出来的是 `余波`（"平静但带着代价"）或 `阴影`（"静中必须埋险"）——两者都是事件 |
| **对手行动 = 一次催全部逾期冲突** | `对手行动间隔幕 = 3`，且不看阶段、不看强度。主线在"铺垫"阶段也照样被催 → 主线推不动就塞个小的来交差，这就是杂兵流水线 |
| **幕纲的格式全是障碍** | 每幕一行写「目标 / 障碍 / 转折 / 代价 / 结束条件」。一幕没有障碍，在这套词汇里**没法描述**。提示词里「冲突」出现 36 次，「日常/生活/文戏/喘息/B 故事」出现 **0** 次 |

### 二、四件改动

1. **对手主动性收口**（`字段表.ts` 的 `该催对手行动` / `取该出手的对手`）
   - 只在**会出手**的阶段催（升级/僵持/决战）；铺垫阶段催动手＝提前引爆主线，收束阶段该收尾。
   - **杂兵不催**：强度 ≤ 3 且没有未收档伏笔挂在它名下。强度缺失（规范化后是 0）不当杂兵——"不知道多强"不等于"小麻烦"。
   - 间隔 3 → **5 幕**（有了日常幕之后，连着几场没动手是正常的）。
   - **一轮只点名一条**（最逾期的那条），且引擎记账（`对手行动更新`）与导演提醒（`结构提醒`）**共用同一个选择** —— 两边各算一遍会出现"提醒点名 A、账本记到 B"。
   - 未收档对抗 ≥ 3 组时，提醒里直接说"先收掉一组再开新的，尤其别引入强度≤3、没有伏笔的小麻烦"。
2. **新节拍「日常」**（`schema.ts` / `字段表.ts` / `引擎规则.ts` / `账本数据.ts` / `prompts.ts`）
   - 它是**唯一不要求发生事件**的节拍：不引入新的对抗/新角色/新麻烦，只演已有的人怎么过日子；**允许"什么都没发生"**。
   - 张力增量 **0**（不涨不跌才是喘息）；在**中性桶**里：`连续低张力` 既不 +1 也**不清零**（清零等于"演一场日常就把憋了几场的账一笔勾销"）。
   - **连胜无代价** 也不受它影响 —— 否则"赢了没代价 → 演一场日常 → 再赢"就能把反舔计数洗掉。
   - 契诃夫/收束调度**不许征用**它（那一幕的契约就是"别来事"）。
   - 核验判法**反过来**：正文没有引入新对抗＝执行了；又打起来、又冒出新敌人＝未执行。
   - 若上一幕是高潮，日常正是**代价落地**的地方（伤、债、失去、关系裂缝要出现在生活细节里）。
3. **幕纲加「幕型」**（`prompts.ts` + `取料.ts`）
   - 每幕先标 `类型: 事件/生活/收束`；**一章至少一幕生活幕**，禁止整章全是事件幕。
   - 生活幕写清干什么：**展示承诺**（类型片最爽的那一面）、给关系温度、**让主角有东西可失去**——一直打下去，读者不知道他护的是什么。
   - **幕型是给下一层的指令**：`结构提醒` 看到当前幕标着"类型: 生活"，就直接告诉导演"别开新麻烦，节拍优先选日常"。只认 `类型: 生活` 这种明确写法，不靠"正文里提到生活"猜（猜错会把事件幕悄悄放空）。
4. 以上都带用例：`tests/daoyan-日常节拍.test.ts`（35 条）+ `daoyan-反舔` 的 `[反舔-3b]`（14 条）。

### 三、和 2026-11-08 那次拒绝的关系（重要）

2026-11-08 的结论是**不做"加一个日常节拍"**，理由是"那只是把'被逼着跌宕'换成'被逼着温馨'，决定权还在引擎手里"，当时做的是平静模式。

这次的实现与那次**不冲突**，区别只有一条：**日常是许可，不是义务**。

- 代码里**没有任何一条规则会把节拍强制设成「日常」**；
- 它只做三件事：不计入连续高/低张力、张力增量 0、不许被其它规则征用；
- 选不选，仍然在导演/玩家手里。平静模式解决"这一段我不要导演"，日常解决"导演还在跑，但这一幕允许空着"——两者是不同粒度的阀门。

### 四、诚实边界

- 这套只是**允许**松，不会自动变松。如果导演照样每场都写事，下一步才是"事件额度"（一章只有 N 个事件幕）。

### 五、做完自查又补的五处（都是"加了日常之后，别处还在说反话"）

1. **正文指令第 1 项** 原来固定收一句"这一步要在正文里真的发生" —— 对「日常」是反话。现在日常单独一句："**这一幕不需要发生事**，唯一硬要求是已经发生的代价要出现在生活里"。
2. **核验升级/封顶** 原来会说"只把节拍「日常」要求的结果做出来" —— 对日常同样是反话。现在日常走另一套话术：`【这一幕别再开新线】…不引入任何新角色/新敌人/新麻烦，不埋伏笔、不推主线`。
3. **「日常」+ 必演** 是一道自相矛盾的指令（一边"确定发生 X"，一边"别引入新事"）。不硬拆 —— 按必演走，但在「调整」里划边界："必须是生活里会发生的事（一封信/一个人回来/一件东西坏了），不许借它开新的对抗"。
4. **两条提醒会跟"这一幕可以空着"打架**：对手提醒改成"**若这一幕是事件幕**（不是「日常」），让对手先动手"；连续低张力提醒改成"**下一场事件幕**安排压力（若这一幕就是「日常」，那就留着，别硬塞）"。
5. **幕纲卡住 = 静默失效**：「当前幕号」和「幕纲」全由模型维护，代码不校验。卡在第一幕不动，后面那些"这一幕是生活幕"的提示永远不会出现，整章一直是同一种节奏。现在加了提醒：`本章已演 S 场，幕纲却只有 M 幕 —— 幕纲明显落后`（阈值 S > M×3），并给出两条出路（推幕号 / 重写幕）。
- 生活幕靠**提示词约定 + 结构提醒**落地，没有 schema 校验：导演不写 `类型:` 时，生活幕提醒不会触发（不会误伤，但也不会生效）。
- 幕纲的「障碍: 无」是给人看的约定，代码不解析它。

## 2026-11-12 — 欲望 / B 线 / 类型承诺（补上"这场该不该演"的判据）

对照了两个编剧技法库（《救猫咪》BS2 的 8 个技法 + Truby《故事解剖》的框架）逐项对账，发现插件缺的不是节拍，而是**判据**：

> 账本里跟"主角想要什么"最接近的是「冲突」（对抗面）与「计划高潮」（本章爆点）—— **两个都是对抗，不是目标**。
> 于是每场戏的合法性只能靠"有没有对手动起来"来判断：一场"买盐"和一场"打杂兵"在账本里地位相同。
> 导演为了让这一幕"有内容"，就只好加敌人。**这才是"打完一个又来一个"的真正来源。**

### 一、主角欲望（Truby: Desire = 全剧脊梁）

`书纲` 新增 `欲望: { 想要 / 为什么是现在 / 输了失去 }`。

- **「想要」必须具体、可失败**（不是"变强"，是"把妹妹从北区带出来"——能判断成没成）。提示词里就这么要求。
- **首次确立直接写；之后不许随单轮输出改写**（否则它每轮换一句，判据就废了）。要改在**面板**里改（`书纲覆盖.欲望`，只换主句，另外两项保留导演写的）。
- 每轮把它摆到导演面前当判据：`这一场与「主角欲望（X）」的关系是什么：推进 / 复杂化 / 还是无关？无关的对手和事件就是杂兵——能砍就砍，或者把它接到 B 线上`。
- 书纲里没有欲望时，提醒他补一条（只在已经有书纲时才提，避免开局噪音）。

### 二、B 线（BS2: 主题不在 A 线里宣布，埋在两个人的关系里讨论）

`书纲` 新增 `B线: { 谁 / 争什么 / 现在到哪 }`。

- **谁 / 争什么 一旦确立就冻结**（它是主题的两端，每轮换一次等于没主题）；**「现在到哪」每轮可以更新**。
- 它也是"切出去喘气"的合法去处：**日常是空着，B 线是有内容但不打架**。刚做的「日常」和它是配套的。
- 面板可手改「争什么」（人和进度仍用导演写的）。

### 三、类型承诺（BS2 十类型）

设置里新增 `导演.类型`（默认「不限」），带来一个**类型承诺块**：这类故事讲的是什么、必须具备哪几个元素（缺一个都会"不对劲"）。

- 十类（**名字已全部改成大白话**，见下一节）：密室困局 / 远行寻物 / 许愿的代价 / 无妄之灾 / 人生转折 / 冤家搭档 / 查案追凶 / 装傻反杀 / 规矩压人 / 能力惹祸。
- 块里写明：这是**整章/整本书**的骨架，不是每场都要有；允许骨架内创新，**不许把必备元素换掉**（那是换了类型）。
- 「不限」→ `build类型块` 返回空串，**一个字节都不注入**（与「真实命运模式」并进档位时的做法一致）。
- **`.catch('不限')` 兜底**：存量里若有不认识的值（手改/旧版），只回落到「不限」，绝不让整个设置解析失败 —— 设置解析失败会关掉写回闸门，用户会看到"设置回默认"，那比类型认错严重得多。
- **一个字段只留一份说明**：`类型标准[x].一句话` 同时喂面板表头、下拉副标题和提示词（原来 `买点` 与面板读数各一份，改名要改两处，已合并）。

### 四、验证与诚实边界

- 新增 `tests/daoyan-欲望与B线.test.ts`（44 条：规范化 / 合并冻结规则 / 用户覆盖 / 提示词渲染 / 结构提醒 / 类型承诺与脏值兜底）。
- 全量 `pnpm test` **132 个用例文件全绿**；`tsc` 对导演模块零错误；`pnpm build` 过。
- **这三样都是"交给导演判断"的，没有代码强制**：欲望写歪了、B 线不写、类型选了不用，代码都不会拦（只有提醒）。代码强制的东西仍然是节拍、必演、张力曲线、红线保护名单那些。
- **token 成本**：欲望 + B 线每轮都进提示词（约 2~3 行）；类型块只在选了类型时进（约 5 行）。用户明确说过提示词还可接受。
- **类型是单选**：BS2 建议 1~3 个类型，这里先做单选（一个主类型已经足够给承诺；多类型会让"必备元素"互相打架）。
- **对账时发现、这一轮没做的**（留档）：中点（假胜利/假失败）没有账本节点、All Is Lost 只有提醒、五步终局还没写进收束幕、道德弱点（主角正在伤害谁）没有字段、符号网没做。前三条更值得做，但要动 schema。

## 2026-11-12（续）— 中点 + 五步终局

上一节留档的第一、第三条，这轮补上了。

### 一、中点（BS2 的 Midpoint：半程假象 + A/B 交汇）

`章回` 新增 `中点: { 类型: '假胜利' | '假失败'; 内容; 过了 }`。

- **它干两件事**：① 主角以为自己赢了（假胜利，其实是陷阱）或全完了（假失败，其实退无可退）；② **A 线（欲望）与 B 线（关系）在这里交汇**，之后赌注从"能不能赢"升级成"能不能不失去"。
- **原来靠猜**：`节奏提醒` 里有一条 `幕号 === ceil(总幕/2)` 的启发式，猜不到就漏。现在有显式锚点，**那条启发式删了**（否则同一件事两处提醒）。
- `结构提醒` 三条：没写中点 → 催他安排；写到半程还没兑现（`过了` 仍是 false）→ 催兑现并把"交汇 + 升级"讲清；已兑现 → 不再提。
- 三个数据纪律：**怪类型按「假胜利」处理并记一笔拒绝**；**这一轮漏写就沿用旧中点**（否则会被一轮漏写悄悄清掉）；**从没写过不留空壳**（老账本读回仍逐字一致，有用例钉着）。
- 面板导演台多一行：`中点·未兑现/已兑现 · 假胜利：内容`。

### 二、五步终局（BS2 的 Five-step finale）

`导演账本` 新增 `终局步: 0~5`。收官请求为真时，**每推进一层 +1**（点「重新推进」重算同一楼不算），每道收束幕**只做一步**：

| 步 | 名 | 节拍 | 要求 |
|---|---|---|---|
| 1 | 召集 | 阴影 | 把还能上场的人聚到一处，各自带任务或代价；顺便用一两句交代掉没人再提的线（不许硬塞回收） |
| 2 | 执行第一套方案，然后失败 | 受挫 | 计划**失败**，而且失败原因必须和主角自己的缺口有关（不是运气、不是对手突然变强） |
| 3 | 挖心 | 余波 | 主角承认自己一直错在哪：一个动作 / 一句短话 / 一个选择，**不讲道理、不旁白点评** |
| 4 | 新方案 | 高潮 | 用"已经变过的那个人"才会想到的办法收尾；让**价值观**分胜负，不是比谁强 |
| 5 | 落幕 | 余波 | 一个动作、一句话、一个画面，在故事内部**自然停下**；不总结、不升华、不道别；余味留下，活线不许留 |

- 以前每一道收束幕都把"回收伏笔 + 收束主线 + 不总结 + 落幕"整段发一遍 —— 演出来就是"什么都想在一场里完成"，既挤又虚。现在一步一格，**节拍也跟着这一步走**，核验才判得动。
- 每步都写明"这一幕只做这一步"，并禁止开新伏笔；待了结的线、未收档的对抗逐条点名（第 1 步与第 2/4 步各管一段）。
- **解除剧终会把终局步清零** —— 恢复游玩后再剧终要重走五步，不能从第 4 步接着走。
- 面板导演台在收官期间显示 `终局 第 N/5 步`。

### 三、验证与诚实边界

- 新增 `tests/daoyan-中点与终局.test.ts`（32 条：中点归一/沿用/空壳、三条提醒、五步的节拍序与各步要求、越界夹取、快照存亡、解除剧终清零）。
- 改了 4 处**旧口径**用例：`daoyan-spoiler-finale` 的"节拍=兑现伏笔 / 【全书收官·本轮必须落实】"改成按步断言；`daoyan-反舔` 的"中点靠幕号猜"换成"中点靠字段"；`update.ts 不出现收官请求`改成"不因收官请求 return"（现在它要读这个字段推进步数）。
- 全量 `pnpm test` **133 个用例文件全绿**；`tsc` 零错误；`pnpm build` 过。
- **诚实边界**：五步**固定 5 步**，不随篇幅伸缩 —— 只想一场收尾的话会显得拖，那种情况直接点「确认剧终」即可（不必走收官）。中点的"交汇"和"赌注升级"仍然靠提示词要求，代码只负责**在正确的时候把它顶到导演脸上**。

### 四、做完又自查一遍，补了四处

1. **终局步的推进判据改成"看有没有真产出收束幕"**（`update.ts`）。原来的写法自己抄了一遍三个前提（新楼层 / 非平静 / 非暂停注入）—— 抄一遍就会漂，而且漏了**冷启动**：冷启动期间收束幕根本不会构造（`构造本幕指令` 早退），步数却照样往前走，等真开演时已经到第 4、5 步了。现在直接 `构造.指令 && 新楼层`：平静（空构造）、冷启动（早退）、暂停注入（早退）三种情况 `构造.指令` 都是 null，步数自然不动。
2. **中点换章时不许沿用**（`账本数据.ts`）。"这一轮漏写就沿用旧中点"原本没比章号 —— 新章的第一轮漏写，就会把**上一章的中点**搬到新章头上，比没有中点更糟。已加 `旧章回.章号 === 新章回.章号`。
3. **书纲缺 B 线也要催**（`取料.ts`）。原来只有"缺欲望"的提醒，而 B 线的补写只挂在"生成书纲"那条分支上 —— 老聊天（已有真相）永远走不到那条分支，B 线就永远补不上。
4. **有章回却没有幕纲 → 先催骨架**（`取料.ts`）。幕纲是整章的骨架，没有它「幕型」「中点」「幕纲落后」三套机制**一起失效**，而且不会有人告诉你。

验证：`daoyan-中点与终局` 43 条、`daoyan-欲望与B线` 46 条，全量 **133 个用例文件全绿**；`tsc` 零错误。

## 2026-11-12（续）— 故事类型全部改名

用户原话：**"这些类型的名字……看不懂，要不是我问了一下你我都不知道金羊毛是什么。"**

这是上一批**我的错**，不是用户理解力的问题：十类型的名字是 Blake Snyder 的术语译名，「金羊毛」原本是希腊神话里一张羊皮，被那本书借去指"上路去找一样东西" —— **一个设置项的名字如果需要先读一本书才懂，那这个名字就是错的**。用户不可能为了用一个下拉框去读编剧教材。

### 改名对照

| 旧（术语译名） | 新（大白话） | 一句话 |
|---|---|---|

## 2026-11-12（续）— 证据膨胀：一条伏笔 53 条回响、每轮四万字

用户拿着面板上的证据链问了一句：**"这个伏笔证据这么长？全都发送给我们的AI或者正文AI？"**

我去他的聊天（`最后生还者`，第 1517 层，第 67 场）实测了一遍，答案比"长"严重得多。

### 实测数据

| 项 | 数字 |
|---|---|
| 账本 JSON | 18,929 字符 |
| 其中**一条**伏笔的证据链 | 5,902 字符（**31%**） |
| 那条伏笔 | 埋设 **1** + 回响 **53**（覆盖楼层 15→66，平均**每 1.0 场一条**） |
| 记忆审计（上一轮） | 请求 **52** 条 / 读到 **52** 条 / **纪要正文 41,796 字** |
| 当时状态 | 平静模式，**平静场数 58** |

**正文 AI 一分钱没花**：`buildInjectionPrompt` 那里伏笔只给一个数字（「N 条未结束的线头」），连名字都不给；只有本幕指令点名时才给 `埋设全部 + 最近 3 条回响`（`前情回响上限 = 3`，第二轮方案 2.3 就做过的有界化）。

**导演 AI 承担了全部重量**，而且是两层：
1. `引擎用账本` 把 `伏笔: 账本.伏笔` **原样** JSON 化 → 全部 53 条回响每轮都在；
2. `收集必需引用` 判定这条伏笔"窗口已开"（最早第 1 章 / 最迟第 2 章，当前第 1 章）且 `最近催办章 = 0` → **每轮**把它整条链的 AM 全部调档，拿到的是**完整纪要**（零截断，每条整篇），41,796 字。

而平静模式**不产出任何本幕指令** —— 这四万字换来的只是一个"什么都没发生"的记账。

### 还会一直长下去的两个原因

- **回响被当成日记**：`中间回响` 的语义是三次法则的中间那步（换个表面形式露一次面，不推进不揭示）。真机上它变成了每场一句"她今天还胸胀"。53 条里绝大多数是同一件事的同一形式。
- **兑现条件没人核对**：这条线的兑现条件写着「在医疗站完成晨尿试纸检测确认结果」，而 **AM0272 就已经演完了**（两道红杠、确诊九周）。账本没兑现，于是后面 25 场继续叠回响 —— 那 25 条其实是**兑现之后的日记**。

### 修法（用户选了 ①②④，没选"给提示词做证据窗口"）

**① 平静期不催办、不调档**（`取料.收集必需引用(账本, { 平静 })`）
- 跳过：到期/逾期伏笔、上一幕任务（伏笔现场）、休眠伏笔、临近窗口。
- **保留**：`待读队列`（导演自己申请的补充材料）与 `待核命运证据`（"谁死了谁走了"是否成立）—— 这两样是**正确性**，不是催办。
- 为什么连"上一幕任务"也跳过：平静期没有下发过本幕指令，账本里那条 `伏笔现场` 是**平静之前**留下的旧编排，拿它调档等于为一道没演过的命令付钱。

**①的配套（必需，否则 ① 会造出更大的 bug）：`盖章证据` 新增 `本轮请求`**
- 老规则：凡本轮没读到的引用 → 一律降成「待核」。于是平静一轮下来，整条证据链全变待核，解禁后兑现门槛反而因为"埋设证据全部待核"拒收 —— **比不修还糟**。
- 新规则：传了 `本轮请求`（`已读引用 ∪ 缺失`）就只对这些做降级判定。**没查 ≠ 查无**：没请求过的引用保留原判定，连"读取失败"也不误伤它。不传则保持老行为（旧用例不用改）。

**② 回响配额 + 收紧定义**
- 提示词写死：**只有换形式/换人/换场合才算一条新回响**；同一件事同一情境反复提**不算**；**每条伏笔每章最多 3 条**，到 3 条就"兑现或写消亡"，别记日记。
- 代码侧 `回响配额提醒`：堆到 **6 条**（`回响条数告警`）就把编号与条数摆回给导演，最多提 2 条最病态的。**一条都不删** —— 证据是内容，删了就再也解释不清当初埋了什么。

**④ 兑现条件自检**（`兑现条件提醒`）
- 条件原文**整句**摆出来（零截断），只对**临期**的线说（待兑现 / 窗口已开），最多 2 条。
- 判不了"正文里算不算发生了"（那要语义），代码只负责提醒核对：已发生 → 当场兑现；没发生 → 安排或改写条件。真机那 25 条无用回响，就是这条提醒缺位的直接后果。

**顺带（面板，不是提示词）**：证据链默认收成「共 N 条（第一条 …；最后一条 …）」，点「展开 N 条」才铺开全部。用户最初看到的正是那面墙。**数据一条不少**，只是默认不一次铺开。

## 2026-11-12（续三）— 「要不我手动引爆？」

用户问：**"要不我手动引爆？"** 背景：那条伏笔（兑现条件早该在 AM0272 满足）一直挂在「发酵」，
每轮把 54 条完整纪要（43,349 字）拉进提示词。②④ 已经在跑（平静已关，`平静场数 = 0`），
模型仍然写回「发酵」。

### 为什么"直接改状态"没用（实测过的结论）

合并以**候选为准**（`合并 = {...规范, ...}`），而 `守卫伏笔状态` 只拦"没证据就把状态升到终态"，
**不拦反方向**。所以：

1. 你在面板上把 #2 改成「已引爆」；
2. 下一轮模型照抄它自己那份账本，仍然写 `"状态": "发酵"`；
3. 合并照收 → 你的手动结账被**安静地**抹掉，而且它继续以"活动伏笔"的身份被整条调档。

我试过加"终态不随候选回退"的守卫 —— 立刻撞上一条既有规则：**状态回滚本身是允许的**
（用来纠正误标，`daoyan-rules-fix` 的 `[8] 兑现证据生命周期` 专门测它，连带"回滚要作废兑现证据"）。
那条用例直接崩在 `账本.伏笔[0]` 上。所以**守卫撤了**，改走机制。

### 改法：改成终态 = 当场收档

`账本数据.手动了结伏笔(账本, 编号, 状态)`：改状态之后**立刻把它从活动集移进历史档案**。
`导演命令.改伏笔状态` 在值为「已引爆 / 已消亡」时走这条路，日志也会写成
`手动了结：伏笔 #2 → 已引爆（已收进历史档案，证据链完整保留）`。

- **为什么这样撑得住**：它已经不在 `账本.伏笔` 里 → 模型拿到的那份账本里根本没有它 →
  既不会写回来，也不会再被 `收集必需引用` 盯上。那 43,349 字当场停。
- **没有丢东西**：证据链一字不动，进的是历史档案，面板的「已归档」区可回看。
- **不是作弊**：兑现条件确实早已满足，账本没登记是**记账错误**，手工收掉是修账。

### 同一批还补了两处（都是我自己上一轮埋的）

1. **兑现条件自检曾经会失声**：它借用了 `取到期伏笔` 的催办节流（`最近催办章`），
   于是同一章催过一次之后，整章都不再自检 —— 正好在本该核对的时候沉默。现在改成直接看
   `评估窗口`，不吃这个节流。
2. **自检第二行**：把它**最近 3 条回响的 AM + 摘要**摆出来（数据就在账本里，零成本），
   它才看得见"条件其实早就满足了"。
3. **补登记的配套**：如果它真去引用一条早年的 AM 当兑现证据，那条 AM 当轮还没被读过 →
   盖章判「待核」→ 兑现被门槛拒。所以 `收集必需引用` 新增一条：未结束伏笔里**待核的兑现证据**
   下一轮必须真去读（这属于正确性，平静期也读）。
4. **提示词**：写明「过去已经演过的事，现在补登记」—— 兑现证据不必是本幕新演的。

## 2026-11-12（续四）— 连续日常的真相：两个坏掉的计数器

用户问：「现在日常节拍是怎么出现的？已经好多轮都是日常了，我已经关掉了平静。」

先答**节拍的来源**：只有一处 —— 模型自己在 `下一幕.节拍` 里写「日常」。代码**从不指定节拍**，
只能事后核验与提醒。所以问题不是"插件塞了日常"，而是"它为什么一直这么选"。

真机取证（第 73 场，平静已关）：`最近节拍 = 6×日常`、`当前节拍.已持续轮 = 2`、
`连续低张力 = 54`、`章号 1 / 进度 收束 / 当前幕号 5 共 5 幕 / 本章起始场 1`。

### 病根一：`已持续轮` 每轮被重置，那条"拖太久"的提醒从上线起没触发过（D）

`当前节拍.已持续轮` 只在模型写 **`节拍结束: false`** 时才 +1；模型几乎每轮都写 `true`，
于是计数每轮重置成 1 —— 连续 6 场日常时它显示 **2**，"同一个节拍演了 6 轮就催"那条提醒
**一次都没出现过**。

改法：不信那个计数器，直接数 `张力.最近节拍` 的**尾部连续值**（这份历史在 `节拍结束: true` 时会追加一格，
所以它是准的）。新增 `尾部同节拍()` 与 `节拍拖太久阈值 = 5`；提醒文案带上场数，
并对「日常」追加一句：**"日常是允许空着，不是必须一直空着"**。

### 病根二：最后一幕 / 收束中还在说"把当前幕号往前推"（C）

`幕纲落后` 提醒的两条出路是"推幕号 / 重写后面几幕"。但真机上当前幕号 = 5/5（最后一幕）、
进度已经是「收束」—— **推不动**，这句话是空话。于是它原地不动，在一幕标着「类型: 生活」的
幕里连演了 6 场日常（生活幕的提醒每轮都在说"不要引入新对抗、节拍优先选日常"）。

改法：`有效幕号 >= 幕数 || 进度 === '收束'` 时换成"**该收章**"的措辞，并给出具体步骤：
让计划高潮落地、收掉该收的线，然后**开下一章**（章号 +1 / 进度回「铺垫」/ 重写幕纲）。

### 这一轮**没有**做的（用户选的，先跑几轮看看）

- **A 连续日常硬上限**（连续 ≥3 场日常 → 下一场必须事件幕）：没做，用户想先观察。
- **B 生活幕时限**：同上。
- **E 去掉"若这一幕就是日常，那就留着"那句豁免**：同上。
  当前 `连续低张力` 冻结在 54（日常是中性，既不 +1 也不清零），每轮都在喊"已经连续 54 场低张力"，
  同时又附一句豁免 —— 这条提醒事实上是自废的，留着等 A/B 一起动。

### 验证

- `daoyan-日常节拍` 扩到 **64 条**：新增 `[10]` 最后幕/收束说"收章"（并断言不再出现那句空话）、
  `[11]` 尾部同节拍 × 阈值 × 假警报（`已持续轮=9` 但节拍史没连续 → 不报）。
- 改了一条**旧口径**用例：`daoyan-反舔` 的 `[P3]` 原本断言"已持续轮 7 轮 → 提醒已经演了 7 轮"，
  那条正是被真机证伪的路径，现改为按节拍史断言，并额外钉住"只有计数器、没有节拍史 → 不说话"。

## 2026-11-12（续五）— 去掉「日常」的豁免（E）

上一轮留下的那句：

> 已经连续 54 场低张力 —— **下一场事件幕**安排一次真正的压力/危险**（若这一幕就是「日常」，那就留着，别硬塞）**。

那半句把它从"要求"变成了"许可"。而真机上 `连续低张力` 在开始日常之后会**冻结**
（日常是中性：既不 +1 也不清零），于是它每轮都在喊"已经连续 54 场"，又每轮都自己给自己开门 ——
**一条永远在响、永远不用管的提醒，等于没有**。

### 改法

- 删掉豁免。
- 说事实：`已经连续 N 场低张力 —— 也就是 N 场没有真正的压力（小胜/阴影/余波都算喘气，空着的「日常」更不算压力；这中间还有 M 场是空的）`。
  `M` 取「最近节拍」尾部连续日常的场数（就是上一批新加的 `尾部同节拍`），所以冻结的计数器**不再吞掉**日常那几场。
- 给落点，而且是**可执行的三选一**：`下一场事件幕必须来一次真正的压力：让对手先动手、让代价落地、让计划失败`。
- 说后果：`再空下去，这一章就没有"值得失去的东西"可言了。`
- **仍然落在"下一场事件幕"**，不是"这一场必须来事" —— 那样会和「日常」的契约正面打架，而日常的许可权是要保留的。

## 2026-11-12（续六）— 架构深化 ④：此刻台上是什么

### 做了什么

**新模块 `台上.ts`（纯函数 + 表驱动）**：输入是一组布尔量，输出是

- **闸就是一张表**，顺序写在数据里（`台上判定顺序` 导出，测试钉死）：

**`注入.ts` 变成薄适配器**：只负责把「账本 + 设置 + 暂停标志」读成 `台上输入`

**面板改为读它**（三处）：
- `指令预览` ← `台上文本(...).文本`（以前自己拼 `build本幕指令`，只查两道闸）
- `有必演` ← `台上.结论.种类 === '下令'`（以前自己列三条，漏掉熔断与剧终）

## 2026-11-12（续八）— 架构深化 ①：账本字段一处声明

评审里杠杆最大的一条。此前**同一个事实有六份名单**：zod 声明、`字段表` 的键表、
`账本迁移.sanitizeSnapshot` 的逐个赋值、`快照.buildSnapshotPayload` 的逐个键、
`prompts.引擎用账本` 的白名单、面板的显示。

加一个字段（`终局步`、`中点`）要同时改六处，漏一处就是**静默丢字段** ——
那时唯一的保险是一个**用正则扫源码**的用例（`daoyan-snapshot` 的 C11）。用那次评审的话：
"a test is the only thing keeping two lists in sync"。

### 做了什么

`账本迁移.ts` 里新增 **`账本字段表`**：每行 = 一个字段 + 两个方向的转换 + 要不要发给模型。

```ts
export interface 账本字段行 {
  键: keyof 导演账本 & string;
  存: (账本) => any;                            // 写进快照时取什么(可缩形状)
  读回: (快照, 已填) => any;                     // 从快照读回来怎么修(第二参=前面已填好的字段)
  进引擎?: boolean | ((账本) => boolean);        // 要不要发给导演模型
  引擎键?: string;                               // 改名: 已分析轮数 → 当前场
  引擎值?: (账本) => any;                        // 换值: 老快照里的字符串要变成数字
}
```

三个消费者全部改成派生：

| 消费者 | 改前 | 改后 |
|---|---|---|
| `buildSnapshotPayload` | 30 行逐字段 + 手写 clone/缩形 | `{版本, 楼层, 处理到楼层, ...快照载荷(账本)}` |
| `sanitizeSnapshot` | 120 行逐字段赋值 | `for (行 of 表) data[行.键] = 行.读回(源, data)` |
| `引擎用账本` | 20 行白名单 + 5 处条件展开 | `引擎视图(账本)` |

**顺序有语义**：读回时后面的行可以读前面已填的字段 —— 伏笔的埋设章要当前章号、指标的队列计数器要现存伏笔、
下一伏笔编号要伏笔列表。这一点写在表头的注释里，也是唯一不能用"无序字典"的原因。

### 用例：把那条正则换成了真不变量

旧的 C11 用两个正则分别抓 `buildSnapshotPayload` 的键和 `data.X =` 的键，再比对两份名单。
现在字段只有一处声明，这种对账没有意义了。新的 C11 是**行为**往返：

1. 造一份**每个字段都有值**的账本（`收官请求`/`待决死亡` 特意用 `true`，否则与默认值分不开）；
2. `sanitizeSnapshot` 先规范一次 → `快照载荷` → 再 `sanitizeSnapshot` → 再 `快照载荷`；
3. 断言**两轮逐字相同**（幂等），并逐字段点名，一旦某个字段被读回时清空，差异会直接指出是哪个。

外加一条**真正的"加字段"闸门**：

> `emptyData()` 里出现的每一个键，要么在字段表里，要么是运行时字段（`版本/锚点楼层/处理到楼层/清空层`）。

也就是说：以后往账本里加字段、却忘了登记"怎么存、怎么读"，这条会当场红 ——
以前这需要人记得去改六处。

### 验证

- 全量 **136 个用例文件全绿**（改了 2 处旧用例，见下）；`tsc` 导演 0 错；`eslint` 无新增错误
  （`快照.ts:104` 的 `message` 是既有问题，行号随重构移动）。
- 构建通过；`dist/剧情导演/index.js` **13:06:38**，标记 **`daoyan-2026-11-12-账本字段一处声明v20`**。

### 改了哪两处旧用例（都是"名单对账"型，被结构取代）

1. `daoyan-snapshot` 的 `[C11]`：正则扫源码 → 行为往返（见上）。
2. `daoyan-wiring` 的"引擎消息带上当前指令"：grep `当前指令: 账本.当前指令` → 真的构造一份带指令的账本、
   调 `buildDirectorMessages`、断言消息里出现 `"编号":7`。

### 诚实边界

## 2026-11-12（续十）— 架构深化 ③：提醒规则成表

`取料.结构提醒` 原来是一条 **130 行的 if 链**：20 条规则挤在一个函数体里。
加一条 = 在链中间插一段，顺序靠读代码才知道，阈值散在字面量里，用例只能逐条抄文案。

### 做了什么

规则变成**数据**：

```ts
export interface 提醒规则 {
  名: string;                                                  // 面板排查/用例/日志按它认
  生成: (账本, 上下文: { 当前幕 }) => string[];                 // 空数组 = 这一轮不提醒
}
export const 提醒规则表: 提醒规则[] = [ /* 22 条, 顺序即语义 */ ];

export function 结构提醒(账本, 当前幕) {                        // 只剩遍历
  const 行 = [];
  for (const 规则 of 提醒规则表) 行.push(...规则.生成(账本, { 当前幕 }));
  return 行;
}
```

**22 条**：知情自查缺口 / 上一道缺必演 / 连胜无代价 / 最近代价 / 对手该出手 / 未收档对抗堆积 /
世界时间 / 幕纲现状 / 生活幕 / 幕纲落后或该收章 / 中点 / 主角欲望判据 / B线缺失 / 缺误导 /
读者领先 / 节奏 / 长线回响 / 章长度 / 回响配额 / 兑现条件自检 / 矛盾久悬 / 反转重复。

后面 7 条各自有独立 module 与用例，这里只登记**它们在一轮里的位置** —— 以前那 7 个 `out.push(...)`
散在函数尾部，看不出"它们和上面那些 if 是同一条流水线"。

### 一行数没有变少，但局部性变了

`取料.ts` 从 973 行变成 1070 行（每条规则多了一个 `名`、一个函数头、一个 `return`）。
**这不是在变臃肿，是在把隐式的东西变显式**：

| | 改前 | 改后 |
|---|---|---|
| 加一条规则 | 在 130 行 if 链中间插一段 | 数组里加一行 |
| 顺序 | 靠读代码 | 写在数组里，且有断言钉死 |
| 关掉一条规则 | 删代码 | 删一行（或加 `进引擎: false` 那样的开关） |
| 用例 | 抄文案 | 可以遍历表（`逐条跑一遍不抛错`） |

### 新增用例 `daoyan-提醒表`（7 条）

1. **规则顺序被钉死**（22 个名字逐个列出）——顺序决定输出行序，所以它是语义；
2. 名字不重复；
3. **每条规则用空账本单独跑一遍不抛错**，且空账本上提醒行数 < 6（提醒太多等于没有）；
4. `结构提醒(账, 幕) === 表.flatMap(逐条生成)` —— 钉"没有藏在函数体里的额外分支"；
5. 顺序有意义：幕纲现状必须排在中点之前（中点那条要用"现在第几幕"的上下文说话）。

### 验证

- 全量 **137 个用例文件全绿**（既有那批逐字钉文案的用例一条没改就通过了 —— 说明这次是等价搬移）。
- `tsc` 导演 0 错；`eslint` 只剩既有的 `playerName/playerDesc` 两条。
- `dist/剧情导演/index.js` **13:21:56**，标记 **`daoyan-2026-11-12-提醒规则成表v22`**。

### 诚实边界

- **行数涨了 97 行**。如果只看行数，这是一次"变长"的重构；它的收益在"加/删/调顺序"的成本，不在行长。
- 规则体仍是命令式代码（每条一个 `if` + `return [...]`），**没有**变成"触发条件 + 文案模板"那种更纯的声明 ——
  因为一半规则要拼数字/列表/分支文案，硬拆成模板只会把逻辑藏进字符串插值里。
- `提醒上下文` 目前只有 `当前幕`。以后若某条规则需要「本幕是否事件幕」「最近一次高潮在第几场」，
  加字段即可，不必再改 22 处签名。
