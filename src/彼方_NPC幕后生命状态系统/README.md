# 彼方 · NPC幕后生命状态系统 (Elsewhere)

每次更新项目同步更新此说明

一个运行在酒馆助手 (Tavern Helper) 中的脚本项目。根据《Elsewhere / 彼方 - NPC幕后生命状态系统设计初稿》实现: **让角色在离开玩家视野后, 依然保持"正在生活"的状态**。

玩家看到的是角色人生中的一个镜头, 彼方负责维护镜头之外的状态: 不记录 NPC 每天发生了什么、不生成大量后台剧情、不模拟完整人生, 只记录 NPC 当前最重要的幕后状态。

## 工作原理

每次 AI 完成一次正文回复后:

```
正文生成完成
      ↓
彼方更新幕后NPC状态 (使用独立的 OpenAI 兼容 API)
      ↓
更新每个不在当前场景中的 NPC 状态
      ↓
保存最新状态 (写入当前聊天的聊天变量)
```

- **哪些 NPC 会被更新**: 由 AI 从最近几条正文回复中**自动识别重要 NPC**(排除路人、店员等功能性 NPC), 并更新**不在当前场景中**的重要 NPC 状态; 在场 NPC 只记录不更新。监控名单也可以手动维护, 名单随当前聊天保存, 新聊天默认从空开始。
- **NPC 状态卡字段**: 当前在做、当前状态、接下来想做、当前目标、心里惦记、最近变化、未完成事项。
- **更新原则**: 不强行变化、不制造大剧情、保持角色一致性、只记录必要信息、只记录重要 NPC; 检测到"几天后 / 几个月后 / 一年后"等时间跳跃时只反映跳跃后的当前状态; **时间的流逝（几十分钟/几小时/睡了一觉/一天/几天）也会推进 NPC 状态**——例如主角睡了一觉醒来是清晨，前一天晚上还在上班的 NPC 应处于清晨的合理状态，而不是停留在昨天场所。

## 未来扩展方向 (已实现)

| 扩展                  | 说明                                                    |
| --------------------- | ------------------------------------------------------- |
| NPC秘密想法           | 状态卡新增 `秘密想法` 字段, 不注入主AI提示词            |
| NPC隐藏目标           | 状态卡新增 `隐藏目标` 字段, 不注入主AI提示词            |
| NPC之间的后台互动     | 在设置中开启后, 每次更新可同时生成 NPC 间的幕后互动记录 |
| NPC位置状态           | 状态卡新增 `位置` 字段                                  |
| NPC是否可能与玩家偶遇 | 状态卡新增 `可能偶遇` 字段, 并展示/注入给主AI           |

## 安装

1. 运行 `pnpm build` (或 `pnpm watch` 开发) 生成 `dist/彼方_NPC幕后生命状态系统/index.js`。
2. 在酒馆助手中新建脚本, 将打包后的 `index.js` 内容填入并启用。
3. 也可以把脚本文件夹放进 `src/彼方_NPC幕后生命状态系统` 后使用本项目的实时监听 / 热重载功能。

## 配置

在酒馆网页中会出现一个可拖动的**悬浮球（彼方）**，点击后从页面中央弹出精美的前端面板，包含全部功能：

0. **🌗 白天/深色主题**：Header 右侧可一键切换，选择自动记忆，随全局变量保存。

1. **🪄 状态**：查看每个 NPC 的幕后状态卡（可展开）、可能偶遇标记、更新统计；一键手动更新/刷新/清空。**删除楼层 / 重roll会自动回退**：删除多少层就回到多少层之前的幕后状态（**最近 10 层精确回退**，超过 10 层不回退、删空则清空）；重roll（重新生成最后一条回复）会恢复到前一层状态。**清空 = 真正回到空状态**：清空后会记录「清空层」，彼方只分析清空之后的新楼层，不再从旧楼层重新识别出之前的 NPC。
2. **⚙️ 设置**（每个选项都带有说明文字，此处为功能一览）：
   - **接口配置**：彼方使用**独立接口**更新幕后状态，与酒馆主生成接口互不影响。填写 OpenAI 兼容接口地址（末尾自动补 `/v1`）与 API 密钥，点击「获取模型列表」拉取模型后下拉选择；「测试连接」会发一条短消息验证可用性。**最大输出Token** 限制模型每次返回状态卡的最大长度（默认 2048，上限 131072，可参考模型页的最大输出长度；追踪 NPC 多或使用推理模型时建议调大），**温度**越低更新越稳定。**走酒馆服务器转发请求**：接口不支持浏览器跨域(CORS)时（如 tokenrhythm.studio）开启，请求由酒馆服务器转发，可正常获取模型与调用；**关闭模型思维链**：对原生支持 Responses API 的模型（如 deepseek-v4-flash-0731）注入 `thinking.type=disabled`，加快响应、避免正文被推理占满。
   - **更新设置**：自动更新开关；更新频率（每 N 条回复更新一次，1=每次都更新）；**读取最近 N 条 AI 回复**（默认 3，综合最近几条正文判断剧情与在场 NPC；发送给接口的「最近正文回复」严格按这个数字取，**「最近剧情」上下文取同数量且不含正文的楼层**，不会重复也不会带入更早楼层）；**追踪当前角色卡角色**（默认关闭——仅群聊时角色卡名才是角色；若角色名只是卡片标题、角色写在世界书里，请保持关闭）；**生成 NPC 间后台互动**；**注入幕后状态到主AI**（只注入可公开字段，秘密想法/隐藏目标不注入）；**写入世界书条目**（把幕后状态写入角色卡主世界书的常驻条目，蓝灯常开、禁递归，任何读取该世界书的环节都能读到；切换聊天时自动重新写入当前聊天的内容）；**给彼方接口注入世界书内容**（默认开启，读取角色卡绑定主+附加世界书与聊天世界书，不读全局世界书，按主 AI 的方式激活条目——蓝灯常驻、绿灯按关键字匹配最近回复——让更新 AI 理解世界设定与角色，可在日志页核对实际发送内容）；**世界书内容上限**（默认 8000 字，控制每次注入世界书的字数，想更全调大、想省 token 调小）；**世界书条数上限**（默认 40 条，控制每次注入世界书的条目数）。
   - **标签过滤**：处理发给模型的回复内容。`排除` 模式移除指定标签内的内容；`只读` 模式只保留指定标签内的内容（没有这些标签的楼层保留原文）。**标签直接写名字即可**（如 `thinking`、`aftertalk`、`branches`，不用带尖括号，带 `<thinking>` 也会自动处理）；兼容带属性写法（如 `<aftertalk status="out_of_story">`）。另外 HTML 注释（`<!-- ... -->`，常见于模型思考块）始终会被清理，Subtext 思维链（`<!-- begin_of_Subtext_think -->…<!-- end_of_Subtext_think -->` 整块，含中间纯文本思考内容）也会一并删除；若回复里只有 `</标签>` 而没有开头的 `<标签>`（如模型只输出了 `</thinking>` 结尾的思维链），`排除` 模式会把楼层开头到该结尾标签的整段内容（含中间多段思考）一并删除。
    - **追踪NPC名单**：在**仪表盘的「追踪 NPC 管理」**中添加/删除本聊天要持续追踪的 NPC 名字，**随当前聊天保存，新聊天默认为空**；也可留空，由 AI 自动识别重要 NPC。
3. **🤝 互动**：查看 NPC 之间的后台互动记录。
4. **📜 日志**：查看**本轮实际发送给彼方接口的完整内容**（系统指令 + 最近剧情 + 最近正文回复 + 世界书条目 + 现有状态卡，全部可展开查看与复制）与 AI 输出、使用的楼层、更新/移除的 NPC；**「复制报错内容发给助手」**会把完整报错报告（时间/模型/楼层/请求/输出）复制到剪贴板，方便直接粘贴给 AI 助手排查。

悬浮球可拖动到任意位置，位置会自动记忆。

接口兼容性: 任何支持 `GET /v1/models` 与 `POST /v1/chat/completions` (OpenAI 兼容) 的服务均可使用, 例如各类 OpenAI / DeepSeek / one-api / new-api 网关等。若地址不以 `/v1` 结尾会自动补上。

## 脚本按钮

- **彼方·手动更新**: 立即使用最新一条 AI 回复更新一次幕后状态。

## 数据存储

- **设置**: 全局变量 (`global` 变量, 键 `彼方_settings`) —— 接口配置、更新选项、标签过滤等全局偏好。局域网访问同一酒馆服务器的设备共享同一份配置；导出酒馆助手脚本不会携带设置中的敏感信息（接口密钥等）。旧版本存在脚本变量里的设置会自动迁移并清空。
- **NPC 状态与监控名单**: 当前聊天的聊天变量 (`chat` 变量), 键为 `彼方`, 内含 `名单`(本聊天监控的NPC) 与各 NPC 状态卡。切换到其他聊天/角色卡时名单与状态互不干扰, 默认从空开始。

## 2026-08-07 — v4.2 剧情时间推进 + 世界书注入 + 接口服务端转发

- **后台互动持续性**：互动记录跟踪「已持续轮次」，提示词要求未明确结束的互动持续推进进展（如一起上学→路上闲聊→到校道别），不再一轮就消失；互动参与者的状态卡必须与互动现场一致。

- **剧情时间推进**：
  - AI 返回本次更新覆盖的剧情时间范围（开始/结束），时间轴条目按剧情时间均匀分布在时间段内（在场角色贴近结束时刻）、按剧情时间倒序展示、**只保留最近 5 次更新**的内容；

## 2026-08-03 — v1.12 世界书只读角色卡绑定

- **世界书只读角色卡绑定 + 聊天世界书，不再读全局世界书**：之前会把全局世界书排在前面，蓝灯常驻条目容易占满容量上限导致角色卡主世界书/附加世界书的内容进不了请求。现在只读取角色卡主世界书 + 附加世界书 + 聊天世界书，全局世界书一律忽略。
- **世界书内容上限改为设置项**：新增「世界书内容上限」输入框（默认 8000 字，范围 500–50000），控制每次注入世界书的字数上限，防止请求过大。
- **世界书条目模板语法按主 AI 规则求值**：彼方读的是原始世界书条目，条目里的 ACU 模板语法（`<if cond="cell:恋爱对象表/艾莉/年龄 >= 19 , cell:重要角色表/艾莉/年龄 >= 19">` 这类条件块）之前会原样发给接口。现在彼方会用 ACU 的表格数据（`AutoCardUpdaterAPI`）**真正求值条件**：`seed` 关键词匹配最近回复、`cell` 查表比较（支持 `,`OR/`&`AND/`!`NOT/括号，含嵌套 `<if>` 与 `<else>`），只保留命中分支——和主 AI 看到的内容一致。`{[db...]}`/`{[sql "..."]}` 表达式、`<random/>` 等标签、`$v:` 变量引用无法求值，注入前移除；`<if db/sql>` 与无法求值的条件保守保留主分支内容。条目前的「【世界书名】」来源标记已去掉。
- **世界书条目还支持酒馆宏与 EJS 模板**：条目里的 `{{user}}`/`{{char}}` 等酒馆宏会按主 AI 的方式替换（用 `substitudeMacros`）；`<% ... %>` EJS 模板会用与主 AI 相同的模板环境（`EjsTemplate`，合并全局/聊天/楼层变量，MVU 变量 `stat_data` 等可直接使用）渲染；EJS 环境不可用时兜底移除模板块，避免把代码发给更新 AI。处理顺序为 `<if>` 求值 → EJS → 宏替换 → 清理。

## 2026-08-03 — v1.11 更新弹窗可中断 + 切聊天不闪

- **更新弹窗 + 中断**：彼方开始更新（自动或手动）时，页面顶部出现「彼方更新中… [中断]」弹窗（悬浮球面板收起时也可见），不想等更新完成、想直接重roll时可以点「中断」立刻中止本次请求，更新不会写入任何数据。
- **切聊天不再重载页面**：原来切换聊天会整页重载导致悬浮球闪没一会儿，现在改为只刷新数据、重新注入，悬浮球不再消失。
- **修复悬浮球「手动更新」按钮**：之前悬浮球里的手动更新按钮没传强制参数，清空后点击会因「清空层」直接跳过；现在手动更新一律强制分析最近 N 条回复。

## 2026-08-03 — v1.10 修复清空/移除NPC 无效

- **修复「清空清不掉NPC」「移除NPC删不掉」**：酒馆助手的 `insertOrAssignVariables` 对**对象是深合并**——写入空的 `NPC:{}` 不会覆盖旧 NPC、从 NPC 中删除的键也不会真正删除，所以清空后旧 NPC（如已退场的马琳）一直残留。彼方保存数据改用 `updateVariablesWith` 直接**整体赋值**「彼方」键，清空、移除NPC、楼层回滚现在都能真正生效。清空会把 NPC、名单、快照、统计、已处理层数全部清空。
- **手动更新不受清空层限制**：手动更新（悬浮球按钮 / 脚本按钮）强制分析最近 N 条回复；清空层只约束自动更新，避免清空后手动更新"点了没反应"。确实没有可分析的 AI 回复时会弹提示。
- **清空后删楼层自适应**：楼层被删到清空层以下时，清空层自动挪到当前楼层末尾，自动更新不会被卡死。
- 设置存储同样改为整体赋值，避免旧设置字段残留。
- 清空改为二次点击确认（避免 iframe 内 `confirm()` 被浏览器拦截导致点无效）。

## 2026-08-03 — v1.9 世界书注入 + 清空真正重置

- **给彼方接口注入世界书内容**：彼方更新时会把**角色卡绑定的世界书（主 + 附加）与聊天世界书**中激活的条目一并发给自己的接口（可在设置中关闭，**不读全局世界书**）。激活方式近似主 AI：常量条目(蓝灯)始终包含，可选条目(绿灯)按关键字在最近回复中扫描匹配；概率/黏性/递归等高级规则不模拟。更新 AI 因此能理解世界设定与角色，不会再凭空误判 NPC。
- **清空 = 真正回到空状态**：清空时记录当前楼层为「清空层」，之后彼方只分析比它更新的楼层——清空后手动/自动更新不会再从旧楼层重新识别出之前那些 NPC；没有新楼层时更新会跳过。
- **移除NPC**：更新时 AI 可把已死亡/永久离开/彻底退出故事、不再影响剧情的 NPC 列入顶层数组 `移除NPC`，彼方会删除其状态卡并从监控名单移除（日志页显示「移除NPC」）。解决了"死了很久还被记录、最近楼层没出现还留着"的问题。

## 2026-08-03 — v1.7 楼层回滚 + 上下文窗口修复

- **删除楼层 / 重roll自动回退**：每次更新后按 AI 楼层数保存状态快照。删除楼层时回到对应楼层之前的幕后状态（删多少回多少，删空则清空）；重roll（重新生成最后一条回复）自动恢复到前一层状态。最近 10 层精确回退，更早每 10 层保留一个检查点（最多 20 个，覆盖约 200 层），快照总量有上限不会随楼层无限膨胀；回退时名单、后台互动、统计一并还原。
- **修复发送给接口的内容带出旧楼层 / 正文重复**：「最近剧情」上下文原来固定取最新 6 条，现在与「读取最近 N 条 AI 回复」一致；并且上下文会排除已作为「最近正文回复」的楼层——正文只在正文区出现一次，上下文只放正文之外的楼层（主要是玩家最近的输入），不再重复。

## 2026-08-03 — v1.0 创建

- 依据《Elsewhere/彼方 设计初稿》实现核心工作流: 监听 AI 回复 → 检测不在场景中的 NPC → 用独立 API 更新其幕后状态卡并保存到聊天变量。
- NPC 状态卡: 当前在做 / 当前状态 / 接下来想做 / 当前目标 / 心里惦记 / 最近变化 / 未完成事项, 遵循"不强行变化、不制造大剧情、保持一致性、只记录必要信息"原则。
- 时间跳跃处理: 从正文回复中识别"几天后/几个月后/一年后"等, 只更新跳跃后的当前状态。
- 未来扩展方向全部实现: 秘密想法、隐藏目标、位置、可能偶遇、NPC 后台互动。
- 独立 OpenAI 兼容接口: 支持自定义接口地址/密钥, 通过 `GET /v1/models` 获取模型列表并下拉选择, `POST /v1/chat/completions` 生成更新; 内置超时、错误提示、连接测试。
- 设置面板 (Vue): 接口配置、更新设置、NPC 名单管理、NPC 状态卡查看/移除、后台互动记录、手动更新与清空数据。
- 可选功能: 把 NPC 幕后状态注入到主 AI 提示词 (注入前过滤秘密想法/隐藏目标); 自动追踪新 NPC; 更新频率控制。
- 脚本按钮: 「彼方·手动更新」。
