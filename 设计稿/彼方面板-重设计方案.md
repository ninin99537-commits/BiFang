## 一、现状诊断与整体设计方向

### 1.1 现状问题诊断

1. **整体气质割裂**：现有面板已具备「暖琥珀拱窗悬浮球 + 墨蓝底色 + 宋体标题」的雏形，但内页大量混用厚边框卡片套卡片、工业后台式按钮堆叠与松散字号，尤其后三个功能页（事实档案、日志、设置）退化成了纯表单/调试台，丢失了「隔窗看远处故人生活」的叙事感。
2. **「事实档案」（`页面-一致性.vue`）**：筛选栏、统计数字与列表卡片层级平铺；条目缺少账本式的视线锚点（谁欠的、何时记的、剩几天/逾期多久、本轮是否刚变动、结果是否幕后结算），扫读效率低。
3. **「日志」（`页面-日志.vue`）**：请求摘要、错误诊断、大段收发 JSON 与控制台输出挤在同一纵向流或窄双栏里，代码块横向/纵向抢高；复制排障头信息与切换查看 `发出的内容 / AI 返回原文 / 世界书快照 / 错误详情` 动线分散。
4. **「设置」（`页面-设置.vue`）**：6 大块配置（接口、幕后更新、恋爱、生理、提示词与世界书、导出导入）单列瀑布到底，滚动过半即迷失位置；提示词段落卡片与发送顺序说明缺少清晰收束。
5. **「此刻的彼方」与「人物」页**：人物行标签过多时拥挤；人物详情在「只读叙事」与「全字段手编」两种模式之间缺少清晰的版式切换；生理周期圆点排布在窄栏易折成零散尾行。
6. **已知 CSS 缺陷**：
   - `.bf-empty-hint` 在非 flex 父容器中无法真正垂直居中，切换空列表时视觉跳动；
   - 暗色模式下部分次要说明字对比度偏弱，亮色模式下分割线与输入框底色区分度不足；
   - 多处嵌套滚动容器未统一细滚动条样式。

### 1.2 视觉母题：「夜色纸面 + 暖灯 + 竖签」

- **一页只留一块「纸面」**：废除卡片套卡片。整页以 `--bf-shell` 为桌面，仅核心焦点区（如人物页「当前在做」、日志页代码查看器、设置页折叠提示词卡）使用 `--bf-paper` 托底，其余区块一律采用 **1px 发丝线（`--bf-line`）+ 留白 + 衬线小标题** 分隔。
- **衬线管叙事，无衬线管控件，等宽管机器文本**：
  - 衬线栈 `--serif`：`Noto Serif SC / Source Han Serif SC / Songti SC` —— 用于面板主标题、人物姓名、「当前在做」正文、大号统计数字与分组小标题；
  - 无衬线栈 `--sans`：`PingFang SC / Microsoft YaHei UI / Noto Sans SC` —— 用于所有表单标签、按钮、徽标与说明文字（基准 `14px / 1.7`）；
  - 等宽栈 `--mono`：`ui-monospace / Cascadia Mono / Consolas` —— 专用于 API 地址、模型名、JSON/提示词代码块、事务编号 `[T1]` 与控制台时间戳。
- **桌面端右侧竖排书签轨 + 窄屏顶部横排自适应**：桌面端（`>800px`）主面板右侧伸出书页索引签（竖排文字 + 未读变化琥珀点 + 事实档案逾期红徽标）；窄屏（`≤800px`）把书签轨转为主面板**顶部横排可滑动**导航，人物索引/设置目录同步改为横向滑动条（详见 3.3 响应式适配）。

> **主题令牌纪律（本次实机 bug 的教训）**：任何「实心底 + 文字」的组合都**必须**用 `-ink` 令牌，禁止在规则里写死深色或浅色。此前顶栏更新按钮的成功态写成 `color:#0f2412`，在亮色主题下 `--bf-success` 本身是深绿，于是深字压深绿 —— 看起来"绿色按钮用的是夜间配色"。同理，`已越过档位`的细条不能直接用 `--*-soft`（亮色下是近白半透明），必须另给 `-past` 实色令牌。检查方法：把主题切到亮色，逐个触发「运行中 / 成功 / 失败 / 逾期 / 恋爱暂停」等状态，确认没有一处文字与底色同色系到看不清。

- **8 组固定人物头像底色/字色对**：保持按角色名哈希稳定映射到 `avatarPalettes[0..7]`，整套面板（仪表盘行、人物索引、人物详情大头像、事实档案行）同一个人始终同色。
- **空状态修正规范**：`.bf-empty-hint` 统一使用 `display: flex; flex-direction: column; align-items: center; justify-content: center; min-height: 220px; text-align: center; color: var(--bf-muted);`，不再依赖外层偶然高度。

## 三、外壳与两个全局弹窗规范（`悬浮球界面.vue`）

### 3.1 拱窗悬浮球与主面板外壳
1. **悬浮球（`.bf-orb`）**：保留标志性的 `46×58px` 上圆下直拱窗造型（`border-radius: 23px 23px 6px 6px`），支持拖拽防误触打开；正在请求 AI 更新时窗口内亮起呼吸暖光动画；右上角展示未读变化数角标。
2. **顶栏（`.bf-topbar`，高度 `52px`）**：
   - 左侧：`18×22px` 微缩暖光拱窗徽记 + 衬线标题 `彼方` + 副标题（当前角色卡名或 `幕后人物档案`）。
   - 右侧状态与快捷动作组（全字段保留）：
     - `剧情时间`（无数据时可省略或显示 `未推进`）；
     - `上次更新`（如 `15:31（第 42 楼）`，正在运行时显示脉冲点与阶段文案）；
     - 快捷按钮 `更新`（运行中变为 `更新中…` 并禁用防连点）；
     - 主题切换按钮 `☀ / ☾`（读写脚本主题设置并同步 `data-theme`）；
     - 关闭按钮 `×`（支持 `Escape` 键先关内层弹窗、无弹窗时收起面板）。
3. **右侧竖排书签轨（`.bf-nav`）**：
   - **书签内部用 flex 排版，不用绝对定位**：`<button class="bf-nav-item"><span class="bf-nav-badge">2</span><span class="bf-nav-label">事实档案</span></button>`；
     - 竖排态：`.bf-nav-item { display:flex; flex-direction:column; align-items:center; gap:6px }`，角标在上、`.bf-nav-label { writing-mode:vertical-rl; letter-spacing:4px }` 在下，两者与书签三者共一条中心线；
     - 横排态（`≤800px`）：`flex-direction:row` + `.bf-nav-label` 转回 `horizontal-tb`，并用 `order` 把角标排到标签**之后**（`事实档案 ②`），`align-items:center` 保证角标与文字垂直居中对齐。
   - **不要再用「`position:absolute` + `top/left` 百分比 + `:has()` 补 padding」那套**：旧写法既算不准（竖排下 `left:50%` 与文字列中心差 4px），又留下 `.bf-nav-item:has(.bf-nav-badge){padding-top:26px}` 这种特异性炸弹，横排时会单独把某一枚书签顶下去。
   - **激活态向左探出 6px，必须给内容区让位**：激活书签 `width:46px; transform:translateX(-6px)` 会压到面板右内缘；如果内容区（`.bf-page`）仍顶到边缘，它那 10px 宽的滚动条会被书签盖掉一半。做法：桌面端给**顶栏 / 内容区 / 底栏一起 `margin-right:6px`**（`.bf-topbar, .bf-main, .bf-rail-foot`）—— 这样 ① 滚动条整体落在书签左边，② 顶栏下沿、底栏上沿这两条发丝线的右端仍与内容区对齐，不会出现"缺一小口"；`≤800px` 时三者一起归零。
   - 依次固定 5 项：
     1. `此刻的彼方`（含 `本轮有变化` 暖色圆点提示）
     2. `人物`（含 `本轮有变化` 暖色圆点提示）
     3. `事实档案`（含**已过期事务数**红色胶囊徽标，为 0 时隐藏）
     4. `日志`（若最近一次更新出错显示红色圆点）
     5. `设置`
4. **底栏（`.bf-rail-foot`，高度 `32px`）**：
   - 左侧：状态圆点（`#runDot`）+ 一行状态文字（`#runText`），默认 `接口已就绪 · {模型名}`（等宽字体，未配置时提示 `未配置模型 · 点设置填写`）；
   - 右侧：当前页名称 + 快捷键/状态轻提示（窄屏隐藏）。

### 3.1.1 更新状态怎么让玩家看见（不弹浮层，靠面板本身的动效）

**问题**：模型在跑的时候，酒馆全局提示条会被彼方面板挡住；玩家想确认"在跑 / 跑完了 / 跑失败了"必须切到日志页。**做法不是再塞一个弹窗或横幅**（弹层会遮挡内容，横幅会挤压布局并让滚动位置跳动），而是把状态做进三个本来就存在的元素里 ——**核心是顶栏与主体之间那条分割线（`.bf-topbar` 的 `border-bottom`）上的光效**：

| 位置 | 运行中 | 成功 | 失败 |
|---|---|---|---|
| **顶栏分割线（主视觉）** | 一段暖光沿分割线**反复扫过**（`linear-gradient` 38% 宽度，`bfLineSweep 1.7s` 从 `-40%` 到 `140%`），并有轻微外发光 | 整条线**绿闪一次**（`bfLineFlash 1.1s`）后淡出 | 整条线**红闪两下**（`bfLineFlash 1.4s × 2`），够醒目又不刺眼 |
| **顶栏「更新」按钮** | 文案 `更新中`，左侧 2px 圆环转圈（`bfSpin .72s`），并禁用重复点击 | 文案回 `更新`，按钮短暂转 `--bf-success` 底色 | 文案回 `更新`，按钮转 `--bf-danger` 底色（表示"上次失败"） |
| **底栏状态行** | 圆点转琥珀 + `bfDotPulse` 呼吸缩放，文字 `正在更新 · 读取第 N 楼 · 已用 3.2s`（每 200ms 更新） | 圆点绿，文字 `更新成功 · 第 N 楼 · 3 人已更新 · 用时 2.3s`，**4.5s 后回落**为 `接口已就绪` | 圆点红，文字 `更新失败 · {原因摘要} · 点这里看日志`，**常驻不消失**，整段可点击跳日志页 |

实现要点：

1. 光效用 `.bf-topbar::after`（`position:absolute; left:0; right:0; bottom:-1px; height:2px`）压在原有 1px 发丝线上，**不新增任何占位元素**：不挤压页面高度、滚动位置不跳、也不遮挡任何内容。
2. 三态用面板根节点类名切换：`.bf-panel.is-running / .is-ok / .is-err` + 后代选择器 `.bf-panel.is-ok .bf-topbar::after`，避免给按钮和顶栏各自加状态类。
3. 秒数用 `setInterval(200ms)` 更新，**面板收起也继续跑**（脚本常驻）；重新展开时直接读当前状态渲染，不做补间动画。
4. 失败态必须常驻且可点击跳转 —— 这是"不用专门去日志页"的关键：一眼看到红字，想深究再点进去。
5. 成功后 4.5s 回落待机文案，绿闪只闪一次不循环；`prefers-reduced-motion: reduce` 下关闭 `bfSpin / bfLineSweep / bfLineFlash / bfDotPulse`，只保留静态颜色与文案。

### 3.2 两个全局弹窗（Modal）全字段定义

均挂载在 `.bf-root` 内，共享半透明遮罩 `.bf-modal-backdrop`，点击遮罩、右上角 `×`、「取消」按钮或按 `Esc` 关闭：

#### 弹窗 A：「添加人物」（手动建档弹窗）
由「此刻的彼方」页人物名单底部的输入条触发（若外层输入框已敲了名字，自动带入弹窗 `姓名` 框）。包含 **1 个必填项 + `卡字段.ts` 中全部 5 个标记 `可建档: true` 的字段**（零增删）：

| 顺序 | 标签 | 绑定键名 | 控件 | 必填 | 占位提示 |
|---|---|---|---|---|---|

### 3.3 响应式适配（平板 / 手机）——四档断点 + 320 验收宽

面板以 `@media` **四档媒体查询**适配（`≤1050` / `≤800` / `≤560` / `≤380`；`>1050` 是桌面默认、不设查询），桌面 → 平板 → 手机逐级降级，全程不得出现横向溢出；**`320px` 只作为验收宽度，不单独设断点**（由 `≤380` 那档覆盖）。验收视口共**五段**：1800 / 1024×768 / 820×1180 / 390×844 / 360 / 320 逐一验证 `scrollWidth === clientWidth`：

| 断点 | 目标设备 | 关键处理 |
|---|---|---|
| `> 1050px` | 桌面 | 主面板 `min(1120px, 95vw)` × `min(760px, 100vh-56px)` 居中；右侧 `46px` 竖排书签轨；人物索引列 `200px`、设置目录列 `172px` |
| `≤ 1050px` | 平板横屏 / 竖屏 | 左右留白收至 `--bf-gutter:20px`；索引列压缩为 `176px` / `148px`；统计数字 `30px → 26px`；日志四标签与错误横幅长文本改为**可换行**（`flex-wrap` + `overflow-wrap:anywhere`） |
| `≤ 800px` | 平板竖屏 / 手机横屏 | 主面板铺满 `100vw × 100dvh`（`100dvh` 兼容移动端地址栏伸缩）；**竖排书签轨转为顶部横排、可横向滑动**（隐藏滚动条）；`剧情时间 / 上次更新` 不再隐藏，改为顶栏第二行常显；页头标题与动作组 `flex-wrap` 分行（避免标题被压成竖排）；人物页索引与设置页目录改为**横向滑动条**（`display:flex` + `overflow-x:auto` + 隐藏滚动条）；人物头部动作组整行下移 |
| `≤ 560px` | 手机竖屏 | `--bf-gutter:14px`；人物行改 `3px 32px 1fr 24px` 四列（桌面为 `3px 38px minmax(0,1fr) auto`，R12′），姓名/位置与胶囊分组分行、`当前在做` 两行截断；`当前状态` 等三栏信息改单列堆叠（覆盖内联 `grid-column:span 2`）；`.bf-notes-grid` 标签列 `88px` 且 **`dt` 不换行**；表单控件统一 `font-size:16px`（避免 iOS 聚焦自动放大页面）；**两个弹窗由居中卡片改为底部抽屉**（`bottom:0`、`width:100vw`、`border-radius:16px 16px 0 0`、`max-height:88dvh`、底部补 `env(safe-area-inset-bottom)`），弹窗内字段行改单列、底部按钮等分整行；账本行到期信息折到正文下方；代码检视窗高度 `230px → 190px` |

**触摸设备专项（`@media (hover:none)`）**：`从追踪名单移除` 的 `×` 按钮原为 `opacity:0` + hover 显现，触屏上无 hover 将永远不可见 —— 必须改为**常显**（桌面端仍保留 hover 淡入）。

**书签轨横排对齐坑（已修）**：桌面端为了让带角标的那一枚书签不压住文字，写过 `.bf-nav-item:has(.bf-nav-badge){ padding-top:26px }`。这条规则**特异性高于**窄屏里的 `.bf-nav-item{padding:9px 12px}`，切换到顶部横排后仍然生效，于是「事实档案」的文字被额外顶下去 18px，视觉上比其他书签矮一截、且不在同一基线上。修法：窄屏规则必须**显式把带角标的变体一起覆盖** —— `.bf-nav-item, .bf-nav-item.active, .bf-nav-item:has(.bf-nav-badge), .bf-nav-item.active:has(.bf-nav-badge) { padding:… }`，并把书签改成 `display:inline-flex; align-items:center` 让角标与文字在同一条中线上（角标不再撑高行盒导致基线偏移）。

**激活指示：竖排用圆点、横排用底部发光下划线（已修）**：竖排书签轨上"当前页"是底部一枚 `5px` 琥珀发光圆点，这没问题；但横排后同一个圆点挂在字角上（`bottom:4px; right:12px`），既贴字又不对称，看着像文字上的脏点。窄屏改为**底部发光下划线**：`.bf-nav-item.active::after { left:10px; right:10px; bottom:3px; height:2px; border-radius:2px; background:var(--bf-accent); box-shadow:0 0 6px var(--bf-accent) }`（`width:auto` 覆盖基础规则的 `5px`），同时把横排 padding 调成 `9px 12px 11px`（手机 `8px 9px 10px`）给下划线留出 4px 净空，文字与指示器不再相连；带角标的书签下划线会自动延伸包住角标宽度。

**顶栏右对齐：动作组必须自己成组靠右（已修）**：桌面顶栏把 `更新 / 主题 / 关闭` 三个按钮靠右，靠的是 `.bf-crumb`（剧情时间·上次更新那行）的 `margin-left:auto` 把后面的兄弟节点顶到右边。窄屏把 crumb 换成第二行（`order:3; flex:1 0 100%; margin-left:0`）之后，这份"自动外边距"就消失了，三个按钮紧跟着品牌文字**全挤在左边**。修法：把三个动作按钮收进 `.bf-topbar-actions`（`display:flex; align-items:center; gap:8px; flex:none`），桌面靠 crumb 的 auto 外边距天然靠右，窄屏则显式给 `.bf-topbar-actions { order:2; margin-left:auto }` 让它继续贴右边缘 —— 不要依赖"某个中间元素碰巧有 auto 外边距"。

**页头动作组在窄屏也保持右对齐（已修）**：`.bf-page-head` 允许换行后，被挤到第二行的动作组（`.bf-actions`，含 `上次更新 … / 立即更新`、日志页那三个按钮）会落到行首变成左对齐。窄屏补页头内 `.bf-actions { margin-left:auto; justify-content:flex-end }` + `.bf-page-head { flex-wrap:wrap }`，保持"标题靠左、动作靠右"的层级不变。**注意：右对齐必须靠 `margin-left:auto`，不能只靠 `justify-content:space-between`** —— 换行后单个动作组会被 space-between 丢到行首。

**交互态（展开后）的溢出专项（已修）**：静态扫描「页面默认状态」抓不到只在点开后才出现的元素，实测漏掉了两处 ——（a）账本行内抽屉：`input(min-width:180px)` + `三段切换器` 横排时「已作废」被推出屏幕，窄屏改纵向堆叠、输入框改 `.bf-led-res { flex:1 1 160px }` 且**在列方向要把 flex-basis 改回 `auto`**（否则 `flex-basis:160px` 会被当成高度，输入框被拉成 160px 高的方块）；（b）日志元数据的 `.bf-summary .v.text`：`white-space:nowrap` + 内嵌 `<small>` 会把「移除人物：无」顶出格子，窄屏改 `white-space:normal` 并让 `<small>` 另起一行。**验收时必须逐个点开这些交互态再测一遍**，不能只测折叠态。

**验证结论**：五个页面在 390×844（手机）、820×1180（平板竖屏）、1024×768（平板横屏）与 1440+ 桌面上均无横向滚动、无内容遮挡、无字段丢失；暗色/亮色两套主题在上述尺寸下均保持可读对比度。

## 六、不可破坏的业务不变量与验收清单（交接必读）

负责实现代码的 AI 在提交前必须逐条核对以下硬性约束：

- [ ] **生命周期规范**：入口遵守酒馆助手脚本规范，使用 `$(() => { ... })` 初始化与 `$(window).on('pagehide', ...)` 清理事件监听/定时器，**禁止**使用 `DOMContentLoaded`。
- [ ] **字段 100% 精确对齐**：`卡字段.ts` 的 **33 个卡内字段** + **1 个卡外索引键 `名字`** 在只读/编辑/弹窗中各有归宿（见附表 A），7 个 `废弃键` 零出现、5 个隐藏键不得被清理。
- [ ] **未完成事项正文冻结铁律**：事项创建后正文不可编辑；`editDraft` 绝不包含 `未完成事项`；只能通过个人账本行内抽屉修改状态（`进行中 / 已完成 / 已作废`）与 `结果`。
